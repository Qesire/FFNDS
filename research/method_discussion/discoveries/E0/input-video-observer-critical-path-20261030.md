# Input-video P64: physical work and observed critical path

Author: /root/teal_full_llm_calibration_build_terra. Status **OPEN**; SRC/ALG/OBS are distinct. This proposes a subsequent comparison, not an authorized experiment or a claim of deployment speed.

**OBS.** Four exposed sources, seed 42, five phases in fixed order, same native A100 recipe. Source-equal FFN event sums are NONE 6.4101 s, H-cache Dense 7.0135 s, X-cache Dense 7.0959 s, H-readonly candidate 7.2919 s, X-recompute candidate 7.5745 s. Thus H-cache Dense−NONE is +0.6034 s and H candidate−H-cache Dense is +0.2784 s; X-cache Dense−NONE is +0.6858 s and X candidate−X-cache Dense is +0.4786 s. These subtractions describe these phase measurements, not independently measured causal component costs. The two old-source H videos match prior HIGH_ONLY bytes, while timings from the separate scope/order need not match. Source results, actual controls, receipts, and live cache boundary samples are in [native results](../../../20261030/CHIPMUNK_INPUT_VIDEO_NATIVE_RESULTS_20261030.json). No cross-arm mask identity is assumed after the candidate trajectories diverge.

**SRC.** In [tap](../../../../tools/chipmunk_input_video_tap.py), `charged` executes each action and device-wide `torch.cuda.synchronize()` before ledger completion. At 40 candidate sites it separately charges weight transpose/contiguous materialization, 64-row proxy/gather/W1/GELU/RMS, selection, indices D2H and SHA, old selected h (or old-x selected W1/GELU), and packed action. The packed action [recipe](../../../../tools/chipmunk_input_state_math.py) clones old Y, gathers W1/bias/W2, computes selected current W1/GELU, rounds delta to BF16, performs FP32 W2 accumulation, and returns BF16. X adds old-input W1/GELU. At high step0 each cache mode charges two cache clone/shadow operations per block; X also clones old x at W1. All cache modes synchronize before each step1 release and record a memory sample after each put; cleanup after the last block synchronizes, empties unused allocator segments, then synchronizes. Ledger calls and persist/journal machinery are host work; their exact per-call elapsed contribution is not isolated by these results. Mask SHA includes a real device-to-host copy and host hash, not merely an asynchronously enqueued observer.

The [native FFN event wrapper](../../../../tools/e0_original_bf16_videos.py) records CUDA events around the FFN invocation; [driver](../../../../tools/chipmunk_input_video_driver.py) sums 160 pairs. These event intervals can include GPU idle gaps while the CPU synchronizes, hashes and persists between enqueues; they do not decompose GPU arithmetic time, host time, or transfer overlap. Per-phase wall includes observers. The [original block loop](../../../../.runtime/code/LightX2V/lightx2v/models/networks/wan/infer/offload/transformer_infer.py) prefetches next weights on the load stream and computes the current buffer on the compute stream; [manager](../../../../.runtime/code/LightX2V/lightx2v/common/offload/manager.py) synchronizes both at buffer swap. Existing prefetch requested bytes are logical enqueue observations, not physical-bus measurements. A device-wide sync inside the FFN may join outstanding load work and reduce overlap. Existing observations do not measure the time attributable to that join.

**ALG / competing predictions.** Mechanism A: selected GEMMs, index-dependent packing/gather, large cache and X's extra W1 dominate the added critical path. With recording held constant, CUDA events around individual actual actions should retain most of candidate-minus-matched-cache cost; X should remain slower if the old-input recomputation is costly. Mechanism B: per-operation device-wide barriers, synchronous mask D2H/SHA, persistent host bookkeeping and joins with prefetched transfers create much of the observed event gap. With exactly the same actions and information dependencies but deferred observer completion and stream-local synchronization, candidate event and end-to-end wall penalties should shrink; per-action arithmetic durations need not change. Mechanism C: fixed phase order, resident allocator state, shared-host contention or clock variation account for a material part; matched order-reversed repetitions and isolated-resource observations should change the apparent gap. These hypotheses can coexist; the existing phase differences cannot separate them.

**Minimum later discriminator, subject to quality result and independent review/ACTIVE.** For each selected source on identical hardware and checkpoint, compare the existing instrumented H/X and matched cache-Dense recipe with a separately implemented observer-deferred version, across all 160 sites and complete videos; include repeated balanced order and paid warmup/setup, same source/seed, resource/clock observations and output byte gates against the respective instrumented arm. Retain original Dense, H-cache Dense and X-cache Dense controls and unchanged prefetch/attention. Record actual FFN events, phase wall, copies, cache allocated/reserved samples, journal/observer work and total end-to-end; call results SYS only with an explicitly controlled full-system comparison. An A/B neutral failure stops the comparison, and no K tuning is introduced. Paid startup and observer work must remain reported rather than disappear from total cost.

Moving a pure mask SHA or ledger serialization after its dependent action is permissible only if an immutable snapshot of the actual mask survives, its D2H completes before host hashing, bounded buffering and failure/UNKNOWN durability are explicitly accounted, and no later online selection sees it. Replacing global barriers with compute-stream events must establish old-x/h/Y readiness, selected indices readiness, weight-buffer lifetime, current-gate use, cache release completion, and load/compute buffer swap dependencies; cross-stream waits and allocator lifetime/record_stream must be demonstrated, not assumed. Host memory samples may be deferred or sampled separately only with their sampling semantics retained. Such changes alter instrumentation and scheduling, so exact byte-neutral gates and independent review remain necessary.
