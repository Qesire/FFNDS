# Native NVFP4 full-model video path: SRC audit

**SRC:** The available LightWan2.2-A14B I2V high/low checkpoints are not drop-in inputs to the current original-BF16 video producer. Each actual safetensors header has 2,295 tensors: 400 U8 packed weights, 400 F8_E4M3 weight scales, 800 F32 scalars and 695 BF16 tensors. For each of 40 blocks the ten packed linears are self-attention Q/K/V/O, cross-attention Q/K/V/O and FFN W1/W2. Attention *projections* are therefore quantized too; this does not imply that the attention score computation itself is NVFP4. Each attention projection has packed weight `[5120,2560]` and weight scale `[5120,320]`; W1 is `[13824,2560]`, W2 `[5120,6912]`. Each of the 400 linears has `alpha` and `input_global_scale` F32 scalars, with no `input_absmax` key in these headers. Biases, modulation, normalization, patch/time/text embedding and the output head remain BF16 in the inspected header. The high and low serialized headers both have SHA-256 `a683b47cd886105a8ba53aa241442ae51df47ee5dc872c914432c9d0e4d12384`; full checkpoint byte identities and actual CPU exit are in [the existing checkpoint result](../../../20261029/NVFP4_CHECKPOINT_BYTES_RESULTS_20261029.json). This audit read only these small headers, never weight payloads.

The original-BF16 producer's `OriginalGuard` forbids quantized model loading and quantized MM construction, insists on BF16 original-weight tensors, and binds ten Default MM calls per block. Packed U8/FP8 scale tensors and quantized MM dispatch cannot satisfy that guard. A new instrumented producer must bind the quantized loader, exact checkpoint keys, `MMWeightWnvfp4Anvfp4dynamic`, its real activation pack and GEMM calls, and the original mixed BF16 operators. Given the frozen four-step/two-expert 40-block architecture, full coverage means 160 block visits and 1,600 block linears, of which 320 are FFN linears; actual operator counts and operand shape/scale paths must be observed rather than inferred from the probe.

The local vendor `WanTransformerWeights` assigns the configured `nvfp4` MM type to the block projections and FFN, while head uses Default. `BaseTransformerModel._load_quant_ckpt` loads checkpoint tensors and optionally a separate `calib.pt`; `MMWeightWnvfp4Anvfp4dynamic` uses the directly stored `input_global_scale` and `alpha` when `input_absmax` is absent. At each linear `apply` the SM120 path dynamically packs that call's activation and local group-16 scales, then calls packed CUTLASS GEMM with static packed W/weight scales, alpha and bias. W1 input and W2's current post-GELU input are separate activation producers. The already executed isolated extension and its exact overlay/export proof are available for this route, but this audit does not establish that every full-model import and kernel dependency has been exercised.

The vendor I2V preset also fixes `dynamic_sparse_attn` at sparsity 0.9 with `sage2`, Sage2 cross-attention, four denoising indices 1000/750/500/250, shift 7, CFG disabled, no DiT CPU offload, T5/VAE offload, and 81 frames. Its sparse self-attention path builds a data-dependent block map and uses the separate sparse Sage implementation; cross-attention uses SageAttention. The relevant `spas_sage_attn` and `sageattention` package/ABI/SM120 availability and actual source origins are **not verified by the FFN-only probe**. T5, VAE, tokenizer, scheduler, I2V input processing, full model residency, SM120 attention kernels and node-local runtime also require exact asset/version binding and fresh run-time checks. SDPA can be an explicitly changed, separately registered recipe if necessary; it is not the official sparse/Sage recipe. The original BF16 producer's shift 5 and SDPA configuration are a different numerical experiment.

The existing RTN fake-QDQ path explicitly stores floating QDQ weights and activations and calls BF16/FP16 `F.linear`; it is not the packed W4A4 kernel. The [actual FFN probe](../../../20261029/NATIVE_NVFP4_REAL_FFN_PROBE_RESULTS_20261029.md) instead executed both SM120 quantization and packed GEMMs for high/low block 0 at M256 and repeated-row M31668. It used real saved BF16 teacher rows as operator inputs and a decoded BF16 same-checkpoint reference; it did not load the full quantized model or generate a video. Its strict BF16 reduction timing is a scoped operator comparison, not an official full-system speed claim.

**Next executable steps:** first freeze a lightweight CPU/header/runtime closure for both checkpoint identities, existing isolated kernel overlay, vendor source manifest, package/ABI and all attention/encoder assets, explicitly marking any unresolved Sage dependencies. Once a device is available and a new scope is registered, run a bounded full-model loader/one-block integration check observing all ten block projection types and dynamic W1/W2 inputs, followed by one unchanged official-recipe four-step 160-site native video. This tests the actual loader and attention boundary that the block-0 FFN probe cannot cover. Preserve failure receipts and avoid silent backend fallback.

For matched comparison, freeze the same checkpoint identities, scheduler, attention, source/prompt, seed/noise, model components, numerical settings and hardware/offload for all arms. A decoded-BF16 version of the same packed checkpoint is a useful explicit baseline, but must specify whether only FFN W1/W2 are decoded while attention projections remain native, or whether all ten block linears are decoded; these answer different questions and require real producer work. Compare the candidate to the relevant same-checkpoint baseline with full 160-site free trajectories, paired complete videos, predeclared quality axes and full-system latency, setup, memory, activation packing, scales and attention costs. Recheck a truly warmed timing protocol separately from video correctness. Original BF16/HiF4 model videos are useful distinct-family references, not a controlled estimate of NVFP4 alone. All full-model, quality and performance claims remain OPEN until those scopes actually execute.
