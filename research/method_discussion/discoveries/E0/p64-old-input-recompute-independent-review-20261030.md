# P64 old-input recomputation: independent mechanism review

Reviewer: /root/asset_readiness_terra. This is a proposed single-transition comparison, not a new experiment or deployment result.

Keeping the old BF16 W1 input x, old pre-gate Y, and an exact 64-row h shadow can reduce the history payload relative to storing full FP8 h and Y. After selecting the same K=5120 columns, recomputing old selected W1/GELU supplies the previous activation for the existing delta action. This trades storage and an encoding pass for an extra W1 GEMM at reuse; four-step execution provides one reuse per expert, so multiple-reuse amortization cannot be assumed.

For M=31668 and input/output selected widths 5120, this extra multiply is 31668×5120×5120 = 830,157,619,200 logical MACs per site, plus bias/GELU, selected-weight packing, x reading and selected-activation temporary traffic. Forty sites add 33,206,304,768,000 logical MACs. These are operation counts, not latency measurements. Cost depends on actual GEMM implementation, storage, device residency and synchronization. Copying or retaining the old x and making/retaining the exact shadow must be charged with the actual cache lifecycle and peak memory, alongside old Y and existing model weights.

A different selected-width GEMM can produce different BF16 values from the original full-width W1, even at the same source row and with identical stored weights; the difference can be magnified or canceled by selected W2, current gate, and existing baseline error. An informative fixed-scope comparison uses the same mask, saved full h, and saved x: report recomputed selected h versus saved selected h, direct gated output versus the already verified no-write B, and both versus the same-M Dense. Count all work and record per-case worst errors and finite checks. The 64-row shadow must come from the actual previous activation and remain causally available to selection; current full h is reserved for the paid reference after actions. Compare actual one-time old-x/shadow preparation plus one reuse against FP8 preparation and reuse, with cold and repeated intervals identified as measured or arithmetic combinations. All are local saved-state evidence; full-depth free video and model/system speed require separate reviewed scopes.

A smaller payload does not ensure lower peak allocator memory or faster execution. Reusing x after original buffer release may require an otherwise avoidable copy and co-residence; the large selected-h intermediate and second W1 can negate the nominal saving. Conversely, hardware-efficient BF16 GEMM and avoidance of full-h encoding could make recomputation competitive. These competing predictions require a real fixed same-mask cost and numerical comparison, without changing K or fitting the two development sources.
