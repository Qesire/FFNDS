A safe initial reduction is to defer only same-compute-stream device work within a single candidate FFN transaction, retaining all cache-write, cache-release and expert-boundary barriers and original load/compute stream swap. The real mask transfer and SHA remain synchronous; they already create a dependency and may limit the expected benefit. Before W2's cache release and return from that block, explicitly synchronize the device, then mark all pending operations completed. This block-level barrier keeps weight and cached operand lifetime within the prefetch-buffer transaction; no asynchronous tensors need survive phase or stream swap. A final phase barrier is independently required and recorded. It may not remove many barriers because of the synchronous SHA; that is a falsifiable result rather than grounds to omit it.

Original ledger call marks observed immediately on Python function return, so it cannot represent deferred GPU success. New `tools/chipmunk_p64_deferred_ledger.py` demonstrates predebit before dispatch, an ENQUEUED_UNKNOWN state and completion only after the barrier, with retained returned objects. Failed enqueue/barrier stays UNKNOWN and stops without retry. This helper is not yet wired into the real tap or durable journal. Real implementation must ensure all intermediate allocations are made and consumed on the same active compute stream, retain inputs/outputs through the block barrier, ensure the monitor/failure path cannot record completion after asynchronous error, and atomically report each completion on journal-write failure. A synchronous CPU mask hash must not be described as a GPU event or as proof all other streams completed. Cache release and the buffer swap must happen only after the barrier.
