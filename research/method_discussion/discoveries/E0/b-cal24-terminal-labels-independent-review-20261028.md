## Discriminating findings

1. **Stored row payload is not revalidated.** `write_label` verifies `pack["rows"].tolist()` before safetensors serialization and then `validate_label_header` verifies only metadata and the tensor header. A changed I64 payload with unchanged metadata/header passes the latter. The saved-byte SHA makes subsequent corruption detectable but does not establish that the originally written payload matches the sampled row list. Add readback of the actual rows bytes or tensor after serialization, compare exact ordered coordinates and account for this work; add a negative control that changes only payload bytes. The same reasoning favors checking the serialized bytes for all seven claimed tensor hashes, because existing `tensor_record(v)` hashes pre-serialization in-memory objects. This is a producer acceptance gap, not evidence that an actual generated pack is wrong.
2. **External CPU preflight is not an execution gate.** `main` executes `preflight()` and directly calls `execute()` in the same process; `execute` does not bind an independently completed worker preflight receipt, its actual exit status, RUN SHA, exact part/protocol, and worker identity. The draft explicitly lists this future binding as pending. Implement an external receipt gate before native work if required by the registered run design; the inline byte-only preflight remains a useful independent check but is not a prior external exit receipt.
3. **Exact topology must be frozen beyond aggregate counts.** The reviewed `Cal24LabelTap.finish` checks 400 linear/QDQ events, 10 per block, 80 FFN linear names, and event pair equality, but does not prove the exact ordered ten distinct projection names per block. An accidental repeated or substituted non-FFN projection can satisfy those totals. Five pre-infer MM events are counted without checking distinct ordered identities. The author is adding topology controls; verify those changes against the real source and bind their test/version before any run.
