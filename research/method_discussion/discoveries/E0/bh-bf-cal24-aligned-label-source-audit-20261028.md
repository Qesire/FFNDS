# B-H / B-F：CAL24 对齐标签的真实资产与生产路径（2026-10-28）

**结论（SRC + 资产检查）**：CAL24 已保存真实 block39 的每 source×step 256 行 V1/V2/Y/b2/gate 和行坐标，但未在这批目录保存 r、u、head 标签，也未发现同一步完整 latent、初始噪声或 encoder condition 张量。其 INPUT 中的四步 post-state 是哈希而非可重放 state。要把新标签与原 CAL24 精确配对，当前可行入口是重建每个来源的原始 seed42+i、条件和四步 Dense 链，并在每一步 block39 使用**该 INPUT 中的对应 selected_rows**捕获 r/u/head；以历史 post-state 哈希及原 V1/Y/gate 字节对照验收。若将来找到经身份验证的同一步完整 state 和 condition，则可在该状态重跑该步完整40层，只捕获 block39；不能仅用哈希恢复状态。B0 consumer01/04 是另一组 seed42 的两个历史开发来源，仅适合 CPU 标签和算子对照，不能冒充 CAL24 的 train16/heldout8。

**现有资产。** [completion config](../../../../config/e0_compact6016_full80_completion_20261028_v1.json#L251) 固定 index0–15 train、16–23 heldout，24来源历史均已暴露；[source 列表](../../../../config/e0_compact6016_full80_completion_20261028_v1.json#L282) 的 seed 为42–65，不等于 consumer 两来源统一 seed42。配置的 `inputs` 给24个 HF 相对 locator、字节数及 SHA；本审计逐个重算24个 INPUT 小文件 SHA，全部一致。每个 INPUT 为160个 step×block 的已采行对象、原 source/prompt/image 绑定、四个 plain/observed post-state 哈希及视频文件 SHA；24个目录每个均有160个 safetensors、两份 PHASE、INPUT 和两份视频，未见 state/noise/condition 文件。此为指定 CAL24 目录的检查，不排除其他另行登记资产。

**原生生成与可复用性。** [原采集器](../../../../tools/collect_ffn_operands.py#L68) 在每个实际 FFN 的 QDQ 和 W2 输出采 V1/V2/Y、gate/b2；行由 namespace、CAL24 index、step、block、grid 派生，存入 INPUT（[81–104](../../../../tools/collect_ffn_operands.py#L81)）。[原流程](../../../../tools/collect_ffn_operands.py#L199) 对每 source 重置 scheduler.generator，分别跑 plain 与 observed `seed=42+index`，要求四步 post-state 哈希及视频 SHA 一致；[采集器](../../../../tools/collect_ffn_operands.py#L203) 将 post latent 转 FP32 后仅计算哈希，未保存其内容。[原 protocol](../../../../config/calibration24_ffn_operands.json#L10) 固定256行、namespace及seed。当前 [Wan distill scheduler](../../../../.runtime/code/LightX2V/lightx2v/models/schedulers/wan/step_distill/scheduler.py#L21) 以 FP32 初始化，实际 `torch.randn` 发生在 [Wan scheduler](../../../../.runtime/code/LightX2V/lightx2v/models/schedulers/wan/scheduler.py#L80)，后续 post 以 FP32 算 flow 更新（[80行](../../../../.runtime/code/LightX2V/lightx2v/models/schedulers/wan/step_distill/scheduler.py#L80)）。这是源码路径和历史采集行为，不是已保存的 FP32 noise 资产；需按历史版本、device、环境和 seed 重新生成并以逐步输出哈希判定。INPUT 内 image/prompt/path 与 image SHA 可绑定重建 encoder，但 encoder 输出本身在上述目录未存；重算后才有条件对象，不能预先宣称逐字节复现。

**可直接实现的 producer（OPEN，尚未登记/运行）。**

1. 读取24个被 config SHA 绑定的 INPUT，校验 source image/prompt/seed及16/8角色，提取每个 step 的 block39 `selected_rows`、采样 seed、V1/Y/gate 资产路径和 SHA。不可调用 B0 的 `row_draw` 重抽：B0 验证的是另一套 source ordinal/采样方案（[capture driver](../../../../tools/e0_b_final_block_capture_head_asset.py#L111)），CAL24 必须沿用原 manifest 实际坐标。绑定冻结的原模型、HiF4 cache、量化器、运行时及 head 两 expert 权重/调制。
2. 每个来源重算 image/text encoder，清空 generator，再以原 seed 重建 FP32 初始 latent；逐 step 调用原 pre、40个 native block、原 LN/head、unpatchify 和 scheduler post，连续推进四步。每 step 将 FP32 post-state 原始字节 SHA 与 INPUT observed 哈希逐一比对；不匹配则该 source 不准标为原 CAL24 对齐。由于历史只记录 post 而未记录初始 raw SHA，step0 的哈希及同坐标数据是首次可见的对照，不能声称直接验证初始噪声。
3. 参考 [FinalBlockTap](../../../../tools/b_final_block_capture.py#L269)：只在 block39 写回前抓 r、原 FFN 输出 Y、gate，写回后抓 u；读取原 step 的同一256索引。捕获真实 time/head modulation、head weight/bias 身份和 stride，head 原输出的同一256行。对同坐标 V1/Y/gate 做逐字节比较，并在 CPU 按 BF16 先乘 gate 再 add 重放 u（[核对](../../../../tools/b_final_block_capture.py#L404)）；需要查验相同 backend 和精度。记录实际执行次数、RNG 不变与明确 mismatch，而非假定重跑必定相同。head 标签要和同一 source/step/row 对齐，后续可从真实 u 与条件构建 direct65 或 B-F 目标；这并不证明现有65统计在 BF16 中精确。
4. producer 输出一条每 source/step manifest，含输入 SHA、历史 state SHA 对照结果、expert、rows、V1/Y/gate 对照、r/u/head/modulation tensor header与哈希及退出凭据。先对 B0 两来源做 CPU neutral/标签控制；成功后才考虑24来源实际采集。若历史状态或 operand bytes 不同，应报告新的再生 cohort，与原 CAL24 teacher 分开，不能标成 matched。

**最低完整预算估算（OPEN，非已执行或授权）。** 覆盖训练与 heldout 的四步共24×4=96次 Dense flow、3840 native block/FFN、24次条件准备及24次 seeded 初始 noise，96次 LN/head、scheduler pre/post；无视频解码、学生拟合或额外 shadow FFN。CPU 验证至少96×256×5120各一次 BF16乘和add，外加 SHA、header与编码器/调度准备；GPU 资源与时间需先实测，B0 单进程一次运行观测峰值79,162 MiB，不能直接视作 CAL24 配额；权重是否复用决定 transfer 总量，不能简单线性外推。仅新增96组 r/u BF16 行理论载荷 503,316,480 B，96组256×64 BF16 head 3,145,728 B，再加 gate、条件/调制、索引、header、日志和对照约若干 MB；如保留完整 u，则额外 96×31668×5120×2 = 31,130,910,720 B（若替代而非叠加行数据应相应扣减）。是否存 full u 是后续训练/neutral 合同决定；以上不含原 operands、临时 buffers、真实 checkpoint 或 condition 保存，需测盘与精度。重复 plain/observed 两条链会将96 flow翻倍；单链与原历史 post SHA 和原 operand 对照已经是区别性检查，但新 observer 自身的 no-op 证据要另行设计，不应沿用历史两次运行通过的结论。
