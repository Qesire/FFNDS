# Independent SRC/ALG review: SharQ resident FP4 and FFN prefetch

Reviewer: `/root/asset_readiness_terra`, distinct from proposer `/root/teal_full_llm_calibration_build_terra`. Reviewed [candidate](sharq-resident-fp4-prefetch-elision-20261030.md), SHA `7a8163a79a4cb77fa3ecd93d108139951fe62f6e669dc5c97efa5c27702cacb2`. I support its bounded SRC/ALG premise as a useful execution question; no new experiment or speed, memory, or quality result follows.

**SRC.** In [runtime](../../../../tools/e0_sharq_wan_all160_runtime_v2.py), `_pack` (lines 62–78) materializes the original CUDA BF16 buffer transpose and caches the four actual shared weight tensors by expert/block/linear. `_apply_fp4` (83–103) pulls that cache but takes bias from the current MM buffer; `_apply_bf16_cache` (105–112) first populates missing entries. Forty blocks × two experts × two linears means 160 cached matrices, not 160 FFNs. [FFN ops](../../../../tools/e0_sharq_wan_ffn_ops.py) lines 11–29 prepare A and its scale for each call; SharQ executes sparse plus full-K dense residual, whereas Dense32 uses one dense GEMM. Thus replacing current W copies cannot remove dynamic A preparation, bias readiness, or the full-K residual.

The actual LightX2V `common/offload/manager.py` lines 65–99 initializes the first buffer on its init stream, loads later buffers on the load stream and synchronizes load and compute before swapping. Its `common/ops/utils.py` lines 321–338 performs `copy_` for each present base attribute, and Wan `models/networks/wan/infer/offload/transformer_infer.py` lines 50–64 overlaps the next prefetch with current compute. [Bridge](../../../../tools/e0_sharq_wan_author_stream_bridge.py) lines 12–23 records caller→default and default→caller events and tensor lifetimes. Consequently, removing a W copy without replacing the buffer's identity/operand guard and preserving bias plus stream readiness can feed stale state even when packed W is correct.

The existing [V2 report](../../../20261030/SHARQ_WAN_ALL160_VIDEO_V2_NATIVE_RESULTS_20261030.json) records per phase requested W1 22,936,836,096 B and W2 22,934,016,000 B, and 7,102,136,960 B static packed cache accounting. The original audit sums weight **and bias**, including prefetch/initialization repetitions; these are logical requested bytes, not measured physical traffic. Exact skip savings require subtracting retained bias and identifying actual copy instances. The static cache accounting does not measure extra live bias, temporary storage, allocator reserved peak or bandwidth.

**Counterexample and decision.** If all removable copies overlap compute, reducing their requested bytes has no critical-path benefit; if they determine the load/compute join, the same reduction can matter. A premature cache lookup with stale current-buffer metadata can violate byte-neutrality even if the cache key is correct. A future same-recipe paired native test should first validate cache identity, current bias, all linear outputs and states, plus both stream dependencies, then separately measure cold pack, actual copy timeline, peak allocation/reservation and controlled repeated wall. Dense32 neutrality is not evidence that SharQ's two-GEMM path is neutral. No GPU, tensor data, model or new numeric computation was used in this review.
