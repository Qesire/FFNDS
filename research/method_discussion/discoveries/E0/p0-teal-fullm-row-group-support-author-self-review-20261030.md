# TEAL full-M row-group support: author self-review

Status: FROZEN_PENDING_REGISTRATION and independent exact recheck pending. The eight real inputs and actual capture RUN/EXIT are bound following the coordinator’s independent file/header verification; ACTIVE registration and this CPU experiment remain pending. This is an author review, not independent approval or a completed experiment.

The fixed question is whether support unions for real contiguous raster row groups are narrower than those for the same real rows under one paid, fixed PCG64(seed 42) shuffle. Local coherence predicts more empty K columns and K16/K64 blocks for natural groups; a distributed or row-exchangeable support predicts little advantage. The same BF16 elementwise TEAL mask is used for both, and union support is only an execution accounting upper bound. The permutation is identical for all eight cases, both thresholds and both group sizes. Its algorithm/version, seed and raw hash are recorded. The original source/seed images are development sources; four sites within a source are not four new independent images.

Each case records every group union size and empty K16/K64 count, logical W2 MACs weighted by each group's actual row count, full-group distribution/median/p95/max and a separate tail. A full M has 1,980 M16 groups with four real tail rows and 990 M32 groups with 20 real tail rows. No synthetic rows or source replication are introduced. Summaries average the four sites within each source and then the two sources equally. The gate and original raster shape are bound/validated but neither is treated as an all-ones mask or used to claim quality.

The scope pays for 8 packet file SHA reads, 8 full H raw-tensor SHA reads, a further 8 full H analysis reads (each 7,004,454,912 aggregate H bytes), small original gate SHA reads, 16 keep matrices, one permutation and 95,040 group-union scans. File SHA, tensor SHA, BF16 threshold comparison, permutation, gather and union scan wall observations are kept separate; scans use the same two keep matrices per case and no model call, W1/W2 multiplication, QDQ, fit or GPU kernel. `observed` means successfully completed work; a partially completed predebited operation stays unobserved, with the failed scope retained. This is a logical MAC upper bound and structural support measurement, not a speed measurement or complete video-quality result. Repeated CPU serialization, page cache and observed Python/NumPy timing do not represent native inference cost.

Before execution bind the exact capture protocol, exited RUN/launcher receipt, eight complete file hashes/sizes and H/gate raw hashes, gate layouts and actual grids, then freeze the final read budget, exact private launcher and protocol SHA. A truly different agent must audit the BF16 scalar tie behavior against the V3 `abs <= threshold` action, the contiguous raster flatten order, full file/header/tensor integrity, single-permutation identity, M16/M32 tail and weighted MAC algebra, failure accounting and hardware/time budget. Only after their recheck may root register and execute the CPU scope. The fixed source shapes are `[31668,13824]`; natural row coordinates follow the capture's source-bound `(t,h,w)` flatten, with width changing fastest. Synthetic tests exercise BF16 scalar comparison against Torch on tiny CPU values, natural/shuffle union and tile counts, tails, malformed safetensors headers, draft refusal and the exact call budget. No real H has been read by this producer.
