## Exact metric semantics and useful comparisons

Let `c_t=max(0,cos(e_input,e_t))` and `a_t=max(0,cos(e_(t-1),e_t))`. Both I2V functions compute, per clip,

`0.4 max_t(c_t) + 0.3 mean_(t>0)(a_t) + 0.3 min_(t>0)(a_t)`.

Thus only the maximum input-frame similarity enters the first term. The remaining terms measure adjacent consistency. They do not require every frame to preserve the input or preserve the intended motion. A static repeat of a similar frame can perform very well on these terms. This is a property of the source equation, not an observed official score on E0 clips.

| `vbench2_beta_i2v.i2v_background` | **DreamSim0.2.1 ensemble embeddings** (DINO/CLIP/OpenCLIP with LoRA), 224×224 resize, original image plus every frame; same formula | Conditioning-scene alignment plus consistency; no semantic background mask. 2. **Resolve known metadata conflicts locally.** Original VBench requirements specify `numpy<2.0.0`, `timm>=0.9,<=1.0.12`, `transformers==4.33.2`. Current NumPy/Transformers violate them. 5. **Keep original model resolution.** The cached loader locally binds DINO, DreamSim ensemble, CoTracker2, CLIP B32/L14, AMT-S, RAFT-things and MUSIQ-SPAQ.
