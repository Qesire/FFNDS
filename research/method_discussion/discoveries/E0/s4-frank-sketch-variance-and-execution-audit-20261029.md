# S4 FRANK: paired sketch variance and execution audit

**ALG:** For fixed gated row errors `e0`, `e1` and independent standard Gaussian columns `ωj`, use the same columns for both actions: `Δ̂ = (1/k) Σj[(e0·ωj)² − (e1·ωj)²]`. Gaussian fourth moments give `E Δ̂ = ||e0||² − ||e1||²` and `Var Δ̂ = (2/k)(||e0||⁴ + ||e1||⁴ − 2<e0,e1>²)`. The negative covariance term is the benefit of the paired probe; two independent probe matrices remove it. Sign and magnitude of the error correlation matter, and unbiasedness is over independently sampled probes, not a guarantee for one frozen probe on a new source.

For a whole physical M tile with error matrices `E0`, `E1`, the same shared `Ω` yields `Δ̂T = (||E0Ω||F² − ||E1Ω||F²)/k`. Writing `A = E0ᵀE0 − E1ᵀE1`, `Var Δ̂T = (2/k)||A||F²`. Rows share Ω, so summing single-row variances as if token estimates were independent is generally wrong. Correlated errors can make tile-level uncertainty remain substantial; independent Ω by row changes both variance and the hardware/metadata cost. If a decision is taken from a single frozen Ω, all source-held evaluations must preserve that identity, with probe-seed sensitivity reported separately rather than selected on held-out video.

**SRC/OPEN:** With full original W1 and GELU already paid, `h` is the first actual input to both the sketch and factor W2. This route does not save W1. A straightforward split computes base `(hU0)V0` and, only for selected rows, `(hU1)V1`: four GEMMs plus row/tile gather and scatter for a selected group, with separate base/intermediate materialization and an output combine. Unselected rows pay the two base GEMMs. An alternative concatenated rank-960 two-GEMM path computes all optional work and cannot claim rank-320 compute savings. A fused physical implementation could route an M tile to a rank-640 or rank-960 two-GEMM kernel, or fuse accumulation of the optional block, but must measure launch, packing, padding, occupancy, bank residency, synchronization and BF16 output/bias staging; no such speedup is established here.

The probe can be one projection `h[P0 P1]` of shape `H×2k` instead of two launches; it still costs `2Hk` MAC per row and materializes `M×2k` projected values unless fused with the sum-of-squares and tile reduction. It also stores the precomputed projection and pays its read bandwidth. For `H=13824`, `k=16`, this is 442,368 MAC per row, while one rank-320 factor increment costs `(13824+5120)×320 = 6,062,080` MAC per row before launches and movement. If a fraction `p` of physical tiles takes the increment, a necessary arithmetic-only comparison to always-r960 is `2Hk + p(H+D)320 < (H+D)320`; real break-even is stricter once routing, padding and memory are included. The hardware benchmark must compare a static rank at the same observed expected cost, plus static expert/block/step policy, using equal setup and full FFN timings.

The existing rank-960 BF16 two-GEMM export is not automatically equal to a rank-640 two-GEMM output plus a rank-320 two-GEMM output: independently rounded intermediate GEMMs, accumulation order, output casts and the single original bias can differ. The proposed probe's continuous linear `B0+B1` benefit therefore does not by itself certify the actual BF16 action benefit. An authorized later diagnostic can use existing raw `h`, W2, gate and exported factors to measure both actual staged actions, signed gain, covariance and disagreement; it need not generate a new video. Any numerical work requires its own registered scope and source-held split.

**Decisive comparisons:** report a row oracle only as an unconstrained upper bound, a common-action contiguous physical M-tile oracle, the fixed rank and fixed step/block baselines at matched measured expected cost, and the sketch policy with false-negative benefit, harmful selections, source-equal regret and tails. The saved 256 rows are sampled native coordinates and do not establish contiguous full-M tile composition: valid physical tile tests require actual coordinate coverage or a separately authorized producer. Probe generation, projection storage, online projection, reductions, routing, any packing and the original full W1 must all be charged. Dense future output and a teacher error are offline labels, not free inference-time observations. Video dynamics, quality and end-to-end performance remain OPEN.
