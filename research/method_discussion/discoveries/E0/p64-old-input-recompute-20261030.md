# Old input as a recomputable FFN history representation

Proposer: /root. This is an unexecuted I/C mechanism proposal following actual history-encoding results, not a new accepted video method.

The actual four-case probe shows a useful separation: removing the dead h clone/update preserves every output byte, while FP8 and per-column int8 halve stored h but add roughly10ms and28ms construction cost for one real reuse. Their output drift versus BF16 history is below1% in these cases; that does not establish full-video quality. Retain the same P64 correction and reconsider which historical object must persist.

For fixed FFN parameters, h_old=GELU(x_old W1^T+b1). It is sufficient to retain the narrower BF16 x_old, old pre-gate Y and exact64 sampled h rows. The future current x64 and exact shadow select the same P64 columns. Only then, reconstruct old h on those columns and perform the original selected current W1/GELU, BF16 delta, FP32 W2 accumulation, BF16 merge and current gate. Recomputing the old selected W1 is causal; neither current full h nor teacher Y selects the action.

At M31668, x_old has324,280,320 BF16 bytes versus h_old875,556,864. Including oldY and exact shadow gives650,330,112 logical bytes per block, compared with763,828,224 for FP8 h+oldY+shadow. These counts exclude weight storage, conversion/gather temporaries, allocator peaks and copies. Selected old W1 at K5120 adds approximately0.830 TMAC per position; actual time and any memory benefit must include this compute, old-x cache clone, shadow creation, weight reads/packing, GELU and temporary outputs. No speed conclusion follows from the byte count.

Competing predictions: a compute-rich/memory-expensive regime can make narrower native input plus selected recomputation competitive with full-history encoding; alternatively, the extra W1 and its gathers dominate and make cached h preferable. An independent numerical alternative is that changed selected-W1 width alters BF16 results; a full-width old-W1 reconstruction followed by the same gather distinguishes selected-width effects from differences between current replay and the stored model path. [Independent counterexamples](p64-old-input-recompute-independent-review-20261030.md) identify the added MACs and rounding issue before execution.

Prepare four same-source/expert block20 full-M cases, without changing K: A readonly BF16 history, B FP8 history, C input-state selected-old-W1 recomputation, D input-state full-old-W1 recomputation. Each gets1 warm+3 timed+1 comparison call; cold history construction and every mask/observer are separately paid. All masks must match the original P64 identity. Compare C/D reconstructed old selected h and gated output to A, to one another and to same-device current Dense; preserve nonzero saved-teacher differences. Read or evaluate teacher values only after action outputs are fixed. Logical resident storage and cumulative multi-arm diagnostic peak are different evidence.

This finite operator discriminator precedes a separately reviewed all160 free-student video experiment. Its four cases are two exposed sources with two expert conditions, not four independent sources.
