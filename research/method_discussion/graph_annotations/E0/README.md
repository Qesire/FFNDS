这里记录原始贡献，不是算子实现或实验排队：
1. 研究者选择**恰好相关的**节点/边，从源代码和上游/下游查证，允许反向从视频现象或一篇新论文定位节点；
2. 将 [GRAPH_CLAIM_TEMPLATE.json](../../GRAPH_CLAIM_TEMPLATE.json) 拷贝为唯一名称的 `<claim-id>.json`，填入 `anchor_nodes`、来源、机理、反解释与判别式，依据实际身份标注 `SRC/ALG/OBS/NATIVE-OBS/NATIVE-ACT/SYN/VIDEO/SYS/OPEN`；
3. 独立 Agent 用另一份记录或既有 `reviews/<method-id>/vN/` 文件提出实质证实、反例或争议，引用精确claim ID；
4. 整合者核对图ID、实际代码/证据路径与评议后，决定更新 G0–G6 源图的文字证据、OPEN边或实验谱系；保留原研究讨论的所有不同意见。

一条新科学定理、一个对新表示的反例，或一个发现原图忽略了重要源码分支的分析均为有效科研贡献。若用户未许可新模型执行，则记录下一实验需求而不自动运行。**第一份示范性机制种子**：[跨token共享函数基的OPEN假说](E0_GRAPH_SEED_FUNCTION_BASIS_20261025.json)，在F08/F09/F15/P06/P08节点注册“输出函数空间可能共享而原hidden列不共享”的竞争机制；严格代数分解有依据，所提出的可执行低维基属于**未证实/未独立评议**，不能当作已完成模型加速。
