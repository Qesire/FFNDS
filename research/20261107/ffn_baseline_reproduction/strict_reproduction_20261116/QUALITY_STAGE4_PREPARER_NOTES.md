# Stage4 offline metadata candidate

`quality_stage4_prepare.py RECIPE RECIPE_SHA256 DESTINATION` validates actual immutable inputs and writes review candidates only. It does not create REVIEW/ACTIVE, submit a job, decode a video, run VBench, or allocate a GPU. It fails before creating the destination when the complete requested cohort or any evidence is missing.

Recipe fields:

* `dense_admission`, `dense_audit`, `paired_contract`, `conditions`, `frozen_comparison`, `e6_decision`, and `old_quality_scope`: `{path,sha256}` specs. Use the original audited 11-source admission, its READ_ONLY_AUDIT_COMPLETE receipt, the fixed quality contract, real V2 conditions, the completed comparison freeze and its matching E6 decision. Old metric scope is byte-pinned to `work/quality_ref/scope.json` SHA `302afde8c3d038af5ca4f644aff9a3ecdcac30b3601e8c6f3fccf45494ff64fc`.
* `submitted`: a list of `{path,sha256}` specs for each actual generation `SUBMITTED.json`. Each doc must contain `stage`, `job_id`, `scope_sha256`; actual stage REVIEW/ACTIVE, RUN/EXIT, NFE, SUMMARY, all producer code, source receipts, MP4 and latent bytes are checked. Two Stage1 Dense files come from admission, the remaining nine must come from completed new Dense generation. Main requires every one of the remaining four arms for all 11 sources. E4 requires the three DEV3 child videos as well as the main ICC parents. E6 requires three DEV3 valid52 child videos and main Chip parents only when the matching true-M decision is E6_TAIL52_FROZEN. Precision E6 is not implemented by this quality producer proof and is rejected.
* `metric_project_root` must equal the old metric root. Each actual V2 condition image's basename is resolved under `metric_project_root/vbench2_beta_i2v/data/crop/16-9` and SHA checked against the V2 condition. Prompt bytes, noise, scheduler, cluster, checkpoint identity and unique actual video paths/inodes are bound for every pair. V2 generation's distinct image directory is not substituted as the VBench locator.
* `quality_reference_source` contains the four byte-pinned old `runner_metrics.py`, `metric_contract.py`, `metric_loaders.py`, `runtime_contract.py`. `runtime_guard_source` and `runtime_guard_sha256` must supply the verified compute guard with `process_peak_rss_bytes`. `python_executable_sha256` must match the real `vbench_i2v_official/bin/python3.10`. `metric_additional_source_roots` must be explicitly supplied, possibly as a verified empty list. Old asset and source SHA closure is rechecked with the old dimension-specific `verify_closure`; hashes can be expensive and are read-only.
* `planned_root` is the absolute future shared-filesystem root corresponding to `DESTINATION` when staged. `authors` is nonempty. `budgets` is indexed by `main`, `E4`, optionally `E6`, then each applicable dimension and must supply exactly `gpus_per_job`, `max_jobs`, `cpus`, `host_memory_gib`, `gpu_memory_gib`, `wall_seconds`, `soft_seconds`, `min_free_disk_gib`, and `output_bytes`. Provide explicit per-axis budgets; the old two-source estimates do not establish a 55-video budget.

Outputs: shared `bundles/` (the exact quality_wan_proof inputs), `reference/`, one `protocols/<dimension>.json`, and one `batches/<comparison>__<dimension>/` with sorted records, scope, verifier code, `quality_stage4_job.sh` and SHA256SUMS. E4/E6 use the same protocol bytes as main per dimension but distinct paired batch identities. Camera motion is excluded because this fixed cohort has no explicit supported camera instructions; it is NOT_APPLICABLE. The shell uses the VBench Python 3.10 environment; actual partition/account/QoS/GPU/wall resources must be supplied explicitly by the separately reviewed dispatcher.

Engineering evidence: `test_quality_stage4_prepare.py` exercises 55/6/6 composition, sorted record scopes, shared protocol, E6/duplicate rejection, and all required protocol keys using fake inputs. A read-only CPU metadata probe checked the actual completed Dense job 168900, nine source receipts/videos/latents and 36 NFE; 11 actual VBench image SHA values match the V2 conditions. Python 3.10 AST parsing and `/bin/bash -n` passed. This is not a metric run, a decoder check or full asset-SHA revalidation. Remaining blockers are actual reviewed successful main approximate, E4 and conditional E6 generation, complete frozen comparison/decision, explicit reviewed metric budgets, independent review and live resource/closure verification.
