# FFNDS · 广泛深入 Web Search / Literature & Code Discovery

**适用：** 所有以科研探索、现象发现、机理推导、文献查重、方法讨论、跨 Agent 独立评议或方案调整为目标的 FFNDS Agent。由根 `AGENTS.md` 和 FFNDS domain skill 引入，具体问题按 `research/ACTIVE_RESEARCH.json.current_stage` 执行；当前 **E0_OPEN_DISCOVERY** 的产出仍是现象、竞争解释、区分性观察，**不是默认设计算子**。

> **研究默认动作：先开展广泛、深入、迭代式的联网检索，再形成文献定位与机制判断。** 不满足于一次搜索、热门论文列表、原论文摘要或单个 GPT/Agent 的二手陈述。已有源码/实验仍需直接检查，不可用网上综述替代。

## 1 · 怎样做到“广泛”而不是关键词碰运气

围绕正在讨论的科学现象，**主动覆盖多个互补方向**，既检索该现象本身，也检索与它竞争的解释或可迁移的邻近领域：

- **科学对象：** 视频扩散/Flow Matching/DiT、Wan 及少步蒸馏；跨步、跨层与时空表示；FFN / GELU / gate / residual / attention。
- **信息结构：** 动态稀疏、token/channel/group sensitivity、FFN 有效特征、signed cancellation、信息瓶颈、conditional computation、价值信息、时空相关性。
- **量化与算子：** HiF4 QDQ、W4A4、FP4/E2M1、MXFP4/E8M0、NVFP4/E4M3、scaled GEMM/Tensor Core、量化副信息、scale/exponent/code distribution、native versus QDQ。
- **相邻原理与反例：** 非线性与量化耦合、码本几何、线性代数/随机矩阵、硬件执行图/packing、误差传播、视频稳定性与运动/背景细节。
- **时间与来源：** 最新预印本和会议录（尤其当前与前两年）、经典理论和早期工程实现；不要用只看“最近”的方法漏掉已知同构机制。

至少从**现象描述 / 数学关系 / 方法功能 / 已知失败形态 / 工程算子名称**等互补表述中选择多个入口。中文关键词与英文专业术语分别扩展；拼写变体、别名、作者引用与论文改名都应考虑。**搜索内容从问题和新结果动态扩展，不限定上述固定清单。**

## 2 · 怎样做到“深入”：多轮追踪到原始证据

按研究价值迭代，而不是凑次数：

1. **宽检索建立领域图：** 先了解有哪些经典线、领先路线、反向结果、基础定义和相邻迁移线，识别关键词盲区。
2. **机制级深挖：** 阅读高相关论文的**方法、核心方程、计算图、实验设置、消融及失败条件**；源代码/配置存在时核对关键实现，而不是凭标题或 abstract 宣称“重复/创新”。
3. **引用图扩展：** 从高相关种子做 backward references、forward citations、同作者前后版本、相似论文和公开代码对照，主动查找与本假说冲突的研究。
4. **交叉源验证：** 论文作者 PDF/会议官方页面与官方仓库、模型源码和格式/硬件厂商规范互相核验；学术索引用于**发现**，不把索引摘要当作数学/性能证据。
5. **补漏再次检索：** 按新发现的机制、失败现象、同构算子和关键术语回搜，直到继续检索几乎不改变候选解释及最近先例的判断；记录仍未覆盖之处。不要把少量搜索结果或无结果当作学术“无人做过”的证明。

**可用的互补入口（视工具与访问权限选择）：** arXiv、OpenReview、NeurIPS/ICLR/CVPR/ICML 正式论文或 proceedings、作者/研究机构网站、Google Scholar、Semantic Scholar、OpenAlex、GitHub 官方仓库、模型厂商/OCP/NVIDIA 的格式与算子规范。Semantic Scholar 可沿引用/参考文献和推荐展开；OpenAlex 支持全文检索及发表日期等过滤（注意“发表时间”不等于“索引最近更新时间”）。见：
- [Semantic Scholar Academic Graph API](https://api.semanticscholar.org/api-docs/)
- [Semantic Scholar Recommendations API](https://api.semanticscholar.org/api-docs/recommendations)
- [OpenAlex search](https://help.openalex.org/api/searching/)
- [OpenAlex filtering](https://help.openalex.org/api/filtering/)

研究平台的系统限制若使联网不可用，应在成果中**明确标注未进行实时 Web Search**，先借助仓库现存论文/索引做可验证的最优分析，保留具体待补查询；绝不虚构已联网检索或声称“全面查重通过”。不能将禁网限制解释为禁止做科学推理。

## 3 · 文献查重必须到“机制层”，不只比标题或关键词

对最接近的工作，要核查：

- **对象**：实际研究的模型/任务、是否视频、是否少步蒸馏、是否量化、何种硬件格式；
- **输入/信息时机**：是否在决策前真可获得、是否偷用了完全 FFN / oracle / 未来视频信息；
- **数学和计算流**：原理、非线性/量化/缩放顺序、条件假设、关键等价变换；
- **执行动作**：到底省了什么原生 GEMM/QDQ/搬运/同步，还是仅改变了逻辑掩码；
- **证据**：原始实验设置、量化/质量指标、被测视频模型、负面结果；
- **关系**：`同一方法` / `共有基础组件` / `相似思想但不同机制` / `可迁移的相邻先例` / `尚不明`。不得因共用 FP4、稀疏或 Proxy 术语而一概判重复，也不得因修改名称就判原创。

主动搜索**最强竞争解释与反例**，而不只是找支持提议的引用。特别比较历史 Proxy+HWG、静态/动态组选择、FP4 LUT/稀疏算子、跨层或时空计算复用等最近先例；随发现持续更新，不限制于旧提案集。

## 4 · 每轮科研成果可追溯的最小网络证据

写出足够使另一 Agent **独立复查**的内容即可，不机械堆砌数十篇论文：

- **检索轨迹摘要：** 搜索日期、实际可用的平台、几组有差异的检索式或检索方向、如何通过引用/代码改变了原假设；明确 Web 未覆盖或不可用部分。
- **核心参考**：论文题名、作者/年份、版本/DOI/arXiv/官方链接、关键方程/源代码路径或章节；引用新旧工作分开，对最新 claims 标明查询截止日期与发表日期。
- **发现了什么、没发现什么：** 一个具体新机理、一条竞争先例、一个可区分的来源事实或未被原工作解决的结构；说明它们如何改变研究假说，不输出无决策价值的文献目录。
- **科学证据等级**：`PRIMARY_PAPER` / `OFFICIAL_CODE_OR_SPEC` / `ARCHIVED_WAN_MEASUREMENT` / `MATH_CONDITIONAL` / `SECONDARY_INDEX` / `CONJECTURE`；互不冒充。
- **查重判断的边界**：只能称“在已检索范围未发现同构实现”，不能声称互联网/文献已被穷举。
- **最有价值下一问**：一个可让竞争机制得出不同预言的源核对、证明或后续有权限的数据检查。

## 5 · 多 Agent 如何防止同质化检索

多个发现者可以**独立扩展互补文献簇**（量化/硬件、FFN 内部几何、少步蒸馏与视频时空、下游敏感性），也允许主动跨簇查重；禁止将 Agent 拆分为只收集相同关键词的复制者。Reviewer 需执行自己的**对抗性检索**：找最接近的潜在重复论文、不同格式下的反例、公开源码真实行为，再讨论被评议版本的精确命题。记录是否看过其他 Agent 的已有评议；不以独立检索的口号代替真正不同的证据。

### E0 防偏航

Web Search 的目标是**打开新的现象与解释空间**，不是搜索到一个方法就立刻实施，也不是为了“赶紧找到 10 篇”而回到 G6D/G6E/G6F。文献中出现的漂亮算子可以成为 `idea seed`；优先抽取其揭示的结构、适用前提、最近反例与在 Wan 中仍未知的现象。

### 权限与资源边界

Web 搜索和**只读**论文/公开源码/规范不等于模型实验授权。当前多 Agent 只讨论方法；CPU/GPU/model、Slurm、下载/运行大型权重、外部网页交互写入和自动重试均遵守当前用户权限。没有可用检索工具时不承诺未来后台完成检索。**这是研究质量指导，不是固定检索次数、强制大上下文或禁止创新的审批表。**
