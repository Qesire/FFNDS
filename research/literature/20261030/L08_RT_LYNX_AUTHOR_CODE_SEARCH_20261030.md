What the original paper does establish: Algorithm 1 uses 2:4 TopK on activation X and a norm compensation factor `sqrt(||X||²/(||TopK(X)||²+1e-8))`; §4.1 presents a single 1×4 example, whereas Algorithm 1 writes X as an N×Din matrix without specifying an implementation reduction axis. Removing the trained LoRA branch corresponds to the separately reported SA-NC ablation, not the full RT-Lynx method. Figure 4(c)'s signed example retains a negative value of larger magnitude, suggesting magnitude selection in that illustration; it does not establish a full implementation comparator or tie policy.

The following remain **UNKNOWN** at source-code level: whether the compensation norm is computed per 4-group, per row, per tile or over a wider tensor; comparator and deterministic tie rule; dtype/accumulation/rounding and zero/nonfinite handling; and which GPU architectures and dtypes the authors' fused kernel actually accepts. The paper states image quality was evaluated in FP16 and reports general NVIDIA sparse Tensor Core formats including BF16; that hardware-format table is not evidence that the unlocated RT-Lynx kernel supports BF16 on A100 or SM120. Do not call a guessed Wan SA-NC implementation an author-code reproduction.
