# 配对 value 完整轨迹的独立复核

日期：2026-11-27。证据固定于 `b26f644923646dcd9d853849cf58fdd122c55a54`，学校 A100 作业 `204740`。本轮独立计算公开收据中的配对差、几何比及误差方向，并检查运行源码身份；没有取得原始张量或 MP4，未重新提取其指标，新增模型/GPU 执行为 0。

## 当前判断

完整 128×128 配对运输已经进入正常四步生成、40 层低噪命中，方法从局部构造走到了真实自由轨迹。四来源结果显示它确实改变了最终 latent 与视频；相对当前对角 centered 的收益主要尚停留在局部机制，完整轨迹对 Dense 的距离只有 0800 一源改善，像素距离四源均小幅增加。当前证据支持保留对角 centered 为工作参照，把新矩阵作为具有明确机制证据、尚未带来稳定终点增益的候选。

## 1. 比较身份和已经核验的内容

- 来源为 DEV 0392、0800、1013，以及对本次 paired-value 机制留出的 0128。后者不自动等同于整个 FFNDS 项目从未使用的来源。
- seed 42，四步 HHLL，832×464、81 帧、16 fps，FFN 均为 BF16 wide8192。每来源每臂一次生成，顺序为 B/C、C/B、B/C、C/B。
- B 为当前 centered 对角运输，C 为同位置配对完整通道运输；二者保持高噪恢复、低噪路由、CAL32、原生 P64、256 个配对位置与其它模块相同。
- 八个候选均记录 160 attention sites、80 anchors、80 hits、5120 原生 probe queries。这里 5120=80×64 是全部两个命中步、40 层的 query 行数，并非每层或仅低噪的数量。
- 四来源 B/C 的初始噪声、前三步 flow/latent hash 相同；相应公开相对 L2 均为零。E2E scores 所复制的逐步张量误差与原 receipt 完全一致。
- E2E 运行脚本及配对算子脚本的本地 SHA-256 与学校执行清单吻合。
- 三个 DEV 来源复用 jobs 190819、190827、190713 的 Dense 与原生 attention＋wide8192 控制；0128 的两个控制由本次 job 204740 生成。复用控制用于数值配对，不提供同批计时对照。

## 3. 由现有范数还能知道什么

记 B、C 为同一来源的两个最终向量，R 为 Dense 参照。令 e=R−B，d=C−B，则

\[
\|e\|^2-\|e-d\|^2=2\langle e,d\rangle-\|d\|^2.
\]

公开的 B/R、C/R 与 C/B RMSE 具有相同坐标数，因此可以由极化恒等式恢复对应内积。这不是新的模型运行，也不依赖线性化。

| 来源 | 最终 latent 的更新与 e 的余弦 | 完整更新获益所需阈值 \(\|d\|/(2\|e\|)\) |
|---|---:|---:|
| 0392 | −0.019100 | 0.022866 |
| 0800 | 0.071391 | 0.043174 |
| 1013 | 0.014133 | 0.046574 |
| 0128 | 0.047485 | 0.049306 |

C 对 B 的最终 latent 相对 L2 为 1.59%–2.19%，视频间 RGB RMSE 为 0.02322–0.03806；新增算子确实产生可测的全局变化。该变化与减少现有 Dense 误差的方向大多接近正交，只有 0800 的方向和幅度一起越过获益阈值。RGB 上四源均有朝 Dense 的正向分量，但完整幅度的平方代价仍更大。

这支持把“有可预测的 value 变化”“更新在全轨迹中产生作用”“更新减少目标终点误差”作为三个不同的可观测关系。上述欧氏方向是当前固定配对的几何，不等于动作语义或人眼质量，不建议据此再做后验系数扫描。

## 4. 执行时间与显存读数

`formal_timing=false`，且运行包含轨迹保存。每来源只有一次 B/C 生成，没有专门预热和正式重复计时。0392 的第一个 B 包含 80 个新 packing site，墙钟 88.22 秒，而 C 为 35.43 秒；这个差值明显不能作为新矩阵加速的证据。

| 来源 | 低噪命中 step3，B→C（ms） | C/B | 峰值 allocated 增量（MiB） |
|---|---:|---:|---:|
| 0392 | 4633.736→5399.750 | 1.165313 | 292.460 |
| 0800 | 4642.699→4801.801 | 1.034269 | 115.052 |
| 1013 | 4618.104→4718.496 | 1.021739 | 114.386 |
| 0128 | 4604.199→5187.125 | 1.126607 | 115.052 |

后面三次 B 峰值约 64.6514 GiB，C 约 64.7631–64.7638 GiB。约 114–115 MiB 的附加峰值与此前逻辑 100 MiB anchor 样本预算加临时量的方向一致；它仍是这次带观测执行的峰值。step3 四次均增加，记录提示新矩阵有实际成本；正式生产时延应单独计量，不能把此表当作最终性能结论。

E2E 候选运行的原生 attention 标签来自原有 P64，两个控制运行与其逐步误差比较在候选生成之外完成。没有看到为候选每层额外计算全行 Dense 输出的路径；完整轨迹保存、编码和读回的开销属于本次诊断执行。

## 5. 原片与当前交付缺项

学校收据列出 16 条不同的 MP4 SHA-256，评分脚本按 `<source>_<arm>.mp4` 读取四种视频并核验视频指纹。当前新增仓库文件只提供哈希与该命名约定，未给出可访问的原片 URL 或具体媒体目录，本地也无这些 MP4。故本次可复核公开数值和来源身份，不能在此重新评分或代替人审。

新的根 AGENTS 要求成片报告同时交付原片链接与逐来源指标；逐来源指标已齐，原片可访问链接仍是交付缺项。尚无本轮完整矩阵视频的用户判读，也无 SparsePR v2 的自由轨迹成片臂。
