# 冻结 C 的六簇确认：计算收益、整片交付与质量证据的当前位置

> 后续更新（2026-11-25）：用户已经反馈六来源C/A“基本没有差别”。[人审记录](C_CONFIRM_HUMAN_REVIEW_20261125.json)保留实际范围；后续工作已进入[新的推导与论证](NEW_DERIVATIONS_AFTER_SIX_SOURCE_REVIEW.md)。以下保留人审到达之前的分析，文中PENDING描述属于当时状态。

证据固定于 FFNDS `c5e4ee8168708a8e57cdb981103c4dbf715e3bfa`，学校 A100-SXM4-80GB 作业 196504。此文复算已有执行回执、保存时间戳及运动汇总，未重新运行模型或解码视频。

## 当前判断

**六个独立选择的来源簇再次呈现了同一种计算收益：C 的两个恢复步节省时间，low 建锚承担附加成本，四步 GPU 的净时间在六对中均下降。** 六簇等权几何平均 C/A 为 0.865241，即减少约 13.48%。这使 attention 与 wide8192 的组合收益从原两个开发来源扩展到已冻结的新来源。

完整请求从生成入口到 VAE、视频编码与保存全部纳入的正式统计为 1.031752，即 C 的几何平均用时约高 3.18%。最大的时间变化位于保存阶段；全请求结论应保留这一实际后果。逐片扣除已记录保存区间后为 0.880828，只用于判断长尾发生在哪个阶段。

**完整动作和画面质量仍为 PENDING。** 当前六对运动代理没有出现 0392/C0 那样的大幅收缩，完整人审将决定 C 的质量证据能否覆盖这六个来源。研究主线可以收束到这一完整方法的质量—成本—状态需求，而无需继续依赖局部重拟合来决定已有 C 的价值。

## 1. 实际比较对象与独立单位

A 与 C 均使用 BF16 wide8192 FFN；C 在 attention 上采用 native / OUT-ABS / native / OUT-D，A 四步 attention 均原生。共同配置为 81 帧、832×464、seed42、P64、high-high-low-low。实际回执中六对初始状态与第 0 步 flow/latent 相同，FFN 每片为 80 次 anchor 和 80 次 hit，C attention 为 80 次 anchor、80 次恢复和 5120 个全键原生 probe query。

每个来源簇只运行一对正式 warm A/C，顺序按冻结清单交替。模型初始化约 603.907 s，wide 结构设置约 22.628 s，分别登记，不计入 warm 请求时间。两臂先在旧 DEV0392 暖机并核验原有轨迹；这次冻结 C 没有切入 phase0 专用适配器。

来源选择的原始执行清单与方法指纹已由 runner 绑定。公开来源清单归档删去了服务器路径和 prompt 正文，保存图像及 prompt 哈希、完整排除簇和原始未删减清单指纹。复算核对方法文件、执行文件和 observed registry 的字节指纹一致，并核对六个不同簇不在 56 簇排除清单中。

另核查 [在线源文件身份](confirm_source_identity.json)：冻结方法绑定的 attention 源文件 SHA256 为 8781a7983461e5c0042e1e0f4d58e545c2cab5b7508d35dc450e2de87b07dcee，两个仓库证据版本字节一致。前轮分析工作副本仅多出一个末尾 LF；该工作副本指纹差别没有引入代码语义变化。

这项独立性以公开的历史、既有生成输出和 CAL/DEV 台账为范围。新选择来自 355 个具有裁切图的候选簇，排除后有 299 个；按室内/建筑、自然/植物、人物/动物各选两个。代码从已归档输出与回执登记访问史，不把目录中的名字出现本身当作已审看模型结果。

统计单位为六个来源簇，每簇一对；不同 head、视频帧和 GPU 步数均不扩充独立样本数。实际使用了这些六簇后，它们成为已访问来源。

### 保存长尾可以被定位到阶段

对来源 0987：

- C−A 的保存区间差为 156.046−39.356 = **116.690 s**；
- C−A 的完整请求差为 **112.136 s**；
- 去掉保存区间后的其他请求部分，C 相对 A 节省 **4.554 s**；
- 四步 GPU 相对节省 **4.497 s**。

这表明该来源的完整请求逆转集中在保存路径。保存区间包含编码及其间其他开销；当前记录尚未把其中时间分成编码、文件写入、调度等待等来源，也没有通过重复测量确定其重现率。正式表保留该来源及原始边界。

跨六簇用可加的平均有符号差表示：

\[
\underbrace{13.9427}_{\Delta T_{\rm full}}
=
\underbrace{18.4807}_{\Delta T_{\rm save\ interval}}
+
\underbrace{(-4.5380)}_{\Delta(T_{\rm full}-T_{\rm save\ interval})}
\quad{\rm s}.
\]

后一个算术差进一步包含 GPU −4.1469 s 和余项 −0.3911 s。余项是通过两项已测量时间相减得到的量，不能直接命名成独立实测的 CPU 耗时。几何均值是比值统计，不能按这一加法直接拆分；上式特意使用平均有符号秒数。

## 3. 本轮重现了原方法的周期成本结构

C−A 的四步 GPU 平均变化为：

| 阶段 | step0 原生 | step1 high 恢复 | step2 low 建锚 | step3 low 恢复 | 合计 |
|---|---:|---:|---:|---:|---:|
| 平均变化 / s | +0.1190 | −2.8663 | +1.3000 | −2.6996 | **−4.1469** |

两个恢复步合计省约 5.566 s，承担 low 建锚和其他步差后，仍获得四步净收益。这个模式与开发来源阶段一致，支持锚点与恢复必须按真实调用周期共同评价的认识。

A/C 的峰值 allocated 为 47.5671 / 65.4123 GiB，相差 **17.8452 GiB**。同一张 A100 能运行两者，使这次计时可比；容量差也属于方法部署需求。C 的明确成果是用附加状态换取生成计算收益，质量是否在六个新来源上保持由完整审看决定。

对于后续工程，已有信息足以把问题分开处理：模型算子的周期收益已有六来源事件计时，交付时间的主要变异发生在保存路径。继续调 attention 的局部读出并不能直接回答保存长尾的成因。

## 5. 回到核心问题，这批数据支持怎样的主张

1. **结构化 attention 恢复与 wide8192 的联合执行已经形成可重复的周期计算收益。** 这次六个新来源均重现了收益来自恢复步、成本集中于 low 建锚的结构；它跨出了原两个开发来源。

2. **方法价值要同时包含生成行为、调用周期和状态容量。** GPU 净节省约 13.48%，对应增加约 17.85 GiB 峰值；二者共同刻画当前实现的资源取舍。最终接受程度由这些资源取舍与成片质量共同决定。

3. **下一项最有信息量的既有资产是六对完整视频的人审。** 它们已经产生，且拥有匹配输入、冻结方法和真实计时。当前阶段可以先完成这项完整证据链，再决定沿哪类模块或状态结构扩展。

4. **完整交付时间需要同样明确的系统边界。** 当前模型计算收益与保存长尾可以同时为真。若要确认端到端加速，需要在同一完整请求边界处理或测量保存变异；已发布全周期结果保留，任何扣除保存的数字继续标为诊断。

这批结果不需要触发新的 P、rank、λ 扫描。它们把研究从“某个局部恢复器还能改善多少”推进到“当前完整算法以什么状态成本保留什么生成行为，并在什么执行边界实现收益”。
