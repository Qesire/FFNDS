# C0 之后：按计算阶段组织 attention 与 wide8192 的联合恢复

依据：FFNDS `9abe82a6e5131d86f4f4ac5f5c7ba30312da2bff` 的作业 `196295`；保留上一轮 C 的完整轨迹、人审和计时证据。采用 evidence-analysis、operator-tensor-analysis 与 active-abstraction。独立复算原始回执、审查真实代码，并用 SymPy 核验实际读出公式；本轮新增模型/GPU执行数为 0，也没有重新观看视频。视频质量判断引用仓库保存的人审记录。

## 1. 这次结果确立了什么

**现有证据支持把 C 作为工作候选，并把“初始状态构建时的 attention 恢复”单独作为下一项有限研究问题。** 这比按照模块名称一概判断 attention 能否近似，更接近最初的问题。

旧 C 在 wide8192 FFN 的真实执行路径上，采用 high OUT-ABS / low OUT-D，用户对 A/B/C 的完整视频报告肉眼几乎没有区别；C 相对 A 的整片配对时间节省约 12.01%。新 C0 只把 C 的 high step0 的 40 层 attention 改成当前 OUT-ABS，后续继续在自身状态上执行。它再节省 9.25% 的整片时间，但仓库记录的逐来源人审指出，0392 的 C0“直接不动了”，1013 的 C0“变化不大”。因此，这一新增调度没有通过当前的运动质量筛查；原 C 的证据仍然成立。

## 2. 回到最初问题：跨模块推广已经得到了什么支持

最初要验证的核心是：能否用廉价结构计算、有限当前观测及必要的历史状态，恢复网络真正需要的计算结果。旧 C 已经给出一个具体的肯定实例：attention 的恢复可与 wide8192 FFN 连续执行，整个四步、40 层轨迹能够生成视觉可接受的视频，并节省完整执行时间。

C 的 low OUT-D 还给出了与原方法对应的具体过程。对一个 query/head，在实数模型中可写为

\[
\widehat A_s=A_a+(1-\rho_a)(O_s^S-O_a^S)+X_s\Theta_h.
\]

\(A_a\) 是该位置的原生锚点，\(O^S\) 是当前选中支持的输出，\(\rho_a\) 是锚点未选中质量；\(\Theta_h\) 由当前 P64 原生观察拟合。原生起点、真实已计算的有限变化和当前稀疏监督共同构成恢复。实际实现另包含缓存与特征的 BF16 舍入，推导和实际计时见[上一轮分析](ONLINE_REVIEW_AND_NEXT.md)。这使“可以扩展”落实到已有过程及其信息来源。

本轮让这个结论进一步精确：**恢复机制可以跨模块组合，但其适用条件还依赖它在状态演化中承担的工作。** C 中 high step1 的 OUT-ABS 与 C0 中 high step0 的 OUT-ABS 使用相同形式的读出，面对的输入分布和后续责任却不同。step0 同时影响当前 flow、后续层输入、FFN 锚点、attention 路由和下一步 latent。命中步的恢复则发生在这些状态已经由先前计算建立之后。

因此，值得推广的对象是“某一计算阶段上的恢复接口”，其中应包含输入状态、可用观测、缓存读写和后续任务，而不只是某个模块的函数签名。现有 C 对这种推广提供了实现和端到端证据；C0 给出了阶段条件需要单独检验的实例。

“原生初始化承载运动建立，近似只适合后续更新”是与结果一致的工作解释，尚不能写成所有模型或所有来源都成立的分工定理。当前 C0 还混入了一个可检验因素：固定 CAL 来自 high 命中步，而这次将其直接用在 high step0。

## 3. 正确的分析对象是扩展状态

令第 s 步开始时的状态为

\[
z_s=(x_s,c_s^{\mathrm{FFN}},r_s^{\mathrm{attn}},c_s^{\mathrm{attn}},\ldots),
\]

其中 x 是 latent，其他分量是实际会被后续计算读取的锚点、路由和缓存。C 与 C0 从同一个初始状态出发：

\[
z_1=\mathcal T_0(z_0),\qquad
\widehat z_1=\widehat{\mathcal T}_0(z_0).
\]

随后二者执行相同的调度规则 \(\mathcal F=\mathcal T_3\circ\mathcal T_2\circ\mathcal T_1\)，但输入状态已经不同。视频上的差别是

\[
\Delta v=\mathcal D\mathcal F(\widehat z_1)-\mathcal D\mathcal F(z_1).
\]

这里“相同规则”允许同一规则在不同输入上选择不同路由，并建立不同数值的缓存。这正是本轮的真实执行。FFN 在 step0、step2 原生执行，只保证 FFN 对其当前输入按原生算法计算；它写出的缓存也条件于当前输入。这个动作不会自动把另一条轨迹的状态接回来。

### 3.1 不使用原生 attention 输出作为缓存，仍可能依赖它建立状态

high OUT-ABS 的缓存只需要路由，因此从其局部缓存依赖看，step0 可以直接构造当前路由并恢复 attention。C0 的实现和计时已经证实这种构造可执行。

但原生 step0 attention 输出同时进入主计算图：经过投影、残差、cross-attention 和 FFN 后，形成下一层输入，并参与 FFN 建锚。局部恢复缓存无需保存某个张量，并不能说明主图无需它原本产生的状态。新结果恰好把这两个层次分开。

### 3.2 当前 P64 教师约束的是候选当前状态

设 C 在某层的输入是 x，C0 是 \(\widehat x\)。实际代码的 P64 原生子查询使用 C0 当前的 Q/K/V，并在预测末尾用该子查询输出直接覆盖这些行。把 A 定义为实数域原生 attention 算子，则有下面的条件等式；实际浮点执行中，P 行与子查询结果逐位相同，全行原生核与子查询核之间的数值差另由既有核验约束：

\[
\widehat A(\widehat x)_P=A(\widehat x)_P.
\]

与 C 的输出比较，则有

\[
\bigl[\widehat A(\widehat x)-A(x)\bigr]_P
=\bigl[A(\widehat x)-A(x)\bigr]_P.
\]

这是当前方法最重要的条件关系：P64 提供了对**当前输入上的算子**的真实观测。它们会提高当前算子恢复的准确性，却没有额外提供另一条参考轨迹的状态。后续原生调用同样以当前状态为条件。

令 B 返回经过本层后续操作的连续隐状态，z 包含它实际读取的输入和缓存条件。对这一连续读出可精确拆分

\[
\begin{aligned}
\widehat h_{\ell+1}-h_{\ell+1}
={}&\bigl[B(\widehat z_\ell,\widehat A(\widehat z_\ell))
-B(\widehat z_\ell,A(\widehat z_\ell))\bigr]\\
&+\bigl[B(\widehat z_\ell,A(\widehat z_\ell))
-B(z_\ell,A(z_\ell))\bigr].
\end{aligned}
\]

第一项描述当前状态上的算子近似，第二项描述已有状态差别经原生计算继续传播。这个等式说明为什么“局部教师是真值”和“整条轨迹保持任务行为”需要分别验证，并不预设传播必然放大或必然收缩。

## 4. 用什么数学条件判断信息是否足够

### 4.1 先写出真实恢复类

每个 head 有 N=31,668 个查询，输出维数 128；在线设计矩阵 X 包括 31 个投影特征和常数列，教师行数为 64。对于 OUT-ABS，令 B 为选中支持上的 attention，\(R=A-B\)。覆盖教师行之前，实际读出为

\[
\widehat A
=B+X(X_P^{\mathsf T}X_P+64\lambda I)^{-1}X_P^{\mathsf T}R_P.
\]

随后把 P 行改写为当前原生 attention。P 行的精确性因此是直接执行保证；其他行依靠 X 所定义的残差恢复类。

在理想化的 \(\lambda=0\)、\(R=X\Theta\) 条件下，P 对该恢复类充分的精确条件是

\[
\ker X_P\subseteq\ker X.
\]

当 X 本身具有完整列秩时，这可由 \(\operatorname{rank}X_P=32\) 保证。这里 64 行多于 32 列，说明观测数量与这个恢复类在维数上兼容。它仍需要恢复类确实覆盖所需残差，以及采样在数值上可辨识。固定 \(\lambda>0\) 还引入明确的收缩偏差；P64 并不自动保证恢复所有未观测查询。

这些条件把“信息足够”落实为三个独立问题：保留了什么函数类、观测能否区分该类、误差经后续计算后是否仍保留任务行为。C 的成片结果是这三者组合有效的证据；C0 指出这套组合在新增阶段和 0392 上出现任务偏差。

### 4.2 任务充分性需要覆盖后续计算

设 \(\alpha(z)\) 表示一个压缩接口保留的信息，\(\Psi\) 表示最终任务观测。若希望仅凭 \(\alpha(z)\) 决定后续任务，则必要且充分的精确条件是

\[
\alpha(z)=\alpha(z')\Longrightarrow
\Psi(\mathcal F(z))=\Psi(\mathcal F(z')).
\]

这称为目标在表示纤维上的一致性。近似问题可把等号改为任务容许偏差。若还要求用压缩状态连续推进，则还需相应的状态闭合条件；只对某一层的输出拟合良好，并不能自行保证这种闭合。

本轮没有记录足够状态来实测这个一般条件，更没有建立信息不可恢复定理。它提供了一个可操作的方向：为初始状态构建选择的恢复表示，应由它对后续行为的保留来评价。

### 4.3 总范数与运动方向

0392 的 step0 flow 相对差为 27.225%，step0 latent 相对差为 2.289%，最终 latent 相对差为 56.140%；1013 对应为 9.404%、0.887%、16.261%。这些数值与不同的成片后果一致，但其比值不能用作 Jacobian 放大率：各步分母不同，状态与缓存不同，离散路由也可能改变。

实际 scheduler 使用 \(x_{s+1}=x_s+(\sigma_{s+1}-\sigma_s)f_s\)，末步取后一个 sigma 为零。因此两条轨迹的差别按其**各自实际 flow 差**累积；仅看逐步相对 latent 范数，无法区分绝对误差累积、参考范数变化及不同方向之间的抵消。

若在路由不变、其余算子光滑的局部区域，把最终运动观测记为 \(m(z)=\Psi\mathcal D\mathcal F(z)\)，其误差的一阶形式是 \(Dm(z)\delta z\)。影响运动的是误差相对任务敏感方向的分量；\(\|\delta z\|\) 只给出一个总体大小。跨路由边界时应直接分析有限差别，不能把这一局部导数当成全局精确传播模型。

本轮的运动视频给了我们任务证据，而不是只能借助范数猜测任务。它支持将“恢复运动生成所需状态”作为下一阶段的评价对象。

## 5. 三种竞争解释及证据边界

| 解释 | 现有支持 | 仍未区分的部分 |
|---|---|---|
| 初始化与后续更新所需的恢复表示不同 | 唯一步骤干预改变了整片运动，旧 C 保持可接受表现 | 尚未证实原生 step0 本身不可替代；当前恢复坐标可能没有适配该阶段 |
| high CAL 从命中步迁移到 step0 存在分布失配 | 代码使用同一 high out_current 基与 λ；先前 CAL 的 out_current 取命中端 | 未测阶段专属 CAL；已有 CAL 归档的原生上游状态也不同于 C0 的后续层当前状态 |
| 误差在运动相关方向上造成明显影响，0392 更敏感 | 人审与完整视频代理共同显示 0392 的运动大幅收缩 | 目前没有测得任务敏感子空间，不能由两个来源建立一般运动风险规则 |

它们可以同时成立。路由 hash 的匹配层数在两个来源上完全一致，不能用来在上述解释之间作因果选择。

## 6. 下一步的优先级：确认 C，首步只做一次阶段适配

首要工作是冻结 C，并用独立来源判断其完整视频、运动与成本能否保持。可复用既有六个 fresh source cluster 的选择与历史排除规则；C/A 的端到端质量和时间是新的确认对象，应先登记这一目标，保留原 FIN 对比的历史范围。此处尚未选择或执行确认来源。

若继续研究首步，只新增一个明确的候选：**C0-phase0CAL**。该候选保持 C0 的全部 40 层 step0 替换、P64、31+常数的维数、选中支持规则、FFN 时序和 low OUT-D，只为 high step0 使用由原 CAL 来源的 anchor 端构造的 out_current 基及特征 RMS 归一化。固定原 λ=0.1，输出尺度也保持原值。high step1 继续使用已验证的原 high CAL。

这种构造直接检验“恢复坐标的阶段适配能否使相同观测与执行预算胜任状态构建”。按层二分会同时改变近似调用数、原生信息量和干预位置，先回答的是替换多少层；增加 P 则改变观测预算。阶段适配更接近本轮产生的新问题。

### 6.1 现有代码导出的一个简化

OUT-ABS 计算中，target 先除以 `scale_r`，线性 ridge 解后再乘以同一个 `scale_r`。在精确算术中，这个统一输出尺度完全消去，得到第 4 节的公式；`mass_rms` 在该分支也没有参与。已用 SymPy 按真实矩阵维数作符号核验，脚本为 [verify_outabs_scale.py](verify_outabs_scale.py)，结果为 [outabs_scale_identity.json](outabs_scale_identity.json)。这不是模型重跑，实际浮点舍入仍可能留下很小差别。

因此，本次阶段适配真正改变的是：

- out_current 的 31 维特征子空间；
- 进入该子空间前的通道 RMS 归一化，从而改变设计矩阵与正则化的几何；
- 相同固定 λ 在新设计矩阵上所起的正则化作用；λ 数值本身保持不变。

现有 `transform_cal` 先按通道 RMS 归一化，再取相关 Gram 的前 31 个特征向量。为 step0 重建这部分比笼统“重调输出尺度”有明确的数学含义。

### 6.2 资产复用与实施前提

现有 panel 读取代码明确含 `o_native[0]` 和 `o_selected[0]` 的 anchor 端；`prepare` 当前为 out_current 选择的是命中端。可使用原 CAL0032/0304/0456 的封存 anchor 端，构造 `selected0 @ P_v` 的 out_current 统计，来源权重、背景权重沿用原方案，只改变时间端点。这个固定 λ 的候选只需复用现有 anchor selected 输出及 P_v；anchor native 输出可供离线描述性核查。现有材料没有表明需要重新采集原生模型轨迹。

原 λ 评分使用 `downstream_point`，其中包含投影及 `self_gate_s`；目前核查到的拟合代码没有 `self_gate_a`。step0 专属下游评分需从原始 step0 端点或模型时间嵌入核实并取得相应 gate，不能称全套评分资产已经就绪。 原 λ 选择还使用 native numerical-noise 基线，当前代码同样绑定 hit_step；若重选 λ，必须同步改为 anchor_step 并生成相应评分回执。固定 λ 的构造绕开了这项额外依赖：只改变 step0 的 out_current 基及 RMS 归一化，不把 step1 gate 带入后标记为 step0 校准，也不依据 DEV 结果开启另一轮 λ 调整。

加载时应将 step0 CAL 与 step1 CAL 分开记录和校验，避免替换全局 high 项后无意同时改变已通过验证的 step1。规则保持相同，并不要求候选逐层路由或 FFN 锚点的数值与 C0 相同；它们应继续由各自真实输入产生。

### 6.3 一次成片检验与预先确定的处理

首个新生成只需针对已明确失败的 0392，沿用输入、seed42 和完整 81 帧，以封存 C/C0 为参考。判断对象是动作和时间推进是否恢复到可接受水平，视频人审为主；帧差、光流代理及逐步误差作为一致的辅助记录。本分支不按 CAL/DEV 局部误差进一步筛选超参数；只执行已规定的 anchor 端特征统计与基构造。局部误差可作描述性读数，完整成片决定这一构造是否成立。

若 0392 恢复，再检查 1013 是否保留原有表现，然后进行这一新候选的实际计时。相同形状及相同查询预算使其预期运行成本与 C0 接近，但实测之前仍不应直接继承 C0 的时间数字。

若这一次阶段适配仍未恢复 0392，就把该分支收束到“该维数、P64 和当前阶段适配下，step0 全层替换尚未保持运动”，C 继续推进后续来源验证。此时不再自动展开每层扫描、P 扩容或持续调 λ。

**成功和失败所能支持的结论不对称。** 成功将给出一个直接的肯定实例：同样观测预算经阶段适配，可以建立后续可用的初始状态。失败仅收窄这项修补；原生 CAL 的上游轨迹与 C0 layer1+ 的当前轨迹仍存在差别，因此不能由失败推出“step0 必须原生”或“信息在原理上无法恢复”。

## 7. 对研究主线的更新

目前最扎实的主线是：**用结构计算和稀疏当前观测恢复昂贵模块，在完整模型上按模块和阶段安排必要的状态建立与更新。** 已验证的 C 是这条主线的具体成果，新的 C0 使其中的“阶段”获得了可见的任务含义。

下一轮不需要先找出每一层的责任比例。阶段专属表示是一个过程清楚、预算固定、结果能区分解释的构造；它完成一次后，即可决定是否扩展 step0 分支。C 的来源泛化验证依然是把已有成果变为更稳健研究结论的工作，二者无需相互等待。

新颖性方面，这轮带来的是对自身机制的辨析：恢复类、当前观测与全图状态形成之间需要共同匹配。它尚不支持新的文献首创断言。后续比较工作仍应比较这些实际过程、依赖与可验证预测，避免仅因其他方法也追求推理加速或输出相似就判定重复。
