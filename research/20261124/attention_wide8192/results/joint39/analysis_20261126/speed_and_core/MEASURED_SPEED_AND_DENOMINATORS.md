2026-11-26。读取学校 A100 的 job 185220、199260 和 201500，实际新增执行为 CPU 收据复算。模型、GPU 作业、视频解码均为 0。

## 1. 当前可以直接报告的性能

## 2. C 的 18.52% 去噪节省从何而来

199260 的四个实际步骤拆分如下，秒数是全部平衡配对的均值：

| 实际区间 | Dense | C | C−Dense |
|---|---:|---:|---:|
| step0，high anchor | 7.86343 | 7.93420 | +0.07077 |
| step1，high hit | 7.87464 | 4.25580 | −3.61883 |
| step2，low anchor | 7.87003 | 9.03773 | +1.16771 |
| step3，low hit | 7.86026 | 4.41423 | −3.44603 |
| 两个 anchor 合计 | 15.73346 | 16.97194 | +1.23848 |
| 两个 hit 合计 | 15.73490 | 8.67003 | −7.06487 |

因此完整周期的实际节省是

\[
7.064867\text{ s 的 hit 节省}
-1.238479\text{ s 的 anchor 增量}
=5.826388\text{ s 的四步净节省}.
\]

四步 GPU 事件区间外的完整请求时间分别为 Dense 8.77690 秒、C 9.16085 秒，C 多 0.38395 秒，所以墙钟最终净省 5.44243 秒。这里的“事件区间外”包含 VAE、保存及其他流程，不应整体命名为 CPU 或单独保存开销。

这个分解把算法主作用钉在两个命中步，也把锚点费用放回了分母。四步 C 的净节省已有直接测量；仅引用某个 hit 的速度会高估整条流程。

## 3. 从已测份额可得到哪些条件上限

以下是保持其余实测成本不变、把指定工作假设为零的 Amdahl 反事实，只用于界定当前调度结构，不能作为可达到的性能预测。

### FFN-only 的影响范围

185220 中，全部 Dense FFN＋post 为 5.90631 秒，占四步 GPU 32.04845 秒的 18.4293%。两个 hit 的原 FFN＋post 为 2.95475 秒，占全 GPU 的 9.2196%。

因此，在保留两个原生 anchor、其他模块成本不变、并且假定新增 anchor 费用为零的条件下，即便两个 hit 的 FFN 完全免费，四步 GPU 最多也仅节省约 9.22%，倍率约 1.10156×。这一份额解释了为何 FFN-only 的 36.57% hit-FFN 节省最终对应约 3.55% 去噪节省，也解释了扩展 attention 的实际价值。

### 保留当前 C anchors 的极松上限

199260 的 C anchors 两步合计仍要 16.97194 秒。如果把两个完整 hit 步骤都当成免费，四步 GPU 也至少为这个数；相对本批 Dense 31.46836 秒，倍率最多约 1.85414×。

若进一步保持 C 的事件外耗时不变，完整请求下界为 34.80282−8.67003=26.13279 秒，对本批 Dense 的倍率最多约 1.54003×。

这两个上限把 hit 内的 QKV、输出投影、cross attention、状态更新等也假设为零，故非常宽松。更细的算术上限必须保留这些实际不变项，以及 selected 和 P64 的成本。

## 4. 当前 centered 的性能含义

centered 保留原来的全键教师、selected 支持、P64、high 调度、40层及四步次数。它主要改善已有历史槽的表示和当前读取方式，正式实现同时融合了统计、编码和解码。

201500 四对 low 周期和四步 GPU 均更快；完整墙钟两对快、两对慢，差的正负按本批运行顺序分开。0.60% 墙钟节省是两开发来源的顺序平衡观测。新视频“基本没问题”支持用户对本批 centered 画面的整体可接受判断，范围不自动扩成逐源分数或独立来源确认。

因此叙述应把完整 FFN＋attention 复用的 18.52% GPU 节省，与 centered 状态表示的额外 0.73% GPU 节省分开。后者是同一执行结构上的质量与成本改进；它不是当前全部方法加速的大小。

## 6. 蒸馏与本方法可以合并声称什么

设 \(T_T,T_S,T_{S+O}\) 是同任务、同硬件与计时定义下，原教师、四步蒸馏学生、学生叠加本方法的耗时。合法的总加速为

\[
\boxed{S_{total}=\frac{T_T}{T_{S+O}}
=\frac{T_T}{T_S}\frac{T_S}{T_{S+O}}.}
\]

这只是使用同一中间分母的恒等式，不需要假设两种方法的随机效果独立。来源等权几何平均也可以逐源分解，前提是使用相同来源集合、相同权重和对应的中间配置。

由此可以正面陈述“蒸馏＋本方法的合并系统加速”，并同时给出本方法在蒸馏学生上额外贡献的倍率。现有数据已经直接支持后一个数值；当前复核的收据中没有原始多步教师的匹配完整计时，所以当前总系统倍率尚未实测。

单独用教师步数除以4，得到的是某种调用次数比。实际 NFE 还需计入教师 CFG 的条件／无条件调用，学生 CFG 是否移除、批处理方式、每次调用的 kernel，以及 VAE／保存等固定成本。步骤比不会自动等于端到端时间比。

最经济的合并指标验证，是同一组来源和同一计时协议下保留三个完整臂：原教师、原生四步蒸馏学生、四步学生＋当前方法。总系统质量比较也绑定到这三组输出。现有六源 C／Dense 已经覆盖其中后两臂的一个冻结版本；本轮 centered 的两源视频反馈补充了当前状态表示的开发证据。

## 附录：一次性准备费的条件摊销

若将 job199260 记录的 wide8192 准备 22.4499 秒全部视为候选额外的一次性费用，并把本批每片预热后完整请求的均值净节省 5.44243 秒作为后续单片节省，则抵偿这项准备费需要

\[
m\ge\frac{22.4499}{5.44243}\approx4.125,
\]

即至少 5 片。该算例不含未单列的首次编译，也不含共同模型冷启动；它说明固定准备费如何随重复请求摊销，不是实际单片 cold-start 加速主张。
