# A100 激活 2:4：后端算法与布局的预打包对照

**已测现象（NATIVE-OBS，合成算子）**：默认配置下两种 Wan 形状的预打包 sparse 比 dense 慢，但算法搜索或权重布局可在部分设置获得较快的预打包乘法。因而前一默认路径的负例揭示了实际 backend/layout 自由度；它不证明在线激活稀疏能够提速，也不自动转移到其它内核或视频质量。

| M×K×N（M补齐至31680） | Dense 中位 CUDA ms | 默认 view、原输出连续 ms | 搜索 view、原输出连续 ms | contiguous 权重、默认 ms |
|---|---:|---:|---:|---:|
| 31668×5120×13824 | 20.035 | 28.268 | 16.415 | 17.392 |
| 31668×13824×5120 | 19.938 | 26.860 | 16.631 | 15.437 |

对应搜索 view 的预打包功能速度比为1.221×和1.199×；contiguous 权重默认比为1.152×和1.292×。改变输出布局时必须计入恢复连续输出：例如第一形状默认 transpose 原始 SpMM 14.155ms，但含输出连续化为21.989ms；第二形状 searched transpose 为14.905→18.968ms。权重连续布局拷贝分别测得1.657ms和1.253ms，应根据权重驻留与复用次数摊销。

这是固定合成 BF16 输入、A100 和 PyTorch 2.10/cuSPARSELt 701 的预先选择/压缩结果；不含在线 top2 选择与每次激活压缩，也未计量算法搜索内部执行的 kernel 数，**不能把预打包比值当完整在线速度**。搜索 API 实际调用8次、内部 kernel 数未知；记录的128 sparse GEMM 只是显式计数。稀疏输出对相同 masked dense 的相对L2误差分别为6.07e−5和1.22e−4；对未掩码 Dense 的质量、模型 FFN 和视频效果不由此建立。原始测量细节、后端哈希、样本及运行身份见[机器结果](E0_ACTIVATION24_BACKEND_LAYOUT_RESULTS_20261027.json)。

下一项物理判别是冻结候选布局和算法后，将每次动态选择、压缩、输出连续化、权重准备及完整FFN的 wall 与显存共同核算；再以匹配原模型精度和真实视频验证生成能力。2:4激活分组与HiF4 whole64尺度闭包、RT-Lynx作者实现分别保留不同身份。
