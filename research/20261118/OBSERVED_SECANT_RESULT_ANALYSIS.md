## 1. 执行对象与证据范围

采用行向量约定：

\[
F(U)=\phi(UW_1^\top+b_1)W_2^\top+b_2,
\quad U:[N,d],\ W_1:[m,d],\ W_2:[d,m].
\]

当前 `N=31668=21×29×52`，`d=5120`，`m=13824`。latent 时间轴长度为 21，解码帧轴长度为 81，去噪步轴长度为 4，三者是不同轴。全 80 指 high/low 两个专家各 40 层；HHLL 中步 0、2 为 Dense anchor，步 1、3 为近似 hit。每条视频共 160 次主路径 FFN 调用，其中 80 次是 hit。

本轮上传结果包含 12 条全 80 视频和 3 条 0392 六位置诊断，共 15 D4、60 NFE。全 80 与六位置离线 query 分别为 960、18 次 64 行完整 FFN，合计 62,592 token-FFN。这里的 query 费用不同于生成中在线 observer 的费用。执行回执中早于人审生成的 `HUMAN_REVIEW_PENDING` 字段，不能覆盖随后已保存的人审记录。无诊断 I/O 的部署延迟与显存峰值仍未测量。

全 80 视频部分的独立单位是三个已暴露的开发来源，各一个 seed；旧局部面板另有 11 个 DEV 来源，六位置视频只有 0392。80 个位置、64 行 token 与局部折不能当成独立视频样本。本报告提出机制解释，不声称已经获得跨来源显著性或正式泛化结果。

## 3. P64 与我们的构造：同样使用当前观测，压缩的轴不同

### 3.1 Global-P64 更新原生隐藏坐标

令 `H0=phi(U0 W1^T+b1)`、`Y0=F(U0)`。P64 的 64 是当前 **token 行数**，不是隐藏通道数或输出秩。它在固定 64 行 P 上计算完整 W1 与 GELU，按

\[
s_h=\sqrt{\frac1{64}\sum_{n\in P}(H_{1,nh}-H_{0,nh})^2}
\]

选出 5,120 个隐藏通道 I，再在所有 N 个 token 上重算这些通道：

\[
\widehat Y^{P64}=Y_0+(H_{1,I}-H_{0,I})W_{2,:,I}^{\top}.
\]

这是连续算术中的表示；原生实现另含 delta 舍入、packing 和选定 W2 的累加程序。64 行 observer 不运行 W2；全 token 的选定通道收缩才生成最终修正。

其固定状态的理想误差为：

\[
E^{P64}=\sum_{h\notin I}\Delta H_{:h}W_{2,:h}^{\top}.
\]

被省略通道的增量可以在全体空间 token 上非零。因此，**即使没有探针失稳，隐藏坐标截断本身也允许全画幅误差**。空间广泛的损坏不证明问题一定来自全局 mask，更不证明改成区域选择就能解决。

此外，门控后的省略误差能量含有隐藏通道之间的交叉项：

\[
\|E^{P64}G\|_F^2=\sum_{h,h'\notin I}
\langle\Delta H_{:h},\Delta H_{:h'}\rangle
\langle g\odot W_{2,:h},g\odot W_{2,:h'}\rangle.
\]

按隐藏变化 RMS 排序没有直接计入 W2、gate 或通道间抵消。我们的完整输出创新则已经包含 W2 收缩后的有符号结果；这提供了不同的当前信息，但能否从 64 行正确推广仍受特征与辨识限制。上述差别解释了值得迁移的数学信息，尚不定位 0392 的实际损坏来源。

实现来源：[严格 comparator](../20261107/ffn_baseline_reproduction/strict_reproduction_20261116/wan_ffn_comparator_ports.py) 的 `_g64_hit`、[RMS 与选择](../../reports/20261114/g20_two_track_core/BWS/v1/source/chipmunk_fullm_proxy_math.py)及 [packed pre-gate 更新](../../reports/20261114/g20_two_track_core/BWS/v1/source/chipmunk_wan_packed_pregate.py)。函数以 `select(scores,5120)` 选择隐藏轴，在所有 token 上执行 packed 更新；与 64 行 token 轴严格区分。

### 3.2 在线读出估计当前输出映射

我们的构造从固定 16 个原生通道提取配对特征，经 CAL 缩放和有效基变换：

\[
\Phi(U)=[Z_K,\phi(Z_K)-\beta\odot Z_K]D^{-1}T_{CAL},
\quad\Phi:[N,r],\quad r\le32.
\]

缓存自身 Dense anchor 的 `C0` 与 `Phi0`，当前形成

\[
Y_b=U_1A+C_0,\quad X=\Phi(U_1)-\Phi(U_0),\quad
Y_{stat}=Y_b+XV_0.
\]

这里 A 在 high/low 的 04、19、34 六处使用冻结 L64，其余 74 处使用严格 Q1。全 80 不是“全 80 L64”。

在线 observer 在 64 个当前 token 上执行 **完整 FFN，包括 W2**，得到相对静态读出的全输出创新 `D_P=F(U_P)-Y_stat,P`。当前支撑记为 `Z=X T_s`；定义

\[
H_s=T_s^\top(\Gamma_X+\tau^2\Gamma_{CAL})T_s,
\quad K_s=Z_P^\top Z_P/p+\lambda H_s.
\]

则连续算术中：

\[
\boxed{\widehat Y_{on}=Y_{stat}+L D_P,
\qquad L=ZK_s^{-1}Z_P^\top/p.}
\]

原完整静态预测保留，只有在线增量受当前支撑约束。L 的形状是 `[N,64]`，它把 64 个 token 的完整输出创新传播到全部 token。它可以带符号，不保证非负或行和为 1；应理解为有正则的响应重建核。当前全体 token 的 X 还参与 Gram 和支撑估计，方法使用的信息并非只有 64 行。

真实部署使用 `X_b=BF16(Phi1−Phi0)`、BF16 的 V 和两次输出舍入；上述核恒等式解释连续部分，不是逐位 BF16 恒等式。包括 probe 在内的全部 token 都使用预测，未把 probe 真值拼回输出；当前 gate 由宿主施加一次。

来源：[native_readout.py](../../tools/ffnds_observed_operator/native_readout.py)、[observed_local.py](../../tools/ffnds_observed_operator/observed_local.py)、[参考核心](../../tools/ffnds_observed_operator/core.py)。

低秩应写对对象：单次连续修正 `XV` 的 token×output 矩阵秩至多 r；总输出包含基线与 Dense anchor，不受 rank32 限制。V 在不同状态可以改变行空间，联合响应空间可以大于 32；本轮尚未测量收益主要来自方向变化还是幅度变化。V 至多有 `32×5120=163,840` 个动态系数/位置，并非“32 个动态参数”。四模式只有 4 个共享系数，两者的动态自由度不可直接按“32 对 4”作同规模比较。量化舍入还可能提高最终数组的代数秩，rank32 约束适用于舍入前乘积。

## 4. 广泛损坏提供了什么研究方向

### 4.1 共享估计引入跨 token 耦合

在忽略量化舍入的连续算术模型中，固定单次 hit 的缓存，并处于当前有效支撑不变的可微分支上：

\[
\frac{\partial\widehat Y_{nc}}{\partial U_{mj}}
=\delta_{nm}\left(A_{jc}+\sum_a\frac{\partial\Phi_{na}}{\partial U_{nj}}V_{ac}\right)
+\sum_aX_{na}\frac{\partial V_{ac}}{\partial U_{mj}}.
\]

固定权重的原始 FFN 在这个输入边界逐 token 运算。最后一项是共享在线估计额外引入的跨 token 依赖：probe 通过真实响应改变 V，非 probe 也能通过当前全局 Gram 改变 V。它使方法适应当前视频，同时可能传播估计偏差。

例如，若 probe 创新含有共同输出偏差 `1_p b^T`，传播量为

\[
\Delta Y_{bias}=(L\mathbf1_p)b^\top.
\]

这个空间场可能覆盖大部分 token。条件于固定 L，若 probe 噪声相互独立且通道协方差为 Sigma，则 token n、m 的传播噪声协方差为 `(L_n L_m^T) Sigma`。这些是可检验的推导，**不是对 0392 已确定的故障归因**。真实 L 与观测误差也会共同依赖输入，条件噪声模型是诊断假设。

P64 的全局集合在固定选择分支上保持不变，变化发生在选择切换；其机制与连续 V 的耦合不同。两者画面接近并不能证明误差相同。

### 4.2 将余下问题分成有不同预测的机制

| 竞争解释 | 具体预测 | 区分所需证据 |
|---|---|---|
| 当前特征无法表达需要的响应 | 同状态、同特征 oracle 仍留下显著功能相关残差 | 同状态输出残差与子空间投影；局部能量只能说明表达，不替代视频 |
| probe 创新或正则使共享修正偏移 | 表达空间有余量，有限观测修正的方向/增益却不稳定 | 固定状态 prior/online 对照；未来保存 probe 特征与当前 Gram 以检查核传播 |
| 上游改变了下游状态和 anchor | low 局部即时收益有限，但 high-only 在线即可保留较多效果 | 高/低阶段两条交叉配置，使用各自新鲜 anchor |
| low 阶段的当前修正直接重要 | static-high/online-low 已明显接近全在线 | 同上 |
| 两阶段联合作用 | 两条单阶段在线均不足，全在线才能保留 | 同上；交互在完整视频和预先固定行为特征上判断 |

当前证据优先支持保留全 80 在线读出作为研究主线。区域 bank、提高 rank、改 probe 数都需要对应机制证据。直接减掉全局均值或低频响应可能同时减掉目标晕眩、镜头或光照变化，尚无依据将其作为默认修复。

## 5. MSE 已经提供定位信息，但不能决定视频资格

### 5.1 原有 MSE 准入会错过本次结果

旧六位置局部回放中，在线读出相对静态的来源等权 MSE **退步 5.95%，0/11 来源获胜**；同 query 标签拟合的连续 oracle 则可改善约 19.74%。旧选择 JSON 的 `STOP_NEW_VIDEOS` 是当时门槛输出，已被后续方案取消。随后全 80 视频出现 0392 的正向保留，这表明按该局部结果直接停止视频会错过有效构造。

局部 P512 内的 probe、六位置覆盖和后续全 80 的其余 74 处参数均不同，所以不能说“局部 MSE 变差导致视频变好”。准确结论是：**该局部筛选规则没有足够的范围与目标一致性来淘汰完整生成候选。** 通道选择、prior 与 lambda 的 CAL 欧氏拟合仍可作为明确的工程构造；它们并未由本轮结果自动变成最优的视频目标。

只有 34/80 处的原始 MSE 下降；改善并非逐层一致。两臂 query 的输入 hash 仅在 high00 相同，其余 79 处均不同。在真正相同的 high00 输入、teacher 与 gate 下，0392 在线 MSE 为 `0.00089850`，静态为 `0.00087217`，在线反而高约 3.02%。这一个局部负结果与最终视频正向结果可以同时成立。

同时，low40 相对自身 anchor 的真实增量能量从 `0.0523230` 降到 `0.0168504`，下降 67.80%；low30–39 对应下降 73.12%。因此目标响应本身也在变化。low40 的逐位置相对误差均值从 `0.44211` 变为 `0.40774`，全 80 从 `0.35345` 变为 `0.34840`，不能把原始 MSE 的 32.24% 下降解释成固定输入的近似精度提高同样幅度。这里也不把增量能量变化与误差变化作加性或因果分解。

这给出一个有用的动力学线索：静态轨迹在 low 后段进入了更大响应变化与更大误差并存的状态；在线轨迹缓和了这一现象。它可能来自 high 前缀、low anchor 的变化、low 当前修正或它们的组合。现有位置图可以定位联合变化，不能定位最初的致因层。

来源：[逐位置真实 query](../../reports/20261118/observed_secant_ffn_operator/output/FULL80_STUDENT_QUERY.csv)与派生证据的逐阶段摘要、同输入 high00 记录。

### 5.3 为什么局部范数与视频功能不等价

把每次 gated 误差写成 e_i，把生成状态与缓存一起纳入状态空间，对某个终端视频特征 q 的一阶传播有

\[
\delta q\approx\sum_iJ_i e_i,\qquad
\|\delta q\|^2\approx\sum_{i,j}e_i^\top J_i^\top J_j e_j.
\]

局部 MSE 主要记录各 e_i 的欧氏范数；它没有记录下游敏感方向，也没有记录跨位置的增强与抵消。这里是一阶机制表达，不把有限幅度视频差异假定为严格线性。合理使用 MSE 的方式，是在固定状态上定位误差方向、表示边界和数值路径；最终取舍继续看目标效果、完整视频及实际成本。

### 5.4 旧 Q32 的限制有更直接的结构证据

在旧六位置 FP64 面板上，令 D 为候选 gated 修正，R_A 为共同基线 gated 残差；欧氏净增益为 `g(D)=2<R_A,D>−||D||²`。对旧 gated Q32 及其正交补分别计算，有：

| DEV11×六位置面板均值 | 总净增益 | Q32 内 | Q32 外 |
|---|---:|---:|---:|
| panel-P64 | 3954.42 | 32.04 | 3922.38 |
| readout-static | 385.02 | 327.09 | 57.92 |
| readout-fixed64 | −707.54 | 142.28 | −849.83 |
| readout-oracle | 4004.34 | 1280.88 | 2723.46 |

panel-P64 的合并有符号净增益约 99.19% 在旧 Q32 外；0392 单独约 78.49%。这比“原残差很多能量落在 Q32 外”更直接地说明某些有效修正需要旧空间之外的方向。该比例是有符号净增益之比，不是概率或视频贡献率，分量为负时还可能超过 100%。panel-P64 也不是本轮严格 Global-P64 视频本身。

读出 oracle 在 Q32 外仍有正增益，而局部 fixed64 在那里为负，进一步提示表示空间与有限观测辨识应分开研究。这是旧六位置面板的诊断，不将它直接归因为本轮全 80 成功的唯一原因。

## 6. 四模式负结果需要重新限定：基底学习与部署使用了不同增量

源码审查发现一个可复现的语义差异。`mode_local.py::_structural_fit` 实际先调用 GELU：

```python
z0 = F.gelu(u0 @ w1.T + b1, approximate="tanh")
z1 = F.gelu(u1 @ w1.T + b1, approximate="tanh")
dz = z1 - z0
```

所以 source 系数与 POD 基底使用的是

\[
\mathcal L_H(b)=(\Delta H\odot b)W_2^\top.
\]

而 `mode_templates` 使用 `db.float() @ w1.float().T`，`compile_matrix` 编译

\[
A(\theta)=A+W_1^\top\operatorname{diag}(\theta^Ta)W_2^\top,
\]

部署作用为 `L_Z(a)=(ΔZ⊙a)W2^T`，也是原设计要求的作用。两者之间存在逐 token 割线斜率 `ΔH_nh=s_nh ΔZ_nh`。一份共享 a 若要重现 b，必须对全部 n,c 满足

\[
\sum_h\Delta Z_{nh}(a_h-s_{nh}b_h)W_{2,ch}=0.
\]

一般 s 随 token 变化，不能自动吸收进共享 a。标量反例：两条输入的 Δz 都为 1，区间分别为 [−1,0] 与 [0,1]；GELU 增量约为 0.1588 与 0.8412。后激活 b=1 可以给出这两条响应，前激活的共享 a 只能给出相同的两个值。

边界也需要保留：最终 theta_static、lambda 和在线 theta 的拟合使用了真实部署的 ΔZ 模板。视频运行的是合法的算子，只是基底在另一种作用几何中选出。当前结果限制的是这套实际基底，不能据此否定 q=4 的整个状态模式族，也不能证明非线性 token 特征必不可少。

`full80_recover.py` 对六处未收敛方程作了求解器恢复，没有改变 `_structural_fit` 的 ΔH 定义。这项差异不影响 readout 静态/在线对照。本次只记录并推导修正目标，没有改写已有参数或重新运行模式实验。后续若继续这条路线，应先让 source 拟合与 POD 均使用原设计的 ΔZ，再用现存 CAL 端点重建基底，核对作用一致性；不能只改部署端名称或重用旧基底宣称修复。

来源：[mode_local.py](../../tools/ffnds_observed_operator/mode_local.py)、[full80_recover.py](../../tools/ffnds_observed_operator/full80_recover.py)、[native_mode.py](../../tools/ffnds_observed_operator/native_mode.py)。

## 7. 下一证据按信息价值排序

以下是由本轮结果导出的后续建议，不表示新增运行已启动，不扩展已完成的 15 条视频范围。

### 7.1 先检查已保存的当前 V 与 prior

学校归档的每位置 payload 已保存 V、prior、gate、当前 rank/condition 和 query 输入。可以在相同位置比较 `V G` 与 `V0 G` 的输出子空间主角度、相对范数和有效秩。这不增加 teacher 或 D4，可检查读出可达输出空间是否变化；它尚未按当前 X 的激励强弱加权，不能直接当成本次实际修正方向。几何变化存在不等于其引起视频收益，仍需后续干预区分。

发布的 full80 CSV 没有 rank/condition 字段，本次无法据它断言所有位置都保持 r=32。旧六位置全部 readout 支撑 r=32、mode 支撑 q=4，只适用于那批局部记录。

### 7.2 在 online 的同一状态上比较当前读出与静态 prior

固定 `U_on`、本臂 anchor、base 和 gate，比较 `Y_on`、`Y_stat←on` 与 `F(U_on)`。令 `e0=(F−Y_stat←on)G`，`δ=(Y_on−Y_stat←on)G`，报告

\[
\|e_0\|^2-\|e_0-\delta\|^2=2\langle e_0,\delta\rangle-\|\delta\|^2.
\]

这样把更新的方向对齐与更新幅度分开，不以这一个标量重新筛掉视频候选。

现有 `.pt` 保存了 query64 的 u、原始预测、base、anchor Phi0/C0、V/prior，以及 probe residual/baseline；没有保存当前 `X_query`、`X_P`、完整 X 或当前 Gram/support。离线 teacher producer 只落盘 hash 与聚合误差，没有保存 teacher 输出张量。

因此真实的有符号 teacher 误差需要重新算 64 行 Dense：0392×80 处为 **80 次、5,120 token-FFN，0 条新 D4**；若扩到 DEV3 则是 240 次、15,360 token-FFN。它是新的有限离线观测，需要按现行执行入口登记。

另一个数值边界：从 query64 重算窄特征的 GEMM 形状不同于原 full-N 特征程序。应使用保存的原 base，明确将结果标为“同一 64 行特征程序下的反事实”，同时量化重建 online 输出与原预测的差。**即使重建的 online 输出恰好一致，也不能单独证明静态反事实逐位一致：特征差异可能处于 V_on 的零空间，却不处于 V0 的零空间。** 若要获得原生产路径下严格的该反事实，需要原始 X_query 或完整输入重放；后续已计划运行时保存 X_query 是最小补充，不为补日志单独启动新视频。

现有资产也不足以精确恢复全 token 的 L，不能把 probe jackknife 或全图核杠杆分数写成已有分析结果。

### 7.3 优先只补一条：全 80 保持读出表示，仅六处在线更新

现有六位置臂在其余 74 处退回严格 Q1。与全 80 比较时，读出表示覆盖与反馈覆盖同时改变。更有辨识力的一条新增 0392 视频是：**全 80 处都保留同样的 readout 特征与 prior，只在原 high/low×04、19、34 六处在线更新 V，其余 74 处使用 static readout。**

| 配置 | 使用读出表示的位置 | 在线更新的位置 | 状态 |
|---|---:|---:|---|
| static-80 | 80 | 0 | 已有 |
| 全表示、六处更新 | 80 | 原 6 处 | 建议新增一条 |
| online-80 | 80 | 80 | 已有 |
| 原 online-6 | 6，其余 Q1 | 原 6 处 | 已有，作为不同表示覆盖的参照 |

新臂沿用冻结的全 80 参数、A、probe、seed 与初噪，使用自己的真实 anchor，不借其他臂缓存。新增范围为 **1 D4、4 NFE、160 次主 FFN 调用**；在线 observer 为 6 次 64 行完整 FFN，即 384 token-FFN。若逐位置作独立 query，另计 80 次、5,120 token-FFN。已有的静态与全在线视频直接复用。

若它接近 online-80，说明在全覆盖表示下，原六处反馈可能已足够，广泛在线更新未必必需；若它接近 static-80，说明在同一全覆盖表示中，当前六处反馈仍不足；若它优于 static-80 且弱于 online-80，则六处反馈有用但未复现全反馈收益。其余 74 处静态读出相对 Q1 环境的作用，要将新臂与原 online-6 直接比较；不能仅从新臂位于两端之间推出。主要读取目标晕眩、重影、动作和全画幅损坏，不按局部 MSE 给视频资格。

高/低阶段的两个交叉配置（high 在线/low 静态、high 静态/low 在线）可以在之后专门区分 §4.2 的阶段假说。它们需要另立的 2 D4、8 NFE 范围，本次不与上述一条打包成新队列。当前 low 后段的误差定位为将来的阶段干预提供依据，尚不要求立刻扩展实验。

### 7.4 真实成本与下一步实现重心

P64 与 readout 的 64 行 observer 费用不同；“16 通道特征”也不代表只算 16 通道即可替代整个 FFN。读出的全维 A 乘法仍然存在，并且 anchor 需要额外 `U0@A`，hit 需要 `U1@A`。

以一对 anchor/hit 为单位，忽略窄特征、observer 和求解的小项，P64 主 MAC 为 `2Ndm+2NdK`，读出为 `2Ndm+2Nd²`。当前 K=d=5120，这两项相同。原设计的完整主要收缩估算分别约为双 Dense 的 68.5690% 与保守 68.794%；不能根据 hit 的单个 GEMM 宣称总体两倍加速。

可利用的不同在状态表示：P64 的 H0/Y0 缓存 payload 为 40 层约 44.6974 GiB；读出的 C0/Phi0 为约 12.2314 GiB，约为前者的 27.36%。这只是明确张量形状的存储量，不是已测 GPU 峰值。当前全 N 特征的 FP64 SVD/Gram、转换、权重读取和研究用落盘均应进入真实系统测量。下一步应在确认机制后实现低开销统计与缓存路径，而不是从静态 MAC 直接给出性能结论。

## 8. 由这轮证据作出的研究决定

1. 保留全 80 在线读出为当前主要构造。它已产生自己的完整视频功能证据，继续研究它的条件表示与误差传播。
2. P64 保留为机制与相对保留参照，Dense 的目标效果继续定义缺口。最新“P64 也有全画幅损坏”进入记录，不将 P64 设为无损教师。
3. 局部 MSE 用于固定对象的解释；不恢复它对完整视频的准入权。已经完成的反例应改变后续筛选方式。
4. 四模式先纠正基底学习的 ΔH/ΔZ 语义，再判断其表示能力；不把现有负结果扩大成对模式族的否定。
5. 优先复用 V/query 资产，并以一条保持全 80 表示的六处更新对照区分反馈覆盖；阶段交叉留给后续明确问题。暂不展开 rank、probe、区域 bank 或多阈值搜索。性能结论等待真实部署路径测量。

本轮已经把“当前观测是否能成为我们自己的有效算子信息”推进到了一个正向实例。接下来的核心问题是：这些响应如何在完整轨迹中保持目标效果，哪些近似误差又被空间共享和阶段传播放大。
