# High-expert Y-only tap and driver: author self-audit

Author: /root/teal_full_llm_calibration_build_terra. Engineering draft only; no scientific scope, model or GPU was run. Owner, protocol, jobs, independently supervised verification and independent review remain separate work.

The tap observes the original FFN2 pre-gate output at high-expert step 0 and stores one BF16 clone per block. At step 1 the cache-dense arm executes the original FFN and releases that block's entry; the reuse arm returns a clone of that entry while suppressing both original FFN GEMMs and GELU through a transaction-scoped sentinel. Original post-processing applies the current gate and residual. Other sites, including all low-expert sites, use the original path; prefetch is not suppressed. The original call path is in `.runtime/code/LightX2V/lightx2v/models/networks/wan/infer/transformer_infer.py`, notably `infer_ffn` and its caller's `post_process`.

Per source the three phases cover 480 logical FFNs and respectively 320, 320 and 240 actual dense GEMMs. The logical peak cache is 12,971,212,800 bytes; a step-1 reuse clone adds 324,280,320 bytes temporarily, before allocator overhead and other live tensors. These are logical tensor sizes, not measured peak or transfer traffic. A synchronized cleanup after each caching arm's high-expert boundary is charged; actual allocated and reserved peaks remain unmeasured until authorized execution and must not be reset. The reuse sentinel's expand is a view, not a separate activation computation. Captures, video encoding, state comparisons and all prefetch costs are owned and charged by the integrating producer.

Original-buffer guards are imported from the existing factorial tap; that file and its complete import closure must be bound by the owner. No P64 selection, proxy or packed action is called. The integration must require prior Dense byte-identical 10-state and full-video gates for both NONE and cache-dense; reuse must pass the four prefix byte gates. It must independently verify typed state artifacts and actual supervisor EXIT, and retain failures without retry. Exact owner/job identities and resource monitors require separate review.

Six small CPU synthetic unit tests passed with CUDA hidden, including branch behavior, pre-gate/current-gate placement, exception restoration and phase counts. These tests do not establish numerical equivalence on the real model, actual CUDA memory feasibility, or latency. Same-device real gates are decisive.
