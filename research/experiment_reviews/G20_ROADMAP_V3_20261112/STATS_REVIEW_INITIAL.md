## 必须封口的一致性问题

1. **DEV 和 CONFIRM 的产物身份应分开。** 队列 S1 为 DEV48，却输出 `FINALVIDEOS/METRICS/COST`。资产树 `FINALVIDEOS` 的角色为 `SEALED_CONFIRMATION_AFTER_CANDIDATE_FREEZE`、形状为 CONFIRM96；`METRICS` 同样为确认读出。建议建立独立的系统 DEV 视频、指标与计时节点，或强制按 role/source-manifest/version 实例化，避免 DEV 覆盖确认身份。同类问题是 L0 旧 CAL4/DEV5 诊断输出 `LOCALDEV_SCREEN`，而该节点固定为新 DEV48。

2. **确认启动依赖不能等待确认完成。** 队列 S2 以 `REVIEW_CHAIN` 为输入，而资产树 `REVIEW_CHAIN` 依赖 `FINALVIDEOS/METRICS/COST`。若按资产 READY 解析，将形成确认前后的循环。应以独立的 S2 前执行审查记录作为启动条件，最终 review chain 为事后索引，或明确拆分两类记录。

3. **三次计时应是确定默认预算。** 主稿 §9.2 写“至少3”而 §9.3 预算按恰好3计算。建议默认恰好3，任何增加另行冻结；否则4032等只能叫最低执行数。资产树 `FINALVIDEOS/COST` 也需记录3次、1344唯一条件与4032实际执行这三个不同基数。机器队列 S1/S2 已正确写明2016/4032执行数。

4. **T1/T2 首批48新增只在同背景 Dense 参考已存在时成立。** 主稿 §7 若改用强 Attention 背景，原 Dense192 的原生 Attention 参考不能复用；若没有同背景 DEV12×2 Dense，则额外加24条，三臂共72条。需要将48/72的条件写进有限预算，不能只写“重新绑定参考”。

5. **N 自由轨迹需要可追溯节点。** T2 产生 Q 与 N 自由轨迹，资产 `GDEV` 仅描述 Q1。N 的视频、学生状态和恢复缓存应有独立节点或明确按方法实例化，后续状态校准／后缀不能把 Q1 路径当作 N 来源。

## 统计对象需明确的细节

- N1 的“配对相对变化”应明写公式及 source 内 seed/site 的顺序。先平均 MSE 后取比，与先逐站点取比再平均不是同一对象。R1 已显示绝对误差均值和平均逐源相对误差可能异号，故此处不能留给执行时自行解释。
- 建议冻结技术计时汇总，如每 source×seed×arm 三次取 median，再计算 seed 配对 log ratio，最后按 source／语义层等权。该终点对应几何平均配对时间比，不能无说明改成全部 wall-time 池化比。
- “同 CAL 最强线性基线”宜由 CAL-CV 选定；如在 DEV 上挑最佳再计算 N1 区间，区间仅作开发资源筛选，不能称为选择后校准的确认区间。
- 总体估计目标是预设12语义层等权的条件分布。每类8个确认源并不支持12个独立充分检验；种子、token、时间窗与计时重复不扩大 source n。

## 新增12.5%静止控制的意见

支持在240名额内部安排 CAL12 / DEV6 / CONFIRM12，不改变12层的8/4/8配额。要求主体与相机均按输入指令静止；单纯相机稳定不够。图像必须容许静止，不能给火焰、倒水等动作模板硬贴静止标签。

必须同时处理：

1. 静止源进入总体质量与时间估计，但不进入动态运动幅值比有效 n。CONFIRM96 的名义动态 n 至多84，再减纯相机和低分母不可测源；84源对应约0.306 SD的单终点规划检测差，而0.286 SD仍只用于96源总体。
2. CONFIRM静止12源、DEV静止6源只支持失效诊断，不足以宣称低频伪运动已充分排除。即12源零失效，二项分布95%单侧失效率上界仍约22.1%。
3. 标签、允许的微动与光照容差在看方法结果前冻结，不能根据 Dense 或候选结果反过来重新定义静止类。
4. **嵌套子集不能与静止组成混杂。** 若每层第一 CAL 槽位都静止，C12会全部静止。建议三套source排列同时约束静止数：C12=2、C24=3、C48=6、C96=12；每层仍为1/2/4/8源。轮换哪些层早期选到静止，DEV12首批也仅1或2静止，DEV48总6。若扩CONFIRM至144/192，预先安排18/24静止并维持主层均衡。
