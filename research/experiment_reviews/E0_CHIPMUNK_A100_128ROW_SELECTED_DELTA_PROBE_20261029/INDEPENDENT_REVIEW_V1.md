## Required revisions

1. **Partial selection lacks a correctness reference.** `fixed_first_4096` output is compared to the *fully current* Dense output, which measures approximation plus implementation error but cannot distinguish them. Full-selection 0.03 relative L2 is a loose global bound and an empty selection never executes either kernel; neither validates mixed selected/unselected coordinates. Add an independent, same-mask reference for each initializer: form selected current activations and BF16-rounded delta from reference h, keep every unselected h bitwise equal to the starting cache, and compute reference cache-Y update with b2 already included only once. Explicitly state FP32 accumulation/rounding order and compare h, delta if exposed, Y and gated Y under frozen explicit error criteria, separately from approximation-to-Dense and full-M anchor differences. Use full/partial and selected-channel/tail/empty controls; compare selected indexing and cache mutation. Test a scalar/synthetic model with nonzero old Y, b1/b2, signed delta and an unselected channel; silent wrong index selection and double bias are adversarial counterexamples. Since GPU compilation is future experiment, numerical tolerance needs a defensible explicit pre-run bound and if unachieved an actual FAIL; do not adapt after data.

2. **Read accounting and stable identity are incomplete.** The 28,577,915,880-byte checkpoint is fully hashed *before* `ledger.run('high_checkpoint_load',...)`, so a failure after a full checkpoint scan can still report zero checkpoint predebits. Payload SHA reads also occur inside load but bytes actually read and interrupted reading are not represented. Add explicit predebit/actual bytes for full checkpoint hash and both payload hashes, bounded selected-tensor reading, and before/after stable file identity/stat across hash and use (including input payloads); account failed/inflight reads without asserting completion. Include declared total read bound and host-memory ceiling/measurement or explain enforceable limits. Execution may need large real checkpoint reads; no scientific tensor or large checkpoint was read in this review.

3. **Failure and limit evidence need closing.** Persist a started RUN immediately after fresh output creation, before imports/allocations; record and check output bytes and peak host memory in final closure, including errors and compilation cache. Resource checks now occur only at case boundaries and final check: direct HF output growth from compilation between them must be bounded and checked before success; guarantee parent receipt and failure artifact remain verifiable on exceptions. Test interrupted hash and interrupted compute predebits, closure rejection for violations, metadata and input stat mutation, and actual execution-specific calls rather than only source-string assertions. Ensure timeout, stable environment/worker and exact source review bindings are checked prior to numerical work and after revision.

4. **Scope and controls must be described accurately.** Producer uses fixed-first and no proxy, so it cannot test whether Chipmunk proxy beats random or if online selection is efficient. Keep that explicit in RUN and any results; selector/packing/cache wall are single-shot with persistence/possible compile and no paid author proxy. Either provide a separately defined measured end-to-end interval including the applicable costs or treat timing as diagnostic only with no acceleration claim. Current packed rows are a selected non-raster subset; scatter is only an `index_copy_` into an otherwise uninitialized full-sized output and must not be represented as a full permutation/inverse or complete model output.

## What is well specified, and limits

The two metadata identities/rows and same-expert same-block pair match the previously read spatial52 capture. The single-group permutation identity applies to per-row FFN values, not to the group-dependent selector. First W1 biases are included prior to BF16 pre-GELU rounding; h update stores BF16 delta and B accumulates FP32 then rounds cached pre-gate Y to BF16. The existing native DefaultMM uses `torch.addmm` and tanh GELU follows it; reference `F.linear` is a small-M counterpart, not guaranteed bitwise equal to full-M native. Cached b2 once and current gate after Y are algebraically appropriate. Separate initializers and M128-vs-native comparisons correctly make potential GEMM rounding visible. BF16 delta + separately rounded cached Y can make full update nonexact even with correct real algebra.

Static inspection: explicit CPU unique/in-range indices prevent duplicate h-cache writers; A masks row and selected tails and B masks row/output/reduction tails, with each grid output tile a unique writer. This is not a compile, GPU race or numerical verification. `libdevice.tanh`, `tl.dot` layout/types, actual CUDA dispatch and kernel results remain UNKNOWN until separately authorized execution. Original author source uses mean-preactivation proxy, top/random selection and index-cache updates; this implementation omits them honestly. A block-mean cancellation counterexample (two tokens shift equally in opposite directions) makes low group proxy compatible with large individual activation changes; this scope cannot test it as an author-selection mechanism.
