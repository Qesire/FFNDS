# 全 80 位置 CAL 扩展作者自审

本轮按 58f68ab 的修正规则将两类算子都推进到各自的全 80 位置静态与在线视频比较。历史 LOCAL6 的局部 MSE、oracle 和源级差异保留为欧氏诊断。其原定停止决定只适用于旧方案。原数值拟合规则保持冻结，本次使用完成回执和逐参数文件哈希复用那六个位点。

- CAL 生产用每专家 40×11 对已登记的 P512 端点，从原始捕获清单、严格 Q1、原始 BINDINGS、完整绝对文件、捕获 sidecar 和权重绑定，保留全 880 对的身份。每个专家重用三份本轮已有 L64 位置的两类参数，其余 37 层每层以同一规则拟合两类，使用该层的严格 Q1。两次各 0 D4 和 0 NFE 的作业共同覆盖全部 80 个位置。
- 反例一是校准张量形状正确但 anchor/hit 来自不同来源或 token 次序，导致貌似收敛的系数绑定到错误状态。每一端点必须核文件、sidecar、专家层、checkpoint、源身份、步、gate 与 token 字节，同时要求跨层候选坐标对应。
- 反例二是固定 64 行上的有效校准会对 full-M 当前误差或下游视频功能产生不利校正。每类保留自身同缓存静态控制，CAL 只见证数值路径和有限性，后续两类均用同源同噪声的学生自由视频评估，另保存事后 student query。
- 各专家一张 A100 80 GB、4 CPU、64 GiB 主存、2 小时。适用并发上限两张 GPU。先核归档读取和原生路径，然后按 1 层的工作集推进，保留逐位点参数与验收。历史 173607 工作集峰值约 9.67 GB，每位置约 47–68 秒，2 小时覆盖归档 I/O 和新数值见证。无自动重排队或重试。
