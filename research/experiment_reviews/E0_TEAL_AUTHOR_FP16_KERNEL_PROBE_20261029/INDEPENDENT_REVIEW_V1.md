## What can be learned

[LIT/SRC] [TEAL](https://arxiv.org/abs/2408.14690) applies training-free magnitude sparsity throughout LLMs, motivated in part by memory-bound autoregressive decode. The pinned author source implements thresholded single-token FP16 GEMV; this synthetic A100 probe can test correctness and warmed end-to-end eager call latency for one shape and input, not model accuracy, deployed decoding, Wan or demonstrated memory bandwidth. Source dispatch uses dense unmasked matmul for sequence length >1. Comparing that fallback to unmasked dense is correct. Author shape 4096×14336 divides all active M/N tile widths; unlike N=11008 with BLOCK_N=512, no unmasked N-tail weight reads arise here. Input threshold is strict `abs(x)>threshold`; masked reference respects it. Counting 62 source-level forward/dispatch/Triton entry calls is correct if completed; internal autotuner benchmark launches and pre-hook zeroing are additional GPU work, not 62 actual hardware launches.

**Concrete opposing counterexample:** with the same fixed 50%-approximately pruned x, output atomics and initialization plus tiled access/launch overhead can exceed saved weight-load time. Candidate can be slower than dense, or faster at both thresholds because of backend/layout alone: neither proves reduced physical traffic. Even 0.25 versus 0.0 may select different autotune configs (different bins); therefore speed difference does not isolate load skipping from configuration change. A fast candidate against unmasked dense also calculates a different output, so label as a latency tradeoff and pair with masked-reference correctness, never equal-function acceleration. A genuine traffic/causal attribution requires a separately reviewed fixed-config or profiling follow-up.
