## Research question and competing predictions

Can the unchanged TEAL FP16 single-token author kernel enter its actual sparse path, agree with its thresholded dense mathematical reference, and exhibit a measured kernel-time difference on an A100? H1: threshold 0.25 causes the author sparse path to skip some input-driven weight loads and reduces measured GPU time against the same dense matrix; H2: launch/atomic/autotune or dispatch overhead outweighs the saved loads, so sparse can be slower even with half of the synthetic inputs below threshold. One paired fixed-shape probe separates these outcomes for the selected device and input; neither result establishes LLM system speed or video capability.

## Numerical and source risks

Neutral comparison allows FP16 atomic accumulation error (relative L2 ≤0.015); report actual errors and sampled zero fraction rather than asserting a target sparsity. Candidate reference explicitly masks x, while timed dense path is the ordinary unmasked dense matmul. The author kernel's weight `tl.load` mask omits `rn < N`; e.g. Llama-2-7B's 11008 output is not divisible by some 512-wide autotune configurations. This probe's 14336 output avoids that known tail case; full-model follow-up needs an independent tail-safety review and memory-check evidence, rather than assuming the unmodified kernel is safe for all shapes.
