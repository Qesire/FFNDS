# Author CUDA stream and tensor lifetime: static audit

Independent reviewer `/root/teal_full_llm_calibration_build_terra`; source commit `3cc584fe48e32e59c8b4e37323470dcdd606bb11`, no execution. This is a source-derived hypothesis and design obligation, not a measured failure cause.

For the actually planned author paths, `shared_weight_nvfp4.cu` launches weight quantization and scale duplication with bare CUDA launches; `reorder.cu` does the same for dense activation quantization; `fused_sparse_prepare.cu` does so for sparse/residual preparation; sparse scale duplication is another bare launch. `nvfp4.cu` invokes CUTLASS `gemm_op(arguments)` without a stream argument and `sparse_nvfp4.cu` invokes `initialize` and `run` without one. Other published down/reorder and optional fused-RMSNorm kernels similarly use bare launches; those optional branches are not automatically part of the proposed FFN experiment. No `getCurrentCUDAStream` occurs in these wrappers. This implies the author extension's default-stream API must be treated as such until compiler/runtime evidence establishes otherwise; stream semantics are an implementation property, not a proof that this caused a prior NaN.

The author Python `quantize_weight_shared_nvfp4` and activation functions produce global reductions and `(x / scale).to(BF16)` temporary tensors before dispatch, then allocate output tuples inside C++ bindings. If called on the LightX offload compute stream, a synchronization only after the whole function returns cannot retroactively impose producer-before-default-kernel ordering. Temporary allocation and reuse must remain safe until the default-stream consumer finishes; tuples, sparse metadata, scale and GEMM output then require default-to-compute dependency before caller consumption. In addition the author fused kernel output allocations are initialized on the current PyTorch stream, while bare kernels use the default stream. A before/after BF16 output comparison alone cannot show that shared packed/scale tensors were produced correctly.

SAFE design to audit: first execute a default-stream reference, with actual original-shaped W/input and frozen identities. For the bridge, record caller-ready event after all producer work; have default wait before launching the complete author/PyTorch quantization and GEMM sequence in the default-stream context; keep strong references or record_stream for every cross-stream tensor, then record a default-completion event and make the caller wait before any use/reuse. Either safe explicit stream recording with documented allocator lifetime or conservative synchronization is necessary. Both directions, intermediate temporaries, returned tuple and scalar scales require coverage. Observe W/input byte integrity and original BF16 output neutral, then logically consumed scale bytes / packed payload and same-encoding Dense32 and SharQ outputs against default reference, with timing/observer and all work charged. Use identical true W/input, comparison metadata and error thresholds frozen before data work.

UNBRIDGED is a separate fresh finite scope reproducing the old caller/default ordering exactly once after SAFE, not a loop or retry; record failure/inflight even on mismatch. SAFE success and/or UNBRIDGED difference are bounded to tested shapes/hardware/streams and do not prove a full-video root cause. A passing bridge does not prove absence of author kernel out-of-bounds writes; inspect output sizes and canary/integrity with an independently budgeted test.
