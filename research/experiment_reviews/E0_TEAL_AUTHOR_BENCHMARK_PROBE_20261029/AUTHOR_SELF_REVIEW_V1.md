The author runs a complete 0–1 sweep, multiple providers and separately created random inputs per call; this proposal selects only levels 0 and 0.5, ZEAL and dense, with identical input and weight between arms. It is an author-benchmark-style bounded adaptation, not the complete author benchmark or an LLM result.

The pinned installed Triton 3.0 `do_bench` invokes fn once, synchronizes, allocates a 256,000,000-byte cache, estimates timing using 5 flush+fn repetitions, calculates adaptive warmup/repeat, then times each fn between CUDA events preceded by cache zeroing. Our `guarded_do_bench` copies this control flow and arithmetic, inserts caps/predebit/persistence after estimation and outside measured intervals, leaves the measured fn unwrapped, and obtains the same quantile estimator. It does not call the library routine verbatim: loop bounds are explicit safety deviations. A batch that fails midway is UNKNOWN, not silently reported as a complete counter. Python and GPU asynchrony can still affect event intervals, and neither this probe nor V2 isolates Python overhead.
