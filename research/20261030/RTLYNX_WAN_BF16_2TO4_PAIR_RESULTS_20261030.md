# RT-Lynx 启发的 Wan BF16 2:4：完整 FFN 有限实测

同一真实 Wan source911、block20 的两个 expert 中，逐行范数补偿降低了 Top2 的门后相对误差，但误差仍约 0.24–0.27；重复行大形状下，补偿臂完整 FFN 中位数约 51–52 ms，Dense 约 36–37 ms。本次未显示明确部署余量。

该范围已实际 GPU EXIT0 并通过 closed。M32 是各 expert 同状态真实32行；M31668 将这32行循环重复，仅用于形状成本诊断。它是单个暴露开发来源，不代表真实 full-M 分布、完整视频或系统验收。

8 个稀疏 case 的 packed 值和 metadata 均与实际 Torch CUTLASS converter 逐字节一致；同 mask 的 Dense W2 参考相对 L2 全部低于 0.02。四次 M32 独立 stable argsort 选择及补偿结果通过逐字节检查；M31668 的选择参考与执行共享代码。原 BF16 M32 对此前 capture 的 a、h、Y 与 gate 均通过 0.03 相对 L2 门槛，具体值及所有逐项控制见 JSON。

全部预算预扣、调用与返回相等：60 次完整 FFN / W1，20 次 Dense W2，40 次 CUTLASS 稀疏 W2，20 次范数路径，以及 8 次 converter 和同 mask W2 参考；每个额外 GPU 参考含同步的 wall 在 JSON 中列出。RUN wall 42.429 s、外层 43.582 s；bundle 全文 SHA 730509120 B，H2D 逻辑字节 571176960 B；峰值 GPU reserved 19.32 GiB、主机 RSS 1.38 GiB。

本次显式设置 `allow_tf32=False`，未显式冻结或记录 `allow_bf16_reduced_precision_reduction`。因此数值结论以本次进程内 Dense 与同 mask 参考为准；跨设备 capture 仅是有阈值的 neutral。软件文件的字节哈希已核，实际动态库映射路径未记录。

方法为 [RT-Lynx 论文](https://arxiv.org/html/2605.26632v2) 启发的无 LoRA Wan 移植：作者代码、范数归约轴及 tie 规则未证实。逐行补偿使本次门后相对 L2 下降；这项输出误差观察尚不能单独证明下降的原因，被删除的 W2 方向仍无法由行标量直接恢复。将行标量移至 epilogue 是尚未测量的实现可能；本次结果不否定作者训练方法或其他核实现。
