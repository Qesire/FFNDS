# 解释5步窗口结果时需要保留的求解器状态

本条是实际代码核对与条件性推导，不是新增实验结果，也不改变当前138477作业。

已核对本地实际源码副本 `../g19_execution_e4a_20261105/source_audit/lightx2v/models/schedulers/wan/scheduler.py` 与r6冻结的服务器源码SHA相同：`c86af28a3b8d709692fb3a88d67ec441a77624929d397c216e0106f1c0142f4a`。

事实：该WanScheduler采用二阶多步预测/校正；状态包括latent、`model_outputs`、`last_sample`和实际阶数等。`step_post`在当前噪声预测转为x0估计后，用此前状态校正，再更新历史并预测下一步。FFN锚点刷新不调用scheduler.reset，也不清空这些历史。

因此，5步刷新只使当前候选输入上的FFN重新成为原生F；它不会把候选latent送回Dense轨迹，也不会消除多步求解器内此前受近似影响的历史预测。即使锚点步骤每层都执行Dense，整个生成过程的累计偏差仍可以延续。

要讨论误差传播，应以扩充的求解器状态S_t为对象，而不只追踪当前latent。设Phi_t为相同原生求解器、原生网络产生的状态更新；对同一候选状态，缓存近似引入更新缺陷d_t。则定义上有

    e_(t+1) = Phi_t(S_hat_t) − Phi_t(S_t) + d_t，
    e_t = S_hat_t − S_t。

即使刷新步d_t=0，第一项通常也不为0。这里d_t应定义为整个更新的实际差异，不能直接拿某一层gate前FFN误差替代。若FFN锚点返回原生输出且其他运算完全匹配，刷新步的缓存近似缺陷消失；有限精度、调度状态及实现差异需另外核实。

在明确采用平滑实数代理模型、且轨迹邻域内可微的条件下，可进一步写平均Jacobian J_bar_t，使

    e_(t+1) = J_bar_t e_t + d_t，
    e_T = sum_(k<T) (J_bar_(T−1) ... J_bar_(k+1)) d_k，  e_0=0。

此式用于提出后续可证伪问题：局部误差的方向是否落入会被后续更新放大的方向？需要关注有限时间算子乘积的奇异放大，而非单个Jacobian的特征值或仅比较局部均方误差。实际BF16运算含舍入不连续，不能把上述可微代理恒等式直接宣称为真实内核的严格Jacobian结论；还需处理或测量有限精度余项。

当前三臂只提供最终视频、末态及真实成本，未记录40个中间状态摘要，不能由这一轮定位哪一步的传播最强。若5步仍明显退化，后续诊断应区分局部残差创新与求解器状态传播；不能自动归因于BF16压缩，也不能假定进一步增加锚点就按比例恢复质量。当前先完成固定5步实验及全部指标，不临时更换求解器或插入历史重置。
