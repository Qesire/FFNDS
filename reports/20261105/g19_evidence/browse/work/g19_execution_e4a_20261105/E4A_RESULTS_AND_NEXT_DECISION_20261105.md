## 可以作出的判断

1. **当前串行 host FP32 路径没有局部回本点。** 四场均有 B>D 且 H>D，增加锚点间隔也无法使 B+(L−1)H<LD。这个结论针对被测串行实现；C_s 在当前输入出现前已经已知，未来跨层预取仍有不同的关键路径，未被本实验否定。
2. **缓存压缩的首个优先项应是 BF16 GPU 驻留。** 缓存减半、结构简单，四场同状态输出相对 L2 误差仅 0.0535%–0.1158%。INT8 为 0.328%–0.567%，容量更小但 GPU 端更慢。这里的误差是 ||F_hat−F||_F/||F||_F；不是 relSSE，也不是生成质量指标。
3. **S 的容量收益不能抵消已经观察到的结构损失。** 四场同状态残差 relSSE 为 0.172–0.508，输出相对 L2 误差为 18.6%–50.2%。这是用锚点相同输入回放已压缩缓存时的重构误差，尚无跨步漂移；实际刷新锚点的路径仍返回 Dense 输出。因此不可先把 S 当成保质压缩，再把视频问题全归因于锚点陈旧。该反例只否定当前固定分块表示的充分性，不否定其他低秩或时空表示。
4. **驻留 GPU 可允许更短的锚点窗口。** BF16 的 L=2 局部时间比为 0.780–0.785，L=3 为 0.613–0.617。即使不使用已经质量失败的长达10步窗口，局部仍有节省空间。窗口是否保质尚需真实候选轨迹验证。
5. **完整 A 确实是一项执行规整且已经很高效的 GEMM。** 单独 XA 为 6.225–6.269 ms，同场配对约为 Dense 的 18.49%–18.64%。按相同输入输出宽度，两个 Dense GEMM 的算术量为 4Ndh，XA 为 2Nd²，比值 d/(2h)=5120/(2×13824)=18.52%。实测与算术量比例一致，支持继续保留完整 A 作为清晰的执行基线。BF16 命中剩余约3 ms也不可忽略；解码与输出融合值得测，但不能保证任意融合一定更快。

FP32 残差存储及传输元素精确；重新做 A+C 的候选输出存在近零值抵消导致的约 10^-21 量级 relSSE，不能称候选输出逐位等于 Dense。原生 F 与 Au 的独立重算才通过了有限值、元素精确相等检查。所有格式的同状态误差均不能代替跨步生成质量。

## 把质量、缓存与执行放入同一个判据

记 C_t=F(u_t)−u_t A，锚点 s 的缓存解码为 C_tilde_s。忽略已单独测量的有限精度余项，

    F(u_t) − F_hat(u_t) = (C_t−C_s) + (C_s−C_tilde_s) = δ + c。

因此，经当前 gate G_t 后的误差能量为

    ||G_t(δ+c)||² = ||G_tδ||² + ||G_tc||² + 2< G_tδ, G_tc >。

E4a 在同状态 s=t 下主要测 c 及执行成本；E1a 的原生 Dense 轨迹用于分层、分专家、分 CFG、分48个时空组测 δ、c 和有符号交叉项。两者组合才能选择有质量希望且执行能回本的窗口。不得用误差能量直接代替最终视频指标，也不得把 Dense 轨迹上的局部误差当成候选自身轨迹误差。

下一步的数学对象应是**在误差预算约束下的执行代价最小化**：对每层/阶段选择窗口 L、缓存表示 q 和驻留策略 m，同时约束缓存峰值以及 δ+c 的门控尾部误差。暂时只用有限候选 L∈{2,3,5}、q∈{FP32,BF16,INT8} 建立可核对的表，不训练复杂调度器或从四场结果臆造阈值。

## 后续顺序与终点

- source09 原生轨迹现已完整验收，原视频已下载。两源共6400个观测site（1600个完整原生数值site、4800个采样数值代理site），之后对照分析已采集的真实输入统计和残差漂移。将输入分组与输出误差逐组对应，保留高误差尾部，不用总体平均掩盖敏感层。采集与完整性验收不等于谱分析已经完成。
- 优先准备 BF16 GPU 常驻路径的完整资源验证，以及 FP32 GPU 对照。原生 FFN 权重的无效预取、无效 GELU 与 clone 应一并清理，并验证改变执行路径后的实际输出，而不是只审代码。
- 原 anchor10 FP32 CPU clean-path 代码保留为执行等价诊断工具，当前不为这个已经质量失败、串行搬运也不回本的组合新增整轮视频队列。若用于隔离权重搬运，必须明示其诊断目的。
- 根据两源漂移数据选定一个短窗候选，固定后才运行相同配置、相同seed的 Dense / FP32 GPU / BF16 GPU 三臂。先在开发来源辨别时间预测误差和量化误差，再做留出来源；同时交付原始 MP4、原有全部质量指标、完整生成wall、峰值缓存/显存及首载成本。指标通过条件需在看到候选视频分数前冻结，不能以“比旧anchor10好”代替相对Dense保质。
- 20%端到端缩短仍是需要单独证明的目标。若 Dense 总时间中可节省部分比例为 p、该部分剩余比例为 r，必要条件为 p(1−r)≥0.2。仅以3200次局部Dense中位数乘积作粗略外推，得到约107秒，而本来源Dense完整生成约662秒；这提示核心FFN算术本身可能不足以支持20%总加速。此外推不是实际profile，不能把16%左右直接当测得的p；必须量出真实关键路径及FFN权重offload贡献，才能判断架构收益上限。
