## 模型与数值契约校对

官方 [Wan 配置](https://github.com/Wan-Video/Wan2.2/blob/1ea34ff48f87168174e12956e200b1d908b1c5ff/wan/configs/wan_i2v_A14B.py) 的 dim=5120、FFN=13824、40 层、40 heads 与当前契约一致。官方 [模型实现](https://github.com/Wan-Video/Wan2.2/blob/1ea34ff48f87168174e12956e200b1d908b1c5ff/wan/modules/model.py) 的 FFN 为 Linear→GELU(tanh)→Linear，并在 norm/modulation 后计算、经 gate 写回 residual。原始模型官方配置默认 40 步；本地 D 的四步不能据此叫作原始 O 的复现。

LightX2V 历史 [四步 I2V 配置](https://github.com/ModelTC/LightX2V/blob/ed146db64d0b6130c669285fc1aa0b280a6a4823/configs/distill/wan22/wan_moe_i2v_distill_model.json) 同样使用 `[1000,750,500,250]`、shift=5、boundary_step_index=2、CFG 关闭和 use_image_encoder=false；调度器见 [Wan22StepDistillScheduler](https://github.com/ModelTC/LightX2V/blob/ed146db64d0b6130c669285fc1aa0b280a6a4823/lightx2v/models/schedulers/wan/step_distill/scheduler.py)。这支持当前 D 的模型身份，但本地硬件/运行配置有以下差异：

| 设置 | 上游历史示例 | 本地 v4.9.2 contract |
|---|---|---|
| 分辨率目标 | 720×1280 | 480×832 |
| attention | flash_attn3 | torch_sdpa |
| sample_guide_scale 字段 | `[3.5,3.5]`，CFG 关闭 | 1.0，CFG 关闭 |
| CPU offload / T5 offload | false / false | true / true |
| 视频长度 | 81 | 81 |

上游示例不是 A100/H20 复现配置；以上是字段校对，不能推断关闭 CFG 时 guide 字段仍生效，也不能把目标尺寸当成每条实际 latent grid。

新增的 `HiFloat4/ptq/adapters/lightx2v_wan_distill.py` 实际执行 smooth→activation QDQ→取得 cache 有效权重→`F.linear(x, weight, bias)`。`wan_i2v.py` 也明确保留此顺序。因此这里的 native 指复用实际 HiF4 数值 QDQ 后端，**不等于硬件 FP4 GEMM**；切换 H20 不会自动变成硬件四位加速。FFN 动态 mask 与 QDQ 的次序仍须保留，不能假定二者交换。

## 环境与 H20 的直接影响

历史 LightX2V [requirements](https://github.com/ModelTC/LightX2V/blob/ed146db64d0b6130c669285fc1aa0b280a6a4823/requirements.txt) 写有 torch≤2.8.0、torchvision≤0.23.0、torchaudio≤2.8.0；学校当前 hif4 环境观察值是 torch 2.10.0+cu128，属于已经调整过的组合。HiF4 历史 README 又以 torch 2.10.0 / CUDA 12.8 为环境目标。**不能连续执行两套上游安装脚本来恢复本地环境**，否则可能降级或重编已工作的依赖。版本观察值、安装脚本意图和 H20 验证结果须分开记录。

H20 首轮仍按 [迁移必读](https://github.com/Qesire/FFNDS/blob/main/docs/07_A100到H20迁移必读.md) 探测实际设备、独立构建扩展，并保留本地 attention/offload 设置。重点检查 HiF4 current-stream 补丁是否进入新 `.so`，以及 fresh Python 的导入路径是否指向恢复的主 `HiF4_Sp`；不能误用无 PTQ 新增文件的备用树。没有执行 H20 编译、模型生成或速度测试。

## 核验结果与剩余边界

补充包有 92 个完整差异文件和 5 份修改补丁，逐文件 SHA256 通过，88 个 Python 差异文件 AST 解析通过。用固定上游文本源码在本地重建后，92 个差异成功覆盖，1942 个目标文件哈希核验通过；冲突时全量预检拒绝写入，重复应用写入数为 0。5 份补丁经 `git apply --check`、应用和结果哈希检查。机器记录见 [VERIFICATION.json](../upstream_audit/VERIFICATION.json)、[AUDIT_SUMMARY.json](../upstream_audit/AUDIT_SUMMARY.json)、[SOURCE_MANIFEST.json](../upstream_audit/SOURCE_MANIFEST.json)。

Windows 核验时发现全局 `core.autocrlf=true` 会使 `git apply` 的结果变成 CRLF；在临时核验副本使用 `git -c core.autocrlf=false apply` 后字节哈希通过。恢复副本应保留 LF，不能用行尾变化后的文件声称通过原始字节核验。

这些检查只验证源码恢复，不证明 GPU 运行可用。第三方目录与编译产物未做全量逐文件比较；原始 O 的固定输入对照、完整视频质量、真实稀疏加速和同事 H20 验收仍按原交接的待办执行。本次没有把上游近期更新直接合入历史实验树。
