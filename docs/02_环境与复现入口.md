## 同一服务器继续工作的最短路径

1. 先运行包内 `tools/preflight_paths.py`，只检查外部模型、cache、配置和解释器是否存在，不加载模型。
2. 阅读内层 `server/artifacts/wan_hif4_prox_dit_v1/config/cluster.local.env`，再读 formal suite 公共脚本。公共脚本中有固定路径校验和运行目录创建；不建议随意 `source` 历史脚本来“查看环境”。
3. 在原服务器使用现有权威目录，选择新输出路径；本包镜像只是快照。不要覆盖历史实验。
4. GPU 生成/大张量回放交给 Slurm，登录节点只做元数据检查。

## VBench 三项与正式口径

- 使用 `vbench_i2v_official/bin/python`，工作目录 `$ROOT/data/VBench`，模型缓存 `/home/scc/pb23061276/.cache/vbench`。
- 不继承生成进程的 `PYTHONPATH/PYTHONHOME`。按历史 wrapper 的隔离方式启动，不能把 HiF4 的 `sitecustomize` 注入评测环境。
- 正式独立输入为 subject10 + background10，seed42，三项为 aesthetic_quality、imaging_quality、motion_smoothness。
- 历史文件命名需要每条视频五份同内容文件，共100文件；独立样本仍是20条。
- 逐项计算 `(dense-candidate)/dense <= 0.02`，不能使用三项平均替代逐项门槛。

包内保留自定义评分与比较工具于 `evidence/context_20261011/reference/vbench3/`；没有打包 VBench 开源库、评测模型或原图。评分脚本必须显式传新 `--videos-dir` 和 `--output`，不传时某些历史脚本会默认重评旧 dense 目录。
