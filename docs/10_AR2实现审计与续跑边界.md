本记录在旧 D-Q 大资产尚未恢复、尚未看到新的 AR2 风险结果时建立。
原始交接源码保留于 `.runtime/archive/server/work/v5/discovery_ar2/support_probe.py`，

## 可直接从源码确认的问题

1. **静态支持没有按测试 scope 的 donor 绑定。** 支持清单只在 task0 下保存 static，
   评分时却从测试 scope 的条目取 static。task0 会使用自身种子拟合的支持，
   task6 则没有该键。应当对 Fit 与 Validation 的同种子测试，共享对侧 task0 seed
   的静态支持和策略专属 gain；同 step/expert/block 不变。
2. **gain 拟合的 dense 锚点包含 bias。** 旧脚本将带 bias 的 native dense 输出记为 `z`，
   但待缩放信号不含 bias，candidate 仍会独立加 bias。冻结公式的 `z=Σ_b v_b` 不含 bias。
   一个确切反例：dense 线性信号为 2，bias 为 10，保留信号为 1。正确 alpha=2 得到 12；
   将带 bias 的 12 用作 gain 目标会拟合 alpha=12，再加 bias 后得到 22。
   这是实现合同问题，不是根据验证风险选新增益。
3. **重复转换大矩阵。** 逐行循环内反复构造 `wn.T.contiguous()`、`wn.float().numpy()`。
   W2 有 13824×5120 个元素，BF16 约 135 MiB、FP32 约 270 MiB。
   新原语按有效 W2 缓存这两个布局。尚无旧任务的 profiler，不能声称已证明这是超时的唯一或主要原因。
4. **C 范数与描述分位数。** 冻结规格允许 FP32 组投影、FP64 范数，而旧脚本 C 的平方求和为 FP32；
   C/E 几何分位数还用了普通 `np.quantile`。新原语对组投影转 FP64 后计算平方范数，
   设计加权分位数使用加权逆 CDF。它不承诺与旧脚本的所有得分逐位相同。

上述问题不证明历史任务执行到了这些代码，也不将旧超时升级为某个未经日志确认的新退出原因。

## 已实现的部分

- `tools/ar2_core.py`：冻结 task/seed/step/expert/block donor 绑定、稳定 TopK、
  训练设计加权静态支持、显式 actual_n 行检查、A/E/C、bias-free gain、native BF16
  mask→gain→cast→linear/bias→gate 顺序，以及加权逆 CDF。
- `tools/ar2_checkpoint.py`：运行身份绑定、原子写入、分片 SHA256、损坏拒绝和完成分片复用。
  进程被中止时的 `.tmp` 不计为完成；协议、源码、环境、资产身份变化必须使用新输出目录。
  完整 runner 还需持有输出目录的作业锁，防止多个写者。
- `tools/preflight_ar2.py`：只读核验冻结八个 scope 的来源、坐标、实际行数、设计权重与外部资产路径。
  路径映射必须显式给出，原路径同时保留；存在性不等于内容/数值核验通过。
- `tests/` 中的合成数据检查覆盖静态 donor、bias 反例、C/E 的构成与正重参数化不变性、
  实际 511/512 行、权重、稳定 ties、零分母以及恢复/损坏拒绝。

这些是可审计原语和准备工作。**尚未完成可运行的全 AR2 续跑 runner，也没有新的真实 AR2 风险表或决策结果。**

## 完整续跑必须保持的条件

- 原八个 D-Q block20 scopes；task0 作 Fit、task6 作 Validation，各自四个 scope。
  两个独立来源分别判读，不将 scope、seed、token 行当作额外独立来源。
- 原始连续 64 通道组，216 组中保留 108；使用归档 AR1 的四个冻结随机 mask，不重抽或挑最佳。
- selector 仅收 a、有效 W2、gate 和训练分数；测试 dense/Delta/SSE 不进入 selector 或 gain 拟合。
- 每策略独立的对侧 task0 gain；R 的四 mask 同时累计分子/分母拟合一个 alpha。
  bias 保留一次，不参与可缩放线性信号；零分母按冻结 floor 标记 NA。
- native CPU BF16 为主风险，另存相同支持/输入 gain 顺序的 FP32 对照。
  保存实际设计权重、逐行结果、支持、gain 参数和失败；C/其他在线成本不因局部风险较低而忽略。
- Fit 与 Validation 各自要求 ≥3/4 scope，且覆盖每个 seed/step；
  dynamic≤0.8×random 且≤0.9×static。C 另需≤0.9×E，门槛不因结果更改。
- 按 score scope、训练策略和评分行分片保存；预算到期先保存，部分完成不得生成整体验收 PASS。
