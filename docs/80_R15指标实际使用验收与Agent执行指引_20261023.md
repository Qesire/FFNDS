**目标**：检验十个学术指标族在 FFNDS 中能否正确选择、计算、聚合和解释。继续遵守 [R15 论文来源及九维协议](77_FFNDS学术指标族与评测协议_20261023.md)、[L0–L5 层次](76_基于学术文献的FFNDS分层指标体系_20261022.md)及[备选至少一条真实完整视频](75_备选算法必须完整生成与防止视频质量崩溃_20261022.md)。本次仅使用冻结历史数据与合成数学测试，不执行新 GPU/视频。

## 3. Agent 的下一轮研究与实际指标使用流程

1. **先明确机制性假说**：你是在测 FFN 数值等价、动态动作选择器的增益、下游 flow 影响，还是整条视频的时空质量？选择少数能够区分当前假说的 metric ID，逐项绑定 family、L 层级、官方或项目适配、参考模型和实际来源。
2. **直接复用已有证据**：R14N0 的局部写回 SSE+MSE+每来源 p50/p95/max 与动作族 gap、selector regret 属 L1；R14 的 1.913× 是**合成后端** L5，不能直接转为模型速度。需要 post-NMSE 时必须具备真实教师 post 能量，不能根据总 SSE 虚构。历史关闭实例与预登记门槛不追溯变更。
3. **避免用局部误差筛掉新算子**：若 R14N0 的固定双点已在其注册局部测试失败，保持闭合；数学机制不同的新候选可以依靠后续 flow、真正视频或部署行为提出新检验，而不是围绕旧 mask/符号无限换参。
4. **新候选进入部署候选级**：至少一条真实四步、相同输入图/文本/seed、真正自由传播、不在每步恢复 Dense D-Q 的完整视频。按照 docs/75 全片人工比较，特别检查本应稳定的光照与背景细小物体、主体、运动。不崩溃只是 L3 smoke，不是 L4 官方九维验收；模型作业须分别登记与获用户授权。
5. **正式质量（F1–F7、F10）**：配置 `research/metric_system/evaluation_protocol_template.json`；保存实际 checkpoint/量化/调度/分辨率、同源配对、每个 VBench-I2V 维度独立的 source manifest 与 pinned evaluator。F1 PSNR/SSIM/LPIPS 是与 D-Q 的**轨迹保真**，F2/F4/F7 结合无参考质量、人类偏好与局部光照诊断。不同维度子集不要虚构“九维同样本矩阵”。按来源簇（而不是逐帧）计算不确定度，保留全部失败/长尾。
6. **竞争性能（F9）**：分别测试原生完整 FFN（包含选择器/QDQ/pack/writeback）、全部去噪和解码的生成、wall time、显存、训练成本；与 Dense D-Q、UB1、最强同代价静态与可复现论文方案比较。主 MAC、随机 GPU 后端和真实完整视频速度必须三个不同名称。
7. **验收输出格式**：`问题/机制 → metric_id, F族, L级 → 测量输入与统计单位 → 参考与来源重叠 → observed|synthetic|planned → 实测、聚合、尾部和不确定度 → 对竞争假说的解释 → 下一项最便宜区分实验`。从实际结果演绎下一条科研动作，不根据任意 50%/1.5×/2% 数字机械淘汰方法。

## 4. 使用中的小问题已修订

原 R15 的 `paired_mse`、`paired_psnr`、`paired_ssim`、`paired_ms_ssim` 因为沿用 F1 统一字段曾要求 `backbone`，但这些像素/结构指标不需要特征主干；现只对真正依赖网络的 `paired_lpips` 保留该字段。评价器必须仍明确像素范围、颜色空间、对齐与帧聚合。此为协议适配修正，不修改任何已测量指标值。

**最终研究目标**仍是同前提下真实视频质量与推理性能的可复现 Pareto 提升。此文是促进指标*被正确使用*的流程，而不是给新算法增设不必要的审查门槛。
