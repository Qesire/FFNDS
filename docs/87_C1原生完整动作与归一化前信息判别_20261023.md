# C1N0：原生完整动作与归一化前信息判别

本轮把 C0 的归一化信息反例接到实际 Wan/HiF4 计算：在相同原生前缀上，测量完整补偿动作经过下一 block 实际 norm1 的影响，并保存 W1 前已经存在的残差尺度、注意力增量与 R256 中间表示。它解决此前缺少真实配对标签的问题。

## 已冻结的计算与范围

一张空闲 A100；两条旧 calibration0 的 UB1 控制视频，加六条诊断来源的 UB1 自由视频。诊断来源为主体、背景、镜头各两个，均已被选择/暴露，不当作独立最终评测。四个模型 step 各取 block4、17、30，共72个来源×位置；每处执行 dense D-Q、原 UB1、两个等组数 whole64 交换。固定总额为8条视频、288次独立完整FFN、302次额外归一化；不训练、不做新权重分解、不运行官方评分。参数、代码、输入和分析在执行前完成哈希绑定，见[协议](../research/20261023/C1N0_registered_protocol.json)和[授权](../research/20261023/C1N0_authorization.json)。

真实路径保留如下顺序；每一转换使用原生精度与 QDQ，而非把它们当作实数线性恒等式：

```
r = BF16(x + attention)
z = Q1(modulate(norm2(r)))
y_a = W2_a BF16(alpha * Q2(GELU(W1_a z + b1_a))) + folded_b2_a + R256(z)
w_a = native_writeback(r, gate, y_a)
loss_a = SSE(next_block.norm1(w_a), next_block.norm1(w_dense))
```

两个交换动作从现有支持的邻接保留/遗漏边界中，按来源无关的固定规则选择首尾各一对。每步保留组数仍为54/108/108/162，alpha与原R256不变。折叠偏置加上移除组的校准均值输出、减去加入组的校准均值输出；校准均值严格在原 `BF16(alpha * V2)` 后取，最后偏置也转回 BF16。24个原校准来源的张量逐项校验。这里借用既有交换与补偿构件，未把换名或扩搜索当作新机制。

每个动作都以完整31668行输入的独立克隆运行两次投影、补偿、门控与写回，再进入**实际下一 block 的 norm1，尚未做其调制/注意力**。主视频始终走原 UB1；反事实状态不回填主轨迹。这个有限边界可检验归一化传播，不等于完整下一 block、最终 flow 或自由视频质量。

## 信息对照与可证伪预测

原 R256 已经形成 `h256=linear(z,first,bias_first)`。读取它时保留原来两次 BF16 linear 的运算顺序。额外记录每个位置21个潜变量时间 bin各16行，共336行：原 post-Q1 输入、h256、norm均值/逆标准差、注意力更新前后残差尺度及对齐。完整动作的逐行写回/下一归一化损失也保存，但主决策单位为**整个FFN位置**。

预先固定两组互补的三来源训练/三来源测试，每侧主体/背景/镜头各一。控制包括训练选出的最佳全局固定动作、最佳位置固定动作、16维h256当前摘要、增加8维尺度/注意力摘要、位置内分训练/测试打乱新增摘要，以及同一三个等成本动作的事后 oracle。固定 ridge=1，无调参搜索。当前摘要能力有限，因此增量收益只能相对此摘要基线解释，不能证明全部 post-Q1 信息的统计充分性或不足。

两种结果都可判别下一步：若 oracle 本身没有超越固定支持的空间，就不扩大这两个交换的路由搜索；若存在 oracle 空间但新摘要未捕获，区分动作、表示与因果边界的问题。若新摘要增益存在，也要逐来源核查并与打乱控制比较，再考虑真正部署；原生选择器开销和候选完整配对视频仍需独立验证。

C0 的纯标量损失缩放本身不能在同一点翻转动作排名。C1另记录完整有限归一化后的排序：变化可能来自方向/曲率，也可能来自不同原生行的权重重排。保存的有限损失比是实测传播描述，不称作精确 Jacobian 或全局质量模型。PRD 的表示在这里暴露的是“完整动作与下游度量”的自由度；见[新增表示指引](86_PRD_表示发现_耦合新自由度与支持实验_20261023.md)。

## 数值控制与结果入口

运行前先比较 GPU 原 LayerNorm 与统计读取原语。两条旧来源控制分别验证原 UB1 与加入观测后的完整四步 latent/初始噪声哈希。每处诊断要求同前缀 UB1 探针的完整写回与主轨迹逐位相等，且反事实调用不改变 RNG；扣除额外诊断后，每条视频必须有原160处、1600次线性与1600次QDQ，零miss/transfer/fallback。

当前执行状态及结果链接见[交接](../research/20261023/HANDOFF_C1N0.md)。原始视频、72份数值负载与完整日志保留在HF缓存/忽略运行目录，公开仓库仅收数值、动作身份和脱敏凭证。执行时间含观测/复制/磁盘写入，不用于宣称加速；基线视频也不充当候选策略的质量烟雾通过。

## 实际结果

固定范围全部完成：8条完整基线视频、288次独立FFN、302次额外归一化；后台退出码0，峰值64.0541GiB。全部8条视频解码81帧，旧UB1两条控制及72处同前缀写回逐位通过，source0/2还匹配原R17 UB1四步轨迹。没有训练/分解/官方评分或模型重试。见[原生实录](../research/20261023/C1N0_native_results.json)、[媒体复核](../research/20261023/C1N0_baseline_media.json)与[资源/脱敏凭证](../research/20261023/C1N0_completed_resources.json)。

**小支持交换的oracle空间为零。** 72处原UB1均最好；交换A/B合并写回SSE分别高1.87540%/1.74983%，下一norm SSE高2.38745%/1.98385%。该有限集合未出现整位置最优动作改变或相对UB1的收益符号反转。不能靠改进预测器弥补这个集合没有的收益，因此不扩这两个交换的q/组池。原动作和全部校准绑定见[补偿参数记录](../research/20261023/C1N0_action_parameters.json)。

**dense行价值有可测的前置信息增量。** 利用同一批真实dense/UB1有限响应标签，离线在每处336个采样行中选84行，统计被选行承载的下一norm误差。此排序对照不是实际全M压行运行，不是视频指标；假定dense计算可消除这些行上的该单边界UB1误差，实际策略部署还要检验精度、布局和轨迹。

强当前控制之后，新增信息带来0.49436个百分点的捕获率增量，六来源均为正且均好于打乱控制；未选行的这个下一norm误差合并下降约0.7491%。这些数字是**采样行有限响应诊断**，不是生成质量变化百分比，也没有与原R16实际门控补偿能量评分直接比较。完整每来源数值见[初始CPU读出](../research/20261023/C1N0_dense_value_CPU.json)和[更强当前控制](../research/20261023/C1N0_dense_value_robustness.json)。
