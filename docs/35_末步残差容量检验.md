# LR1：末步残差容量检验

TF2相同状态诊断显示四个固定来源的合并末步更新后SSE最大，触发LR1。固定UB1主支持、gain/bias/QDQ，仅比较末步rank512残差与两种rank256对照：相同训练来源重拟合的rank256，以及原冻结UB1 rank256。

rank512此前已在原12输入RR1、step0/2的半宽支持CV中考虑过，256因达到门槛且成本更低被选中。LR1是另一个条件：末步75%主支持、24个C24学生实际状态、固定block10/30；不把rank512本身当创新，也不重开rank/lambda扫描。

使用OP1实际V1、局部dense TeacherY和gate，在原完整M上重算冻结UB1主分支。原C24主分支及加残差输出须先逐位复现24个实际捕获，UB1重算主分支不伪称为实际UB1捕获。输入来自C24学生，尚不是UB1自身轨迹。

固定12/12来源奇偶拆分、lambda1和既有种子，分别使用原RRR函数拟合rank256/512。评估保留原完整M的BF16残差两次线性、BF16加主分支及原gate，FP64累计误差。四个block/fold都须同时满足R512/匹配R256≤0.95、R512/冻结UB1 R256≤0.95，才可进入另行实施的完整40位置拟合与视频。主分支和冻结残差已使用全部24来源，CV只约束新残差训练。

若升级，四步残差秩为256/256/256/512；主MAC仍为50%，辅助MAC从dense FFN的1.85185%增至2.31481%，额外成本必须纳入新的完整FFN实测，不能继承原1.546×速度。

[运行前协议](../reports/worker_20261020/LR1_registered_protocol.json)、[源码冻结](../reports/worker_20261020/LR1_before_fit_source_freeze.json)和[64项测试](../reports/worker_20261020/LR1_preflight_64_tests.txt)均已保存。小试已完成，四项中两项通过，按整体门槛拒绝；没有全40拟合或新质量/速度通过结论。

## 完成结果

| 末步块 | 折 | R512/匹配重拟合R256 | R512/原冻结UB1 R256 | 双门槛≤0.95 |
|---|---:|---:|---:|---|
| block10 | 0 | 0.921840 | 1.108914 | 否 |
| block10 | 1 | 0.922658 | 1.137925 | 否 |
| block30 | 0 | 0.873733 | 0.874868 | 是 |
| block30 | 1 | 0.876492 | 0.900599 | 是 |

block10虽优于相同来源重拟合的rank256，却仍比原冻结残差更差；block30同时优于两个对照。不能只选两项通过后宣称LR1通过，也不能据此断言所有末步层或更大残差都无效。旧冻结残差用过全部24来源，而CV新残差每折只用12，比较较保守且有明确暴露边界。内部45.255秒，见[四项原始风险与参数SHA](../reports/worker_20261020/LR1_native_risk_RUN.json)。

原始源码冻结记录的`condition_still_pending_full_TF2=true`是滞后的状态注记：同一进程随后读到完整TF2，16秒后才启动LR1。原记录未改写，[时间澄清](../reports/worker_20261020/LR1_registration_timing_clarification.json)另存；条件判断仍由程序读取完整TF2执行，协议和门槛没有改变。
