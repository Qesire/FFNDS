# HiF4仿射矩阵的分组Hessian量化修复（R8F2）

[R8F1](59_仿射骨干的完整支持原生精度检查.md)定位出具体障碍：BF16全支持折叠仅占UB1误差的0.081%–0.205%，但完整HiF4表示占10.14%–26.85%，八项均未过固定10%门槛。这没有否定仿射分解；当前问题是新增量化误差。本轮只改变离线仿射权重编码，不开始神经元压缩。

## 已知方法迁移与实际改动

采用已知GPTQ/OBS误差补偿思路。已核对作者的[固定版本代码](https://github.com/IST-DASLab/gptq/blob/2d65066eeb06a5c9ff5184d8cebdf33662c67faf/gptq.py)，来源与SHA见[主来源记录](../research/20261021/R8F2_primary_sources.json)。原实现使用阻尼后的输入Hessian逆矩阵Cholesky因子传播量化误差；论文是[GPTQ](https://arxiv.org/abs/2210.17323v2)。没有继承其语言模型准确率或速度结果。

HiF4的64个值耦合，不能直接套逐标量列量化。本实现从条件二次极小化推导整组适配：设`U=chol(inv(H+λI), upper)`，当前64列量化误差`E=Wg−Qg`，未量化未来列更新为`W_R ← W_R−E*inv(Ugg)*UgR`。用三维已知正定矩阵直接求条件最优解核对符号/转置，另用恒等量化器检查无误差时不改变权重。

使用原R8F1同一个BF16仿射矩阵；仅由12个奇数编号OP2来源的3072个post-Q1行构造未中心化FP64协方差。阻尼固定为对角均值的1%，不做activation order、不置换64组、不调阻尼/组大小。每组都由原生HiF4量化器一次编码；先证明分组RTN与原全矩阵RTN逐位相等。整个组编码、三角求解和未来列补偿使用FP64，推理只存原生HiF4有效BF16权重，无新增在线操作。

最近旧尝试包括历史R22原W1上的SparseGPT/剪枝、R2的未测仿射骨干和R8F1的RTN完整支持检查。本轮是已知补偿方法迁移到新折叠D×D矩阵与HiF4组编码，不增加rank、读出参数或支持搜索，也不声称方法创新。

## 固定对照与门槛

[协议](../research/20261021/R8F2_group64_hessian_protocol.json)仍为step2/3 block20，验证来源00/06/12/18与R8F1完全相同，均不参与本次协方差编码。先复现48项旧UB1原生主输出/R控制、8项完整教师以及原RTN全支持损失。再比较原RTN、Hessian编码配BF16余项、Hessian编码配HiF4余项。两个位置各只编码一次，共两个矩阵。

仍要求全部8项完整HiF4误差不超过原UB1的10%，且都改善原RTN；不改原门槛，不筛有利来源。不满足则关闭本固定量化修复，不搜索阻尼或支持。通过也只满足完整支持精度前提，后续余项可压缩性需单独登记。

所有来源已开发暴露；本轮没有SGD、视频或全新来源质量评估。全支持主MAC仍为原dense的1.185185，不是50%候选，也无完整FFN≥1.5×通过。编码矩阵与大张量只存HF缓存，原50%/1.5×/三项新来源质量各≤2%下降的目标不变。

当前状态：**编码与全部原生检查完成，固定修复被拒绝。** [完整结果](../research/20261021/R8F2_native_hessian_results.json)保留原生控制、两个编码矩阵、全部八项数值和SHA；137项CPU检查通过。48项旧UB1主输出/R与8项完整教师逐位控制均通过；分组RTN逐位复现原RTN。

## 实际结果与数据归因

训练仿射SSE由step2的23317.98降至5329.63，由step3的20335.80降至4646.46，均改善约77.15%。但完整HiF4原生误差/UB1在step2为0.10298–0.12405，step3为0.24134–0.27171，八项均超过原0.1门槛，仅3/8优于RTN。因此关闭这个固定组编码，不调整阻尼/actorder/组大小，不执行余项压缩。

[保存操作数CPU审计](../research/20261021/R8F2_transfer_audit.json)核对全部训练/验证来源：Hessian/RTN仿射SSE训练比0.22856/0.22849，验证比1.01246/0.96107。权重误差平方范数却增至2.57/2.52倍。3072行在5120维中的rank上限不能单独证明样本不足，二阶矩trace有效维度实测约100/108。

[进一步分解](../research/20261021/R10_saved_failure_geometry.json)显示验证输入投影至训练行张成空间后，其输出误差下降58.6%/59.8%；空间外部分输出误差却增至5.72/5.55倍，连同交叉项几乎抵消收益。这里只分析固定已保存矩阵，没有新拟合、编码或模型生成；不能据此断言多采token必然修复。

本实验沿用R8F1固定0.5斜率，并额外量化新仿射矩阵/余项。原R2本来规定学习每通道斜率/截距和BF16骨干，未要求额外HiF4；[原文范围校对](../research/20261021/R9_scope_reconciliation.json)明确两者差别。固定修复失败不能关闭尚未测试的原R2设计。后续广泛复盘、路线取舍和未运行草案状态统一见[当前R10复盘](61_全路线失败归因与组合方案复盘_R10.md)。
