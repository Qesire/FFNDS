# 通道粒度诊断与常驻计时协议

## CG1通道粒度诊断已关闭

协议`config/channel_granularity_cg1.json`在任何通道得分/拟合前登记。
仍使用原calibration12严格seed数据、block20/step0和2，固定单通道E均值top6912，
同样拟合非负中心化增益和b2均值残差。task0/task6不参与训练或选择。

校准对角能量保留率：high单通道69.50%对整组C的53.94%，low为63.98%对52.73%。
独立来源的channel/整组C native风险比约0.664–0.773。
预设≤0.75且每来源≥3/4的门槛，task0只有2/4、task6为3/4，整体失败，不升级部署。
这是post-Q2局部诊断，未宣称减少FFN0、未把任意通道重排当成原生QDQ可交换。
`cg1_channel_granularity_RUN.json`保存完整结果；参数和原始风险在节点HF派生缓存。

## 常驻权重和完整FFN计时

预登记协议`config/resident_ffn_benchmark.json`，实现为`resident_ffn_runtime.py`、`run_resident_ffn.py`。
这项系统工作首先检验数值等价，再使用任何时间数字。

原生offloader原本还会搬运HiF4桥接不再使用的raw BF16矩阵。
新独立runner在模型构建时仅将已被桥接覆盖的MMWeight矩阵换成1×1占位符，
保留真实bias、norm、modulation、pre/post全部参数；任何覆盖层回退到占位符都会直接报错。
真实量化矩阵、step-specific packed矩阵、scales和辅助参数在生成前常驻同一A10080。
不修改上游源文件；报告替换数、真实常驻字节、初始加载开销、显存峰值及零fallback。

完整FFN区域从原生infer_ffn开始，至post_process的gate/残差写回结束。
还保守地把共享pre_process全部成本、所有raw占位符/bias预取及首次初始化成本计入FFN，
其中一部分服务注意力，也不从候选中扣除。每区域设备同步，保存wall与CUDA event两种时间。
包括norm/modulation、QDQ、两个主GEMM、GELU、增益、残差两GEMM、原gate与写回。
仅离线packing和一次模型常驻准备作为两arm共同的稳态setup单列。

必须覆盖实际四步40层，先与此前同输入/arm视频的四步FP32 latent逐位相等。
初始smoke与另一张卡生成正式视频同时执行，因此不能作为隔离的正式速度验收。
正式计时要求无其他项目GPU工作，一次warmup后三次完整请求，使用时间总和之比，不能挑最快一次。
当前正式质量视频使用原offload实现；同一方法的联合验收还要求20个正式输入在常驻实现下逐位验证，不能仅由一个smoke推广。

## 两个实际smoke结果

D-Q和RR1分别完成完整四步/160位置，四步FP32 latent均与原offload版本逐位一致。
D-Q真实常驻参数56,222,842,880字节；RR1还包含固定辅助参数/逐位置偏置，具体字节见RUN报告。
原始矩阵占位符没有被用于计算，所有1600个桥接线性与QDQ调用完整、cache miss/fallback为0。
单次热身请求完整FFN计时为D-Q 9,926.84ms、RR1 6,481.57ms；均保守计入共享准备/全部预取。
它们是不同作业的热身、另一张卡仍有视频生成，不能把比值当正式≥1.5×速度通过。
逐区域wall/CUDA时间及全部实际形状/辅助GEMM在两份`resident_*_smoke_REQUEST.json`中。
`verify_resident_formal.py`已经开始逐条验证正式20输入的全部latent与视频字节，尚未完整完成。
正式质量比较与此独立执行；隔离重复计时仍待两张卡的其他作业完成后安排。
