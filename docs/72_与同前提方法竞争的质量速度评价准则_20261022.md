# FFNDS：同前提竞争优先的质量—速度评价准则（2026-10-22）

> **用户对研究目标的直接修正。** “50% FFN 主 GEMM MAC、1.5× 完整 FFN 加速、三项官方视频质量各下降不超过2%”是最初随意设定的参考值，不是未来所有候选的一票否决条件。现在的目标是**以轻量后训练为主，在真实生成视频质量可信的前提下，使动态 FFN 方法相较同前提的其他强方法有可复现的优势**。本说明指导新探索，不追溯修改任何历史冻结试验的评判和授权。

## 一、唯一科研目标与执行动力

发明一个在冻结 Wan2.2 四步蒸馏 D-Q 上实际可执行的条件 FFN 计算方案，既节省真实运行成本又保留或改善视频质量。算法可以改变信息、动作粒度、FFN 数学表示、跨 block/step 计算预算、量化与融合执行；不要为了填满机制分类而增加组件。追求**可比较的性能贡献**，例如：

- 同等自由视频质量时，完整 FFN 和视频端到端推理更快；
- 相同实际加速水平或总成本下，视频质量更高，特别是运动、背景稳定性和图像细节；
- 相对所有已复现可比方法形成有意义的 Pareto 前沿：速度更快而质量同样好，或质量更好且代价值得；
- 在无大型重新蒸馏、很少后训练的前提下，相比依赖大量训练的文献方法提供有吸引力的现实折中，但必须清晰报告这种不同前提，**不能把不等训练条件的数字硬说成同条件直接领先**。

这里的 **50% / 1.5× / 2% 是历史坐标，不是未来研究设计所依赖的固定门槛**。不必为了让一个模型过 1.5× 而牺牲更有价值的质量—速度曲线。MAC 可以是 40%、55% 或其他，只要真实成本、竞争基线和质量改善解释清楚；没有任何固定 MAC 数值本身能证明论文价值。

## 二、如何与学术界论文真正进行同前提比较

优先查验原论文、官方代码和确切模型配置。把所有指标放进下面这张**对齐账本**（不是把不同工作的一行最佳数字直接排大小）：

| 维度 | 必须核对的信息 | 不一致时怎么做 |
|---|---|---|
| 模型与任务 | Wan2.2 I2V A14B 四步 D-Q、LoRA/蒸馏类型、是否重新训练、教师/学生身份 | 原生适配并跑同源强基线；未经适配只当跨任务参考 |
| 推理过程 | 真实模型时间、步数与 scheduler shift、CFG、视频帧数和分辨率、输入图/文本/seed | 对齐协议、限制结论于共同设置，不做伪同条件加速宣称 |
| 数值执行 | BF16 vs HiF4 软件 QDQ vs 真硬件 FP4、attention 和 packing | 单独列数值与 kernel 开销；不同计算精度不可冒充同方法 |
| 计算设备 | GPU、驱动/CUDA、PyTorch、GEMM/kernel、offload 与峰值 VRAM | 用同一设备实现/复算；跨设备引用原论文数值只作参考 |
| 质量测量 | 新来源、视频序列、VBench-I2V aesthetic/imaging/motion、画面稳定性 | 成对 D-Q 和可比方法；报告逐轴、分布和离群劣化，不能以 proxy SSE 代替 |
| 成本口径 | 主 MAC、完整 FFN、端到端视频 wall time、选择器、QDQ、pack、动态布局、后训练成本 | 等实际计算/等质量双视角比较，至少一条可验证的完整系统口径 |

**核心比较顺序**：Dense D-Q（质量与真实延迟基准）→ UB1（工程静态参考）→ **同条件经过充分调整的最强固定稀疏/时步/空间策略** → 与本算法最相近、可以可信复现或适配的学术方案 → 自己的新动态候选。

优先选择和研究问题直接竞争的工作：E-DiT、PARE、FIS-DiT、Dynamic-in-Few-Step、Prox、Chipmunk、RT-Lynx、ToMe/ToMA 等。只有真正在对应 I2V、few-step、冻结 D-Q、同环境中跑出的版本，才参与“同前提最高”的直接判断；原文中的 T2V/不同硬件/不同训练预算结果是**知识边界和方法先例**，仍有参考价值。

## 三、评价方式：多工作点而非单个数值

在几个预先选定的计算预算或执行动作规模上同时报告：

- `MAC(main GEMM)` 与所有额外物理计算；`FFN latency` 和端到端生成时延，分别有 dense、静态、动态几条曲线；
- 图像质量 aesthetic/imaging、运动 motion、时空闪烁/边缘稳定性分析；三轴不能被一个隐藏权重的分数替代；
- 优化器/选择器训练数据量与训练耗时、参数新增量、峰值显存；
- 独立新来源配对差值及来源维度的置信/不确定性范围，报告失败例与人眼审阅视频；
- 当观测到候选与最强固定有不同偏好时，比较**等 MAC 质量**、**等质量速度**，有真实延迟也比较**等完整 FFN 延迟质量**。

**Pareto 判断**：若其他方法在质量各关键维度不低于候选、端到端/FFN 时延也不高（训练与内存假设相近），且至少一个指标明显更优，则候选被支配；如果方法存在清晰的实际质量—速度改进或优质权衡，值得推进，即便未跨原随意阈值。不可用一个局部 oracle、合成 1.6× 或理论 MAC 直接把点放上已测真实视频 Pareto 曲线。

资源稀缺时先在开发来源做小型、**同条件 paired** 原生/视频实验，找到新的可执行机制，再按独立来源冻结评价；不是每个探索种子都要一开始完整视频跑100条。每个正式新实验必须有**自己预登记的对照/停止条件/指标**，由基线差距、测量精度和资源共同决定；不得试后调门槛美化结果。

## 四、R13 的实际启示

R13 直接二维点非线性方案在随机张量 A100 上测得约 **1.355×**；这仅是该固定直接实现的合成算子性能，尚无真实 Wan 效果，不得因为“比原1.5×少”就全盘否定“联合线性对比 + 两点非线性响应”这一不同数学研究对象。

R13 的 Haar/三方向压缩在固定前提下把理论主投影 MAC 降到约 **45.1381%**，CPU 数值检查通过，但没测 GPU 或真实视频。下一个便宜证据可以是融合重写的诚实 GPU 成本检查与真实四行输入的原生价值测量（需分别登记执行）；若另一种有明显不同的算子实现更有说服力，可优先。**先判断它相对强基线的质量—速度潜力，再决定 GPU 预算**。旧固定直接实现的拒绝仍为那一实例的真实结果。

## 五、对 agent 的具体命令

1. **READ**：当前 `CURRENT_DECISION` → `OBJECTIVE_CONTRACT.research_evaluation_policy` → 最新证据与交接 → 本文件 → AutoResearcher skills → 与算法最接近的论文及代码。
2. **GENERATE**：围绕质量保持与真实省算提出内容/信息/算子/表示/部署上独立的可执行构造；不把机制解释数量、V4/R13 设计名称或 50%/1.5×/2% 当研发任务。
3. **COMPARE**：每条进入模型实验的候选必须说明最强**同前提**动态/静态/文献竞争基线，以及预计质量—延迟的优势和可反驳的竞争解释。旧 UB1 是工程参考，不保证始终是最强竞争者。
4. **EXECUTE**：优先主动执行已获许可的源代码、代数、保存证据、CPU、模拟计算和软件检查；真正 GPU 模型任务、训练、显著资源开销另需原生登记与明确授权。
5. **RECORD**：报告何种性能口径上更强、哪些维度较弱，以及这一结果支持的下一种算法构造；旧注册失败不得改写，未测的加速与视频质量不得宣传为实测。

**成果形式**：可复算算子/对照 + 最新论文差异分析 + 真实质量与端到端成本的证据；评价项目不再是通过随意三数阈值，而是证明在公平设置下确实优于已有可比选择。

## 用户新增：正式备选必须完成自由生成质量底线

当一个算法经局部验证被决定作为**备选方法继续开发**，必须在真实四步学生中至少生成一条完整自由运行候选视频，与同输入/seed 的 Dense D-Q 成对审阅；不允许仅凭本地 FFN、合成硬件或固定输入 flow 验收。检查主体/运动、背景小物体、静态区域光照闪烁等明显质量崩溃。任何严重失稳都阻止该实例晋级，单视频通过也只代表初步 smoke，不替代独立样本的正式质量—速度 Pareto 评估。执行仍需单独登记与用户授权。详细规则见[docs/75](75_备选算法必须完整生成与防止视频质量崩溃_20261022.md)。
