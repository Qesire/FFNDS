# RB1：四支持模式的路由可行性小试

UB1已经提供同一冻结实现的完整FFN1.546×和原正式20质量通过结果，它仍是静态步间预算基线。RB1只检验一个后续问题：使用已有postQ1输入，便宜的小网络能否选出保留更多教师C贡献分数的支持模式。

本小试不修改UB1，也不使用来源分离20输入拟合。它使用原C24学生的24个开发来源、step2/3 block20的实际V1，以及已通过48个TeacherY重放控制的派生dense教师Q2。旧学生本身用过全部24来源，因此12/12来源CV不是整条管线的未见测试。

在每折训练来源上，按连续64通道组计算原FP32 W2/gate贡献的平方和，再将每行216个C分数归一化为和1。固定K4 kmeans++、20次Lloyd更新；每个bank选该簇平均归一化C最高的组，匹配静态对照选全部训练行平均分数最高的组。step2/3分别保留108/162组，与UB1相同步预算。只对训练来源拟合聚类、支持、输入标准化与网络；验证教师分数仅用作离线oracle诊断。

路由器固定5120→32/ReLU→4，FP32 AdamW训练20轮、240次更新，禁止挑epoch或超参扫描。训练输入的mean/std折叠入首层W/b，部署边界用BF16参数和原完整M/布局计算两次F.linear/ReLU，argmax选bank；不在线计算教师隐藏层或做批次标准化。

先记录每折验证行的静态、四bank离线最佳oracle和折叠原生路由的平均保留C比例。只有四折都满足oracle比静态至少高0.02，且实际原生路由捕获至少一半oracle改善，才进入另行登记的native FFN重建实验。空簇或训练bank少于128行时按该折失败处理，不更换seed。

**C分数不是native FFN误差。** 它忽略组间相关、完整非线性路径、gain/bias和残差；即使本代理门槛通过，也不能推出视频或部署速度通过。后续实际模型实验需要匹配的条件残差/静态支持对照、原生逐位控制、真实routing/packing/padding成本及同一实现的完整验收。

入口为`tools/continue_router_bank.py`，等待来源分离20输入的两臂评估完成后，才在一张空闲GPU执行。拟合前[协议](../reports/worker_20261020/RB1_registered_protocol.json)、[拟合前源码冻结](../reports/worker_20261020/RB1_before_fit_source_freeze.json)及[57项CPU测试](../reports/worker_20261020/RB1_preflight_57_tests.txt)均在GPU运行前保存；下文记录已完成的结果。原始C分数和小网络参数只写HF derived cache，源数据和原通过候选均保留。

## 实际结果：簇规模预检查拒绝

GPU实验已完成，四折都在网络训练前被拒绝，没有路由网络更新、native FFN拟合或视频运行。簇规模分别为：

| 位置 | CV折 | 四簇训练行数 |
|---|---:|---|
| step2 block20 | 0 | 467 / 105 / 1381 / 1119 |
| step2 block20 | 1 | 162 / 731 / 2139 / 40 |
| step3 block20 | 0 | 87 / 2154 / 790 / 41 |
| step3 block20 | 1 | 325 / 248 / 2458 / 41 |

均存在小于预登记128行的簇，按协议不更换seed、不降低样本数门槛。程序内部计时9.292秒，C分数数组和两位置payload SHA保留HF缓存。此结果只说明本次普通Kmeans的四bank样本量条件未满足，不能解释成预测网络已训练但无法学习，也没有四折native预测性能数字。见[完整结果](../reports/worker_20261020/RB1_proxy_RUN.json)与[检查点身份](../reports/worker_20261020/RB1_identity.json)。
