# FFNDS：按学术文献测量粒度重建指标体系（2026-10-22）

> **现行评价规范，适用于今后新方法；既有 R4/R11/R12/R14N0 登记的指标、阈值、原始结果与关闭结论均不追溯修改。** 这不是给每个想法增加一长串必须完成的评测项目，而是根据**论点需要的证据级别**使用最少、可区分机制的指标，再在真正选中备选方法后完成至少一次真实自由生成。50% MAC / 1.5× / 2% 是历史参考而非统一淘汰线。

## 1. 文献依据：视频质量、稀疏效果、系统速度属于不同测量对象

1. **VBench**（Huang et al., CVPR 2024）：将视频质量拆为**时序质量**（subject consistency、background consistency、temporal flickering、motion smoothness、dynamic degree）、**逐帧质量**（aesthetic quality、imaging quality）以及视频和条件语义一致性；这些维度的方向、算法与适用样本并不相同。论文及官方说明：https://openaccess.thecvf.com/content/CVPR2024/html/Huang_VBench_Comprehensive_Benchmark_Suite_for_Video_Generative_Models_CVPR_2024_paper.html 、https://github.com/Vchitect/VBench。
2. **VBench++ / VBench-I2V**（Huang et al., 2024）：FFNDS 的核心公开质量基准采用原仓库 \`vbench2_beta_i2v\`（避免和 VBench-2.0 名字混淆），分别报告官方 \`i2v_subject\`、\`i2v_background\`、\`camera_motion\` 及 \`subject_consistency\`、\`background_consistency\`、\`motion_smoothness\`、\`dynamic_degree\`、\`aesthetic_quality\`、\`imaging_quality\`。**官方不同维度可能使用不同素材子集**；保留维度级样本集合、版本、归一化与各指标，不仅报综合分。官方实现：https://github.com/Vchitect/VBench/blob/master/vbench2_beta_i2v/README.md；论文：https://arxiv.org/abs/2411.13503。
3. **VBench-2.0**（Zheng et al., 2025）补充物理常识、人的运动、组合关系等内在真实性，可在相应研究中选用**拓展模块**，不是强行替换 I2V 常规评估、也非首条 smoke 必跑。https://arxiv.org/abs/2503.21755。
4. **FVD 的限制**：Ge et al.（CVPR 2024）指出其可能偏向逐帧内容而不敏感于时序损坏；Luo et al.（ICLR 2025）指出小样本稳定性和 I3D 特征限制。因此 FVD/JEDi 等**数据集分布级**指标只有在样本规模、特征/实现/预处理足够可比时才选作补充，**不能代替单条视频异常筛查**。https://openaccess.thecvf.com/content/CVPR2024/html/Ge_On_the_Content_Bias_in_Frechet_Video_Distance_CVPR_2024_paper.html 、https://proceedings.iclr.cc/paper_files/paper/2025/hash/a57483b394a3654f4317051e4ce3b2b8-Abstract-Conference.html。
5. **真实加速**：稀疏视频 DiT 研究实际区分 theoretical FLOPs 与 end-to-end measured speedup，同时报告视觉保真度（如 Sparse-vDiT，AAAI 2026）。FFNDS 必须进一步区分主 FFN GEMM、完整 FFN、完整四步视频、网络/权重搬运/编解码及训练成本。示例：https://ojs.aaai.org/index.php/AAAI/article/view/37287。

以上为**行业常用指标及框架**，下面的 L0–L5 层次、tail summaries 和分层晋级属于 FFNDS 为实际问题设计的**项目评价协议**，不是声称所有论文都有统一阈值或同一层级命名。

## 2. 核心设计：测量粒度不等于结论粒度

| 层级 | 物理/语义统计单元 | 核心指标及用途 | 允许的结论 | 不能推出 |
|---|---|---|---|---|
| **L0 算子与数值** | Q1/W1/GELU/Q2/W2、gate/writeback；量化边界、一次调用 | BF16 bitwise / \`max_abs\` / \`rel_L2\`、shape/dtype、数值守恒、MAC 账本 | 真实执行链是否忠实，数值/成本来源 | 原生下游、实际速度、视频质量 |
| **L1 token/空间区域** | 单 token、四点 stripe、ROI、patch 和 full-scene spatial strata | 同状态 \`writeback_SSE\`、\`NMSE\`、余弦/方向、\`p50/p95/worst\`、主体/背景/高频区域损失；same-budget matched fixed、oracle–selector gap | 误差来自何处、何种动作有效、长尾是否异常 | 一帧画质、整段时空稳定、完整视频可信 |
| **L2 block/step 传播** | 一层/多个 block、同一完整 denoise step、四步 latent 轨迹 | native step-flow SSE / normalized error、\`cos(delta, downstream_error)\`、步骤敏感度、误差累积；注明固定状态与自由续跑 | 本实验观察的传播位置与方向 | 带 D-Q 恢复的 forced-flow 当真实自由生成 |
| **L3 完整视频 smoke** | 一条完整四步学生自由运行视频（帧和时间段） | 实际完整生成、配对 D-Q 视频、人工全片逐段审阅、主体/运动/背景细节/静态光照异常，必要时 frame-pair LPIPS、稳定区域差值和对齐后 flicker 诊断 | 该条视频是否存在明显崩溃 | 官方平均质量、跨来源泛化 |
| **L4 视频/数据集质量** | 每条视频→每来源/类别→冻结独立来源的整体 | VBench-I2V 9 个官方维度及版本、每维配对差、动态幅度/闪烁、质量尾部；可选 VBench 2.0、FVD/JEDi | 给定模型/任务/来源下的质量分布与失败率 | FFN 实际加速、不同设置直接可比 |
| **L5 整体系统与论文竞争** | kernel、完整 FFN、一次全视频生成、GPU/软件/训练设置 | 原生 kernel+QDQ+selector+layout+correction 延迟；FFN 总延迟；端到端 GPU 生成与 wall time；峰值 VRAM、物理 FLOPs/MAC、训练成本、iso-quality speed、iso-latency quality、Pareto | 同前提的速度—质量—资源竞争结论 | 无新颖性审查即可宣称方法原创 |

**递进但不替代**：低层结果可解释高层现象，但不能冒充高层结果；如果有真实可执行、具研究价值的方法，即便 L1 师生 SSE 不占优，仍可根据机制选择少量 L3 视频判断是否出现灾难性异常。L2 下游误差改善也不能免除 L3。

## 3. 指标计算：必须防止总 SSE 伪代表真实信号

### 3.1 L1：原生局部指标

设同一真实学生输入 \(x\)，原冻结 Dense D-Q 的完整 FFN 输出 \(F_D(x)\)，候选 \(F_\pi(x)\)，真实 FFN 后写回 \(P(r,y)=\operatorname{native\_writeback}(r,y,g)\)。

- \(\mathrm{SSE}_{\mathrm{post}}=\sum_{i\in S}\|P(r_i,F_\pi(x_i))-P(r_i,F_D(x_i))\|^2\)。**只回答同状态局部重建误差**。
- \(\mathrm{MSE}_{\mathrm{post}}=\mathrm{SSE}/(|S|\cdot D)\)，保留 token 数和通道数；对比不同 \(|S|\)/形状不直接使用总 SSE。
- \(\mathrm{NMSE}_{\mathrm{post}}=\mathrm{SSE}/\max(\sum_{i\in S}\|P(r_i,F_D(x_i))\|^2,\epsilon)\)；也可报 \(\|F_\pi-F_D\|^2/\max(\|F_D\|^2,\epsilon)\) 作为 FFN-only 误差，**两者需不同 metric ID**，且 post residual 可能很大使相对误差显得很小。
- \(\cos(\delta,e)\)、投影系数/向下游雅可比的定向误差用于理解误差与先前累计误差的关系；只是在同一状态/方向下的诊断，不能直接代替质量。
- 保留 \`token/stripe\` 分布的 mean、p50、p95、p99、max、各来源分组和失效局部示例。对分母/空间组数、top-k 使用什么统计单元必须写清。
- 如有真实分割/跟踪/静态区域掩码，将主体、背景、边界、纹理/光照稳定区**分别报告**；没有掩码不能推断相关指标。

R14N0 原 \`SSE\` 的计算及 BF16 原生控制可以保留为有效的 **L1 测量**。它只取 step2/block20、四个已经暴露的来源、64 个四 token 组（256 行）；“+31.1642%”是其 L1 局部总 SSE 对 UB1 的相对变化，**不是 +31% 视频画质损失**。它可终止已登记的固定 L1 判定，但不应被用来全局否决有本质机制差异的新方法。旧结果不追溯变更。

### 3.2 L2：原生后续步骤的敏感度与方向

用同一出发状态比较干预对当步预测、denoise step latent、后续 block、最终流/视频路径的影响。至少分清 \`teacher_forced_same_input\`、\`step_native_with_reset\`、\`free_running\` 三种传播模式。每个测量记录干预 \`(step,block)\`、完整重复的步骤数、对照身份、\`denoising_scheduler\` 及 shift 后实际 model timestep。

\(\Delta_{\rm flow}=f_\pi(x)-f_D(x)\) 在相同输入下的范数、与既有状态误差方向的内积等可以阐明补偿机制；**最小 L2 SSE 不必对应最低视频损害**，须在 L3 证伪。

### 3.3 L3：最低质量底线，是一条真实自由生成视频

- 配对：输入图、prompt、seed/初始噪声、相同四步实际 timestep、模型/量化精度、帧数、分辨率、解码流程；保留 SHA、候选实际 FFN 作用位置和生效统计。
- 全片观看并在时间轴上标注：主体身份/几何、运动突然改变、相机运动异常、背景小物体/边缘跳变、**静止区域不自然的光照周期性闪烁/明暗起伏**、噪声/画面崩解。
- 辅助可选：同源视频的每帧 LPIPS/SSIM/PSNR（注意动态运动的像素不一一对应，直接逐帧差值可能把合理运动视为错）、静态 ROI 的 \(\Delta_tI\) 与二阶时间差、光流/相机对齐后的残差（报告遮挡/光流失败/不可信动态区域）。这些是项目自定义**诊断**，不冒充 VBench 官方维度或真实闪烁的唯一度量。
- **一条视频不崩溃 = 仅 L3 smoke 通过**。不能仅凭一条视频报官方质量成功，更不能挑选 seed 隐去失败样本。失败记录保存视频和时间位置；判定不明就保留待审。

### 3.4 L4：公开基准与样本总体

**默认完整正式质量向量（官方 VBench-I2V）：**

\`i2v_subject\`, \`i2v_background\`, \`camera_motion\`, \`subject_consistency\`, \`background_consistency\`, \`motion_smoothness\`, \`dynamic_degree\`, \`aesthetic_quality\`, \`imaging_quality\`。

三轴 aesthetic/imaging/motion 可以和历史原协议继续报告，但**不再是评估新算法完整视频表现的全部维度**。主体、背景、静态光照等不应被高综合分掩盖。\`temporal_flickering\` 如果使用，明确官方版本/实现与视频子集；视频局部静态照明闪烁建议追加自定义时序 ROI 诊断并人工确认。

数据表的最低粒度是**每视频 × 每维度**（以及该维度实际参与的样本集合），随后再按来源/运动类型聚合。报告配对平均差及其不确定性、p10 或最差来源、可见崩溃个数；足够独立来源时按**来源/提示词簇** bootstrap（不是把相邻帧当独立样本）。保留原始分数与方向，不随意在不同来源间求综合百分比。适用时追加 VBench-2.0 物理/常识维度；FVD/JEDi 只在大样本分布级比较中使用并披露特征/样本量/实现。

### 3.5 L5：与学术界同前提比较

同一次测量分别报告：
- \`main_ffn_mac_fraction\`：主 GEMM 算术预算；不声称实际物理延迟。
- \`complete_ffn_latency_ms\`：包括 norm、Q1/Q2、selector、pack/scatter、W1/W2、补偿、gate 和 residual；分阶段时间与总体时间均保留。
- \`generation_gpu_time_s\` / \`generation_wall_time_s\`：完整四步包含 attention 与 FFN 的生成，写清解码、首次启动/编译、权重/offload、是否含数据 IO。定义不同的子项单独列，不能交叉称端到端。
- \`peak_allocated_vram_gib\`、\`peak_reserved_vram_gib\`、\`train_gpu_hours\`，以及算子/模型/精度环境。
- 相比同次 D-Q、同设置强静态、近邻文献的**可复现适配版本**，作 iso-quality latency、iso-latency quality / Pareto 比较；跨型号 GPU、推理步数、量化和训练成本的原文数字标记为 \`CROSS_SETTING_CONTEXT\` 而非“我们领先”。

**核心不是找一项最好看的速度/质量数字**：输出每个被支持的方法工作点的真实质量向量、成本和误差分布，对其他方法是否支配它做多目标判断，允许明确竞争取舍，不把多轴压成随意加权的一分。

## 4. 评估执行次序：按证据价值，不强制全部前置

1. **探索**（L0、L1 可选 L2）：只复算对当前机制最具区分力的最小诊断；局部 SSE 可失败，解释原因并允许有根据地选择完整视频。
2. **备选确认**（L3 必须）：明确可执行算子并获得单独模型作业授权，完成至少一条原生自由视频的 Dense D-Q 配对 + 全片质量崩溃审阅；没有这一步只能叫局部候选，不得宣称“质量可用”。
3. **质量与论文基线**（L4 + L5）：若 L3 无崩溃，在实际候选和强静态/最新可复现方法间做来源独立、官方质量与完整速度的成对多工作点比较，回答是否具备论文价值。
4. **机理复盘**：若 L3/L4 变差，回溯 L2 误差方向与 L1 的空间/step/背景 tail；优先定位造成视频劣化的机制，而不是强行让 L1 数字漂亮。

所有结果必须标注：\`metric_id\`、\`level\`、单位/方向、空间统计单元、时间统计单元、对照输入状态、实验模式（local/forced/free）、已覆盖样本、stage source exposure、聚合规则和代码/数据 SHA。**没有实际测量就填 null，不把 draft、oracle 或 CPU 引导构造写成 measured。** 结构化契约见 [metric catalog](../research/metric_system/catalog.json)，简短可检验记录见 [metric record template](../research/metric_system/metric_record_template.json)，以及 [离线验证工具](../tools/check_metric_contract.py)。

## 5. 与当前 FFNDS 状态的绑定

- R11：局部 loss 与 native step-flow 可反向，是 L1/L2 区分的真实例子。
- R14：随机合成 A100 1.913× 只能称 L5 的 **synthetic backend microbenchmark**，不能称部署端到端加速。
- R14N0：实际 step2/block20、64 空间组的 \`post_writeback_sse\` 是 L1；开发动态相对 UB1 高 31.1642%，但全视频未生成，不能宣称具体质量损失。按原注册 L1 目标关闭固定实例，不改变其结论。
- 以前 UB1 的 VBench 子维度与完整 FFN 性能分别保持 L4/L5 来源标签，不通过合并来源来“凑总评价”。
- 最终论文结果优先回答：**在同前提的强方法之间，真实自由生成视频的时空质量和实测完整推理速度是否形成可复现的优势？**

该体系不申请 GPU、重新登记方法，不扩历史实验范围。
