| 范围 | 现状 | 证据性质 |
|---|---|---|
| UB1（54/108/108/162 个64通道组；含 gain、bias、R256） | 原开发20三项质量通过，补充20 imaging 下降 **3.165968%**，尚未跨来源达标 | 历史 GPU / 视频评分报告的算术复核 |
| 完整 FFN 性能 | dense **10177.568613ms**；UB1 **6582.688544ms**；**1.546111×**。不减少现有成本时，维持1.5×仅剩 **202.357198ms（3.074081% UB1）** 的历史点估计余量 | 旧计时数据，非新计时或置信上界 |
| 有符号收益 | `A = ||y0-yD||² - ||y1-yD||² = -2⟨e,d⟩ - ||d||²`，其中 `e=y0-yD`、`d=y1-y0` | 相同原生边界下的代数恒等式 |
| 真正的动态余量 | 两个等预算固定支持的 tile 收益为 `A_T`；完美动态比最佳静态多得 `(E|A_T| - |E A_T|)/2` | 理论 oracle；必须用实际连续 tile 和来源权重估计 |
| 仿射折叠方案 | `ρ = d/(2m) + K/m`；匹配每步25/50/50/75%预算的余项宽度为896/4352/4352/7808 | 理想矩阵 MAC；QDQ、cast、访存与真实速度未验证 |

## 暂停状态下的未来准入门槛（均未启动；详见第50号审查）

- 先对 R2 主候选在少数位置生成 **同状态、同量化/写回边界** 的 K0/K1 原生输出；证明相对于最佳固定 support 存在真正的 `tile` 级 `V_oracle`，再考虑复用 RR 的 h256 训练轻量标量路由头。行采样不等于连续 tile。
- R1 的 H1/H2/H3 轨迹诊断必须先通过纯 D-Q 与纯 UB1 的原生状态恢复一致性检查；它只能解释传播机制，不是满足50%预算的新候选。
- 对折叠备选先做 **全支持 native folding** 控制，再检验非线性余项是否可压缩；不能由 GELU 分解恒等式推断稀疏性。
- 所有新候选必须复验 **三项视频指标分别相对下降≤2%**、完整FFN **≥1.5×** 与实际相同部署预算，且使用**新的未参与开发来源**。原20与补充20均已参与方法开发，不能重新标注为未见测试。
