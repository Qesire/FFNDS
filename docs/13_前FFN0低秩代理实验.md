# 前 FFN0 低秩代理实验

## PR2：仅依据 W1 的 SVD，未通过

协议 `config/proxy_pr2_w1_svd.json` 在生成因子/得分前登记。
使用真实新 D-Q 矩阵的八个 block20/steps0/2 scope、4,096 行。
两专家分别在 worker GPU0/1 运行，数据独立随机 SVD 固定 seed20261020、q544、niter3。
候选 rank64/128/256/512；每个 rank 比较原始预测和仅由 task0 donor 拟合的输入能量残差校准。
预测链使用实际 V1、量化 W1、原 b1、native GELU(tanh)、原 s2 和 native HiF4 Q2。
测试 Z/V2 只用于诊断和独立投影评分，不进入预测或校准。

所有八种候选的 **Fit 均为 0/4**，按事先规则不选出候选。
Validation 的 rank512 raw 为 1/4，其余为 0/4；这些仅是事先声明的敏感性结果，不能反过来挑选方法。
rank512 raw 的风险/真实 C 比为 1.088–1.293；输入能量校准没有通过门槛。
两种完整计算的控制（dense FFN0 oracle / captured V2）在两个来源均为4/4，风险逐项等于父 AR2 C dynamic。

GPU 完整 FFN0 oracle 的 Z 与捕获 Z 逐位一致，C 得分与父 AR2 的相对 L2 误差约1.1e-16。
这验证了该回放链路；不能把完整计算 oracle 当成低成本候选。
rank512 仅保留量化 W1 约37.4%–37.6%的 Frobenius 能量，实测 Z 相对误差45.2%–49.5%。
代理两次 GEMM 的理论运算量为原 FFN0 的13.7%；尚未测在线总成本、tile支持或完整 FFN 速度。

证据在 `reports/worker_20261020/pr2_*`；原始分片在 `runs/worker_restart_20261020/proxy_pr2*`。
SVD 因子放在 worker 的 Hugging Face derived cache，位置和 SHA 随 score identity 保存。
协议没有因为结果失败而放宽，正式20条视频和160位置稀疏速度尚未验收。

## PR3：donor 输入 PCA，跨来源未通过

协议 `config/proxy_pr3_input_pca.json` 在任何 PCA/PR3 得分前登记。
仅用 task0 donor 的512行 V1 构造中心化 PCA，离线计算 W1 投影因子。
训练支持使用 donor 自身的基，测试支持使用 task0 对侧 seed 的基；Validation 不参与建基、残差校准或 rank 选择。
rank32/64/128/256/512，沿用同一门槛及 Fit 最小通过 rank 的选择规则。
原生 BF16 评估完整完成，约300秒。按预登记最小通过rank规则选出 rank512 raw：
Fit 为3/4，通过；Validation 为2/4，未通过，不能改选 Validation 表现更好的变体。
rank512 raw 的八scope风险/真实 C 比为1.020–1.227，两种完整计算控制仍分别为4/4。
rank512 的训练 Z 相对误差约0.00055–0.00060，但对侧种子为0.454–0.525、独立来源为0.597–0.617。
训练重建接近精确不能证明基在未见来源上有效。`pr3_*` 保存完整选择及敏感性结果。

## 两次缩小主 GEMM 与闭环参考

`probe_packed_ffn.py` 对真实 task0/seed20261001、block20 steps0/2、四个冻结随机mask，
各测试unit和1.3 gain，共16个组合。FFN0只计算6912输出，FFN2只输入6912，两个 GEMM 都为50%密度；
保留 Z、整组Q2、最终 gate 后输出均与完整计算再掩码的参考逐位一致，bias保留一次。
该数值核验没有 norm/modulation/residual 的完整计时或视频质量结论。

随后使用静态随机mask0在 task6/seed20261001 完成两个真正的闭环视频：
unit 与从 task0 block20 两种子/四mask 汇总得到的每专家gain（高1.691773、低1.761108）。
该gain向其他层/同专家另一step的外推在policy中明确标为未经验证。
两者均执行全部160位置/320个FFN线性调用，实际两次主GEMM均为一半，81帧、16fps、624×624。
**两者画面均明显退化**；生成成功不是质量通过。约74–76秒的生成墙钟包含观测、attention/编解码，不能作为FFN速度。
大视频及对比预览留在 `runs/`；小型运行元数据、失败准备记录、完整coverage随报告保存。
