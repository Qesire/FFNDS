## 1. 首要目标，不是手段

**FFNDS 的主要科学问题**：四步蒸馏后的 Wan2.2 I2V 中，FFN 的*条件冗余*是否仍存在？能否依据真正可部署、在昂贵主 GEMM **之前**可获得的信号，自适应选择有效的通道/分组/操作，并在完整 HiF4 计算链和自由学生去噪轨迹中，以可信的质量保持换取实际计算节省？

其工程验收沿用原协议，三者必须由**同一冻结部署候选**共同满足：

1. 全部位置主 FFN GEMM 的 MAC 相对相同原生 D-Q dense 不超过 **50%**。
2. 包含 norm/modulation、QDQ、选择器、两侧主 GEMM、GELU、辅助修正、layout、gate/residual 写回的**完整 FFN** 实际速度至少 **1.5×**；另行报告端到端视频耗时，不与 FFN 速度混称。
3. 在来源去重/重叠审计、首次冻结且真正独立的 I2V 来源上，原协议规定的 aesthetic、imaging、motion **每项相对 D-Q 不下降超过 2%**。这是逐项质量约束，不得以平均分、局部 MSE 或预测 flow SSE 代替。

上述阈值是先前冻结的项目验收合同，不是自然定律，也不是“已经达到”的研究结论。新的学术贡献还需展示**动态机制相对等预算最强静态控制的额外收益**；满足静态工程指标本身不等于完成输入条件动态稀疏。

## 2. 正确重建研究对象与信息时序

固定工作对象是 LightX2V **四步蒸馏 D**（step `1000/750/500/250`，40 blocks，维度 5120，FFN hidden 13824），采用原生 HiF4 Smooth/QDQ 与 BF16 边界。上游/本地源码与哈希参见 [源码校对](08_上游源码校对_20261020.md)、[R11G1 原生输出头](63_原生输出头梯度与零更新等价检查.md)、[R2 算子分析](../research/20261021/Wan_Distill_FFN_机制重构_R2_20261021.md)。

R12 E0补充澄清：上述step数字是配置的选取坐标，原生调度器先施加shift=5；TF2实际模型timesteps约为`1000/937.5/833.333313/625`。见[源码与八份原始步骤记录](../research/20261022/R12_E0_runtime_reconstruction.json)。这没有改变调度、缓存或既有实验结果。

在单个 block 的等价实数**结构记号**下（不是跨 QDQ/BF16 的数值可交换式），写
\[
z=W_0\,Q_1(u)+b_0,\quad h=Q_2(\operatorname{GELU}(z)),\quad
y=W_2h+b_2,\quad x^+=\operatorname{native\_gate\_residual}(x,y).
\]
部署中的预处理、量化、cast、bias、矩阵方向、累加顺序及输出写回仍必须按冻结源码逐项回放，不可把上式当逐位恒等保证。实际四步包含专家切换、所有 40 blocks 及学生状态推进。

令 \(\pi(a_{s,l},s,l,c)\) 是**在主 FFN0/W1 前**使用可观测且计费的信号 \(a\)、条件 \(c\) 选取支持或操作的策略，\(S_\pi\) 是执行支持。要区分：

- **静态省算**：\(\pi\) 只依赖预先固定的 step/block/expert 表格。UB1 的 25/50/50/75 四步预算可证明工程基线，但不是“输入条件动态路由”。
- **后验 oracle**：用实际 W1/全 hidden/教师输出才得出支持。它可能回答“是否存在收益空间”，但不能冒充低成本在线选择器。
- **部署动态**：策略必须在节省对象计算**之前**就能做出决定；特征、选择、pack/gather/scatter、QDQ 和补偿全计入同一时延。

先比较同等主 MAC、支持集合、补偿函数、原生输出边界下
\[
\Delta_{\rm cond}=L(\mathrm{best\ fixed})-L(\mathrm{conditional\ oracle}),
\]
再问提前可用的信息能否以小于其收益的代价预测这部分增益。这里的 \(L\) 只是**严格匹配的诊断损失**，不能由 \(\Delta_{\rm cond}>0\) 推出官方视频质量过关。R4E1 已在指定 16 组、至多双交换、四折原生筛选上失败，不得改名扩大池重复搜索；真正的新检验需指出不同的**信息、算子、动作或因果目标**。

## 3. 四种经常被混淆的“目标”

| 层级 | 能检验什么 | 不能声称什么 |
|---|---|---|
| 局部 FFN native loss | 同一学生输入和同一 QDQ/gate/writeback 的算子误差 | 下游或视频质量 |
| 完整步骤 native flow loss | 给定**同一完整步骤输入**，某窗口扰动传到原生 head/flow 的真实响应 | 自由学生四步轨迹或官方指标 |
| 自由学生 rollout | 稀疏执行反馈到后续 latent，包含偏差累积与时序状态 | 没有独立来源时的外推 |
| 新来源联合验收 | 同一候选的主 MAC、FFN时延、三轴质量 | 自动证明科学新颖性或硬件可迁移性 |

原始未蒸馏 **O**、蒸馏 **D-BF16**、蒸馏量化 **D-Q** 三者严格分离：本项目稀疏化部署的直接等价/质量对照是 **D-Q**；D-BF16 用于隔离量化误差，O 用于研究蒸馏造成的表示/冗余变化。不能把 O 与 D 的不同输入、调度和专家状态直接拼成“蒸馏导致/消灭稀疏性”的因果结论。现有 O/D 仅两图、block20、固定输入对照，不支持总体判断。

## 4. 对最新结果的精确归位

[R11T1](64_相同部署预算下的局部与真实flow目标对照.md) 在相同既有 step3/block39 R256、同来源与每臂20更新下，将本地 FFN 目标与真实原生 flow 目标隔离比较：**flow 目标比本地目标好**（开发 flow SSE 相对本地低 **1.57387%**），且相对冻结 UB1 改善 **1.49121%**。但它未过预设的相对 UB1 改善至少 2% 的门槛，固定实验关闭。

这个结果支持“逐层对齐 FFN 输出未必最有利于固定窗口 flow”的有限机制判断。它**没有**改变动态支持、没有引入在线路由、没有在学生自由轨迹训练/部署，也没有新来源的三轴质量。完整步骤间强制恢复 DQ post 的生成视频仍是 DQ 轨迹，不能当稀疏候选的质量或速度展示。R11G1 只证明真实输出头梯度与零更新重放准备就绪，不是算法达标。

**纠正错误链条**：

- flow MSE 下降 **≠** 视频质量必然提高；不能把 1.491% 当 aesthetic/imaging/motion 中任一项的改善。
- 恢复现有 R256 参数 **≠** 发现动态支持策略；小训练可以是使其可行的手段，而非替代目标。
- 原 formal20 上 UB1 的 1.546× 与三轴通过 **≠** 新补充来源通过；补充20 imaging 下降 3.166%，因此当前联合泛化门槛未过。
- 一个固定20步实例未达门槛 **≠** 原生 flow 目标、R256 容量上限或所有训练方法被证伪；但不得在看过来源15后延长同方案追分。

## 5. 最廉价的下一步应当是什么

不恢复已关闭的模型队列、不运行新的 GPU/视频生成，先用存档原生操作数与实验历史做**机制可辨识性核算**：

1. 固定基线：按各来源、step、block 比较 UB1 的静态预算、同预算最好固定动作、实际原生补偿后的条件动作上界；严格标注支持动作集合与 R4E1 重叠范围。
2. 若新机制存在**额外条件收益**，再问能否由主 W1 前已有输入统计/条件预测。计算可用信息、oracle-to-selector gap、随机/固定强基线，以及预测器与搬运的开销；不可把已算完 W1 的 h 作为“免费的预决策信息”。
3. 若当前动作族条件增益不显著，记录机制层面的负结果，比较新表示或新的操作粒度；必要时承认静态压缩有价值，但不得把静态最优包装为动态创新。
4. 只有机制确实与旧失败配方不同，并冻结数据、停止条件、完整原生算子边界后，再在 [新分支模板](../research/NEW_BRANCH_TEMPLATE.md)登记实验。自由学生轨迹与新来源质量保留为后续候选最终层级。

**训练原则**：优先无额外大型训练或小型后训练；如需训练，必须解释它如何增加*部署可得的动态选择/恢复能力*，控制新增推理成本，而不是默认升级成全模型重蒸馏项目。本文不改变已注册数据、原始结果、资格或阈值。
