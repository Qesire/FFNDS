# 学生状态上的原生局部教师 OP1

C24和VM1的正式20质量均被拒绝后，OP1检验另一个问题：旧残差在dense轨迹上拟合，部署时后续输入却来自稀疏学生，是否存在状态分布失配。仍保留C24的支持、alpha及其cast位置、folded bias、原始HiF4缓存和rank256/lambda1，只重拟合并替换残差。它是标准on-policy局部蒸馏控制，不是动态选择或新理论结果。

## 先解决教师数值控制

第一版手工`fromV1`函数只重放256个采样行，与原始完整序列捕获的V2/Y未逐位匹配，因此没有用于任何训练或数据标签。原协议、源码及错误日志保存为`OP1_sample_batch_probe_FAILED_*`。检查过原始bias、weight/scale dtype、布局及量化开关，尚未将失败归结为已证明的单一原因。

后续改用原封不动的`HIF4CacheRuntime.apply`数值路径，在实际完整序列形状上执行原始dense FFN0、GELU、FFN2。它从实际modulated norm输入重算Q1，并要求Q1与学生实际V1逐位相同；权重来自校验过的原始全宽cache shards，原始bias在实际调用前冻结。

在原C24输入0/1上，两个输入各160位置的完整Q1、Q2、Y逐位等于真实dense执行；全部八份四步潜变量哈希和两个视频文件也与原始dense参考完全相同。元数据写盘调整为每40位置一次后，以新源码哈希重新完成同样的完整控制。不存在数值容差放宽；旧失败控制与两个完整控制均保留。

教师只执行局部FFN，输入来自学生实际状态；不称为dense整网轨迹，更不称为原始O模型。所有额外全宽GEMM只在离线采集使用，单独计数，不能计作50%稀疏速度。

## 当前采集与后续冻结门槛

24个既有来源、图像字节、seed42+index、每图256行、每位置6144行总数不变，SRS坐标沿用原C24。两个GPU按奇偶各12输入。每输入先跑plain学生，再独立清空私有生成器跑observed学生，四步潜变量及视频SHA均一致才接受其160位置。

保存实际V1、原生packed FFN2主分支的BaseY、局部原生dense TeacherY、旧残差相加后的StudentY，以及原始b2/gate。BaseY从真实主GEMM返回值捕获，不在CPU重建；另要求其与实际旧残差相加等于StudentY。保存原生V1形状/stride，以供后续预测重放控制。

大张量全部写共享home的HF derived cache，节点保留80GiB余量。每个已接受输入是独立恢复点。采集入口为`tools/collect_onpolicy_operands.py`，状态位于`runs/worker_restart_20261020/onpolicy_calibration24/shard{0,1}/RUN.json`。

系数拟合前冻结的协议为`config/onpolicy_residual_op1.json`：先在late step2/3、block20做parity两折correction-only CV，旧学生/base用过全部24，因此不称全管线留出验证。四个step/fold都要达到新native风险不超过旧StudentY风险的90%，才按相同公式拟合全部160位置。没有rank/lambda/迭代数搜索，没有正式目标参与拟合。

当前只完成教师控制，学生状态采集已启动；尚无OP1 CV、完整视频、速度或质量结果。正式20会继续明确标为复用基准。
