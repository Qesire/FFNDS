# 跨步FFN复用：冷启动、原生边界与已有数据

基于 `7468a6e5d0be561e4fafc8cddc00c53358dc802e`，遵循项目引用的固定版本 [mechanism-research](https://github.com/Qesire/AutoResearcher/blob/bb34ea7be50624d47cb26de7c7c49e40882001f1/.agents/skills/mechanism-research/SKILL.md)。本次继续处理机制和数据问题，没有重跑已拒绝的支持交换，也没有加载模型、读取大张量数值或启动GPU。

**结论：跨步缓存确实改变可用信息，但当前没有Wan上的正面数值证据。两步一专家导致在线时间差分预测缺少锚点；旧OP2样本也不是现成的256行跨步配对集。该想法登记为未具备执行条件，R5的空准入列表保持不变。** [机制差异记录](../research/20261021/temporal_cache_mechanism_record.json)和[本次原始元数据审计](../research/20261021/cross_step_pairing_audit.json)区分推导、实测元数据及未测数值。

## 实际计算和可复用边界

源码定位与SHA见机制记录。固定的 `WanTransformerInfer.infer_ffn` 先执行当前 `x.add_(attn_out)`，再作norm2、当前时间调制、FFN0、tanh-GELU、FFN2；外层 `post_process` 用**当前gate**写回。HiF4桥在两个线性层分别作Smooth、QDQ、BF16转换与GEMM。教师输出 `TeacherY` 是原gate之前的完整FFN输出，`StudentY` 还包含UB1原补偿，不能混同。

设v为post-Q1输入，当前固定专家/层的完整原生映射为F，Y=F(v)。旧R4E1改变当前输入的支持K，继续使用当前h256和匹配读出；这里考察另一种信息结构：缓存同一请求、同一专家、同一层、同一空间坐标的过去完整Yₐ，当前候选形式为

\[
\widehat Y_t=Y_a+(h(v_t)-h(v_a))B,\qquad h(v)=vA.
\]

这是待验证的实数表达式，不是已实现的原生算子。BF16版本必须固定两次投影、减法和加法顺序；投影后相减与先相减再投影不保证逐位相同。缓存必须在新请求和专家切换时重置。替换FFN时仍须保留当前attention残差、当前gate及其他原生状态更新，不能直接提前返回而漏掉 `x.add_(attn_out)`。

过去完整非线性输出并不属于旧方法只读当前h的函数类：固定当前v、改变历史锚点，可改变上述估计。**这是信息结构的区别，不是改善误差的证明。** 所有旧方法的有限拒绝继续成立；不能把它们当作缓存方案的基线胜利。

元数据中1920个同专家来源/层步对的原始b0、b2和教师分片SHA均相同，支持比较同一固定FFN函数；但1920对的gate SHA全部不同。正确的零阶复用误差为Gₜ(Yₐ−Yₜ)。复用旧的已gate结果则额外引入(Gₐ−Gₜ)Yₐ；不能靠旧输出直接替代当前writeback。这里只证明边界区别，没有测量该项大小。

## 四步下的冷启动约束

实际专家序列是high/high/low/low。若每个专家首次出现必须完整计算，且采用全层一致的“完整或跳过FFN”动作，50%主MAC仅够step0和step2两个完整锚点，step1和step3各复用一次。

因此每次复用之前，同专家都只有一个完整锚点。由两个完整锚点构造的在线一阶时间有限差分，在这两个复用点都不可用；更高阶同样不可用。把high的输出接到low历史上，不是在估计同一个函数的时间差分。若先完整计算0、1、2，再只跳过3，则主MAC为75%，违反原50%约束。

这关闭的是**该冷启动规则下直接移植多锚点在线时间差分**的想法。离线训练的输入差分预测、部分层锚点、不同预算安排仍是不同的未证实方法，不能由本结论自动准入。

对平滑实数比较函数f，采用行向量右乘的Jacobian记号，输入差分校正的误差可写为

\[
f(v_t)-f(v_a)-(v_t-v_a)AB
=\int_0^1 (v_t-v_a)\,[J_f(v_a+u(v_t-v_a))-AB]\,du.
\]

这明确指出需要小的输入变化和足够准确的相关Jacobian近似。原生F还包含Q2及BF16边界；写成F=f+η后，误差还包含η(vₜ)−η(vₐ)。不能不验证量化边界就用连续Taylor余项保证原生准确性。本次未测这些未知量。

## 真正配对的数据有多少

[审计工具](../tools/audit_cross_step_coordinates.py)调用已有OP2加载器，核对两分片身份、24份输入记录SHA、生产源码、输入图像、no-op轨迹和视频SHA，再检查3840份scope元数据。**没有重新校验40.35GB张量体，也没有读取激活值。** 精确配对坐标及各自文件内偏移均保留在审计JSON中。

OP2按step分别抽样256行，采样盐包含step；保存位置i不是跨步一致的token ID。只有 `selected_rows` 的交集才可配对。

| 范围 | 真正相同的原生token坐标 | 数据边界 |
|---|---:|---|
| 24来源×40层×两组同专家步对 | 3908对 | 1920个来源/层步对中238个完全无交集 |
| block20，step0→1 | 58对 | 原12/12来源折的训练行数25或33 |
| block20，step2→3 | 55对 | 原12/12来源折的训练行数25或30 |
| 把所有保存行按下标直接zip | 491520对中仅215对坐标相同 | 其余不是跨步配对，不能训练成伪对应 |

M=31668时，独立均匀抽样的设计参考交集为256²/M≈2.069行/来源/层/步对，与观察量级相符。该参考不证明拟合轨迹风险无偏：所有24来源和旧抽样行均已进入开发/拟合。相同空间坐标也不是运动对齐或激活逐位相同。

block20原来源折中的中心化输入设计秩至多24–32，不能把它写成已有充足的rank256差分训练证据。这不证明小样本拟合必然失败；它说明旧数据并未提供原设想中的密集配对证据。其他层合计3908对不能直接当作一个层的训练样本。

## 成本与下一决定

对已观察的21×29×52网格、40层、5120维BF16，完整缓存Y需要 **12.0804 GiB**；同时保存X和Y为 **24.1608 GiB**。若新算子只需缓存Y和共享投影h256，数组容量为 **12.6844 GiB**，但须在两个锚点额外计算投影。按上述两锚点/两复用调度，主MAC为50%，该投影版本的辅助MAC为四次dense FFN的 **1.3889%**；保存完整X、仅在复用时作双投影的版本为 **0.9259%**。这些是算术，未包含权重、临时张量、量化、norm、拷贝、allocator或发射成本，不是显存峰值或1.5×速度结果。

最近相关工作已覆盖跨步复用和预测：[TeaCache](https://github.com/ali-vilab/TeaCache)、[TaylorSeer](https://arxiv.org/abs/2503.06923)。2026-10的 [AutoTarget](https://arxiv.org/html/2610.03577v1)进一步研究蒸馏少步模型的solver输出缓存对象选择；它与这里的内部FFN输入差分不是同一算子，但排除了“在蒸馏少步模型中研究缓存”本身的创新声明。上述文献不能替代本项目四步双专家HiF4的证据。

本次最便宜的检验已经完成：现有数据配对量和冷启动条件不足以直接承接训练。**不触发新采集、拟合、视频或测速，也不把缓存提升为首选。** 若将来获得独立的机制证据，首先需要明确原生控制、同来源坐标一致的锚点/后步数据，以及相对零阶复用和原UB1的区别预测；仍须遵守原50%主MAC、完整FFN≥1.5×和新来源三项质量各≤2%的验收。当前决定与所有旧拒绝保持不变。

验证见[检查记录](../research/20261021/continuation_checks.json)：完整119项CPU测试通过、零跳过、CUDA未初始化；另用原始输入记录独立重算1920个坐标交集，并检查错位偏移、重复坐标和几何失配。当前路线一致性通过，R4E1/E2/E3及本缓存分支均返回不准入。以上均不属于新Wan准确性或性能结果。
