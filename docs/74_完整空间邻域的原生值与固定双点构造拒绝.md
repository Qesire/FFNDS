# R14N0：真实邻域控制通过，固定双点响应未胜过 UB1

在真实 step2/block20、4 份原暴露来源、相同 64 个完整水平四 token 邻域上，R14N0 已完成 **4 次原 UB1 观察采集、32 次独立 FFN、104 次额外 linear**。输入、原始教师/学生、轨迹/视频、原生量化、实际掩码执行与重复控制全部通过。开发来源 0/10 上，动态方案的原生 residual 写回 SSE 比 UB1 高 **31.1642%**；同数量标签 oracle 也高 **19.1142%**，固定实例按预登记规则结束，未触发新模型工作。

[R14 的 1.913× 合成后端进展](73_三方向融合算子的实际成本与原生价值下一步.md)仍成立。这次补上的是实际完整邻域的数值与条件价值；没有把合成速度转称视频加速，也没有用局部 SSE 代替视频质量。旧 D0、R4、R9、R11 的闭合范围和原始判据均保留。

## 1. 实际执行了什么

用户在审阅已上传的 R14N0 固定草案后明确回答“授权该固定范围，继续执行”。[授权记录](../research/20261022/R14N0_authorization.json)、[不可变登记](../research/20261022/R14N0_registered_protocol.json)、[执行前快照](../research/20261022/R14N0_before_execution.json)与 [CPU 准备](../research/20261022/R14N0_CPU_preflight.json)分别保存。执行前 105 项相关测试通过，原 residual 写回的 3 个 dtype 分支在合成 CPU 输入上与实际源码提取函数逐位一致。

先在一张空闲 A100 上运行原冻结 UB1 四步，来源按 **1、11、0、10**，无候选介入整模型。每份新保存相同 64 个真实四行 stripe，共 256 行；另与旧 OP2 原 256 个采样位置比较。捕获位置是 attention 更新后的 residual、当前 post-Q1、真实教师/学生、原偏置与 gate。每来源只多做目标位置原教师的两次 linear，没有另跑 plain/no-op 来翻倍生成预算。

采集进程退出并释放整模型后，另一独立进程用原全行/点平面 GEMM 形状重放。仅观测的 64 组填入真实数据，其他行填零，使用固定 scaffold 维持全局 3958 双点预算和实际矩阵形状。**这测量的是抽样域内 32/64 的局部动作，不是部署过的整场景 top-k 策略。** 未保存完整场景激活，未运行新候选自由视频。

每来源的 8 次独立 FFN 是：教师重放、原 UB1 重放、互补 A/B 双点位置、最佳固定、动态、oracle、动态重复。原始 W1/W2、raw b0/b2、smooth2、GELU/Q2 均保持；A 为原 R9 expert1 冻结矩阵，没有重新拟合。三方向和全部 native 形状与登记一致。

## 2. 最佳固定控制与实际掩码

只用来源 **1/11** 的真实 one/two-point 写回损失，为 64 个位置计算训练总增益，精确选出 32 个双点位置，平局按组 ID。将[固定掩码及训练数据绑定](../research/20261022/R14N0_training_fixed_mask.json)写入并冻结 SHA 后，独立值分析才读取 0/10 的新操作数和损失。采集阶段已生成这两份数据；不能把这个阶段隔离说成从未暴露的最终质量留出。

动态规则固定为 W1 前当前 post-Q1 共享对比的范数，选 32 组。oracle 用标签选 32 组，仅作有限动作族诊断。最终三个掩码都**实际运行原生 FFN**，与互补 A/B 已测局部值组成的 Y 和 post 逐位相同。这里的 oracle 有实际动作控制，与历史 R12 E0 的最终输出 splice 不同；它仍不是输入可读策略或全视频上界。

## 3. 结果

主指标为：使用实际 residual、gate 和 dtype 分支，当前 FFN 写回相对同输入完整教师写回的 FP64 SSE。四份实际 residual/infer/sensitive dtype 均为 BF16，融合写回与原生分支逐位一致。

| 来源与角色 | UB1 | 训练最优固定 | 范数动态 | 标签 oracle |
|---|---:|---:|---:|---:|
| 1，训练 | 4427.8524 | 5262.8634 | 5663.2310 | 5198.7643 |
| 11，训练 | 4073.8773 | 4796.9375 | 5025.9147 | 4736.8618 |
| 0，旧非拟合开发 | 4107.1046 | 4764.0892 | 5009.5708 | 4578.9561 |
| 10，旧非拟合开发 | 4076.2182 | 5442.2462 | 5724.0168 | 5168.5467 |
| **开发合计** | **8183.3227** | **10206.3354** | **10733.5876** | **9747.5028** |

开发合计中，固定/动态/oracle 分别比 UB1 高 **24.7212% / 31.1642% / 19.1142%**。动态比训练最优固定高 **5.1659%**。oracle 相比训练固定可降低 **4.4956%**，但这混合了固定掩码的训练到开发失配和逐输入选择空间，不能全部解释为纯条件收益。

[事后共同掩码参考](../research/20261022/R14N0_common_mask_reference.json)进一步拆解：若允许看开发标签，从已测局部值选一个对两来源相同的 32 组掩码，行可加参考 SSE 为 **9827.8028**；oracle 相对此参考只低 **0.8171%**。训练固定到这个参考的差额为 378.5325，参考到 oracle 为 80.3001。**这个额外共同掩码没有追加原生运行**，不能称作已执行的控制；原来的训练控制和主判据完全不改。该结果也不是完整场景或视频上界。

这些有限差异均不足以补上当前响应算子相对 UB1 的误差缺口。不能据此声称动态计算没有价值，也不能只更换评分就认定可以救回该实例。

重复动态结果逐位相同，预定绝对 SSE 噪声 eta 为 0。开发动态未小于 `min(固定,UB1)−3eta`，故有限原生值判据为 **false**。这个判据在执行前独立登记，未使用旧全局 1.5×/50%/2% 数字否决新方法；同样没有事后放宽本次指标。

## 4. 数值、资源与证据范围

[采集收据](../research/20261022/R14N0_capture_receipt.json)保留全部新张量 SHA 和旧操作数控制、四步 latent/视频 SHA。[完整结果](../research/20261022/R14N0_native_results.json)保留每来源 64 组 one/two-point/UB1 损失、原始范数、所有最终执行结果与控制。24 个候选 Q2 边界与原 forceFP32 逐位一致；所有实际 pack、pool、BF16 residual 写回、掩码组合和重复均通过，没有稠密掩码替代省算。

[预算](../research/20261022/R14N0_budget_debit.json)逐次预扣、失败不回滚，本次所有调用首次完成。32 次独立 FFN 的实际 linear 为 96，加采集教师 8 次，总 104。原四步模型另外记录 6400 次 runtime linear/QDQ 和 640 个 R256 位置，均没有混作免费诊断。

[资源](../research/20261022/R14N0_completed_resources.json)：仅一张卡；独立 FFN 峰值分配约 **7.565 GiB**，HF 新输出 **66,472,205 字节**，远低于 0.5 GiB；结束后 GPU 已空闲、节点缓存盘仍保留超过 80 GiB。**本次 collector 没有记录整模型阶段的峰值显存**，不以旧实验峰值代替。生成耗时包含观察与 IO，不是完整 FFN/视频速度基准。

## 5. 从这次失败继续提问

眼前的强证据是“后端能加速，固定平均响应的实际误差仍偏大”。[保存数据的 CPU 分解](../research/20261022/R14N0_saved_failure_analysis.json)只读取原 A 和新四份操作数，做 8 次 CPU 仿射投影；没有新增原 W1/W2、量化器、FFN 或模型生成。CPU 学生 residual 写回与保存的原生结果逐位相同，UB1 SSE 重算一致。

把真实教师均值作为不可部署的参考加数，保留三方向仿射对比，开发写回参考 SSE 为 **6777.6604（UB1 的 82.8228%）**；FP64 平滑共同 post 参考为 6773.2776（82.7693%）。前者 CPU 投影是 192 行，原生是 23751 行，后者还改变了 BF16 算术类；**均不是已执行原生策略或 BF16 下的严格下界**。但它们留下一个具体问题：保留个体仿射对比之后，如何以足够低成本得到更可靠的联合平均响应。

开发两来源中，额外一点在 **103/128** 组有益，但范数与实际增量收益的 Spearman 相关分别是 **−0.2582、−0.2675**；动态与 oracle 的 32 组只重叠 10/11 组。这是已暴露样本上的描述统计，未训练新评分器。当前信息规则也失败，但标签 oracle 仍输 UB1，因此先改评分不能消除响应误差。现有数据尚不能把平均响应缺口严格拆成草图方差、偏差或 HiF4 量化噪声。

[最新四项一手先例核对](../research/20261022/method_search_R14.json)说明 ToMeSD 已支持 MLP 合并/恢复、ToMA 已有 stripe/GPU 辅助开销设计，DaTMe 使用轨迹信息，BiGain 使用频率信息。它们不是同条件 Wan 实测对手，本次没有宣称领先这些工作。

两条未注册种子已经留下可证伪的计算：[复用已支付的三个 Ah 构造输出几何信息](../research/20261022/R14_available_projection_geometry_seed.json)，以及[调整共享符号分布的二阶方差定理与不连续反例](../research/20261022/R14_sign_measure_deduction.json)。后者在二次函数下能降方差，但阈值例子误差反而从 0.125 升至 0.5714，不能据此认定会改善原 HiF4。**它们没有改变本次注册的符号、策略或预算，也不自动触发新模型实验。**
