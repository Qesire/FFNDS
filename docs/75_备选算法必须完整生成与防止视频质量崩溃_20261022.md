# FFNDS：备选算法晋级后必须做完整视频生成与质量崩溃检查

**2026-10-22 用户新增明确要求**：某个算法一经源、代数、CPU、局部原生值或后端实测支持，且团队决定作为正式备选方法继续发展，**不能停留在局部/固定输入/GPU 随机张量结果**。晋级到性能论文候选之前，必须在真实 Wan 四步学生中至少完整生成一条自由运行视频，并且先确认质量没有明显崩溃。

这不是探索的准入门槛：尚在机制发现、离线推导或本地故障诊断的想法可以继续低成本探索。也不等于研究只需一条视频；一条成对视频只是最小的灾难性质量筛查，发表、泛化与质量—速度 Pareto 仍需要来源独立、成对、多视频正式评估。

## 1. 必经里程碑（适用于所有新算法方向，不限 R14）

1. **发现与局部证据**：允许真实源码、代数、保存数据、CPU、合成 GPU、原生 FFN/flow 试验。记录优势和机制，不能把其中任何一个结果写作“已验证可用的视频加速算法”。
2. **确认有继续投入价值的备选算法**：确认真实候选算子、必要训练/补偿、部署作用范围和可执行的 FFN hook；登记候选 ID，状态 LOCALLY_SUPPORTED 或 WAITING_FOR_ROLLOUT_AUTHORIZATION。下一件必须完成的交付物是配对完整生成，而不是又一次没有质量反馈的局部优化。
3. **完整自由生成质量 smoke**：至少一条候选视频——真实四步 Wan 学生，自身 latent/attention/FFN 状态持续传播；候选替换在预先定义的真实部署位置实际生效；从头到尾运行并解码视频，不在每一步后恢复 dense D-Q，也不是 TF2 的固定输入 flow 重放、纯 teacher/noop 生成、单帧、输出 token 拼接或只运行某层 FFN。必须用同一输入图、prompt、seed、初始噪声、模型、调度器、步数、帧率/帧数、分辨率以及可比精度，对齐一条 dense D-Q（或经说明的目标部署基线）视频。
4. **优先阻断质量崩溃**：检查完整播放的主体身份与运动一致性、语义对象/布局、肢体与物体突变、摄像机抖动、背景小物体和静态结构闪动、**本应稳定的光照反复明暗摇晃**、纹理闪烁、严重噪点/拖影/画面崩解。审阅人必须记录具体时间段、差异和可打开的候选/基线视频定位，不能只看首尾帧或只看汇总指标。任一明显灾难性异常：标记 ROLLOUT_FAILED_QUALITY，停止把该具体候选晋级为论文性能方法；分析机制后可以提出实质不同的修订候选。看不清/无法判定则维持待核验，不能自动 PASS。
5. **最小筛查通过**：只代表在这一对完整视频中“未出现可辨认的明显质量崩溃”。仍需计划多样来源（包括运动、背景/光照、相机运动和局部细节）、新来源自由视频、真实完整 FFN 与端到端生成耗时，并与最强同前提已发表/静态方法比较 Pareto。不能把一条视频写成官方质量通过/全局泛化，也不能因为未达到历史 50%/1.5x/2% 任一随意数字而撤销真实正面结果。

## 2. 规则和记录

- 候选存放在 research/candidate_rollout/registry/ 的一个 JSON 文件内，填写候选 ID、来源/设计证据、当前状态、用户批准的真实模型执行记录和对应的 rollout 视频证据。样例字段见 research/candidate_rollout/record_template.json。使用 tools/check_candidate_rollout_gate.py 进行离线静态校验；CI 同样检查。
- LOCALLY_SUPPORTED、WAITING_FOR_ROLLOUT_AUTHORIZATION、ROLLOUT_RUNNING 是合理的真实状态，但不等于已经验证视频。必须把下一步标记为 COMPLETE_PAIRED_FREE_RUNNING_VIDEO_SMOKE。
- 只有证据齐全且人工全片审查明确无质量崩溃后，才能使用 ROLLOUT_PASSED_SMOKE；只有此外还有真实竞争比较计划时，才使用 READY_FOR_PARETO_BENCHMARK。机器检查只约束记录结构，不能替人看视频。
- 一个完整候选视频是最低线，不是固定采样上限；如果失败是实现/数值错误，先区分实现 bug 与算法失效，修复后走新的有记录版本，不利用无限 seeds 或隐藏崩溃样例追逐偶然成功。
- 提交必须写清候选与基线视频 SHA/locator、配置及对应同源输入/seed、整个四步学生自身状态流和候选作用范围、完整视频的人工审阅结果、可核验的明显质量异常及下一步判定。敏感的节点名与私有路径不要入库，可用中性 HF 派生 locator 和公开核验 SHA。

## 3. 授权、历史实验及开放探索

**必须做完整生成**与**可以擅自启动模型作业**是两个独立命题。候选确认后立即完成代码、对照、模型资源预算和成对自由生成的执行登记，取得用户对该具体范围的授权后运行。未获授权时明确标注“等待完整视频验证”；**不得以未授权或模型任务队列为空为由称视频已通过**，也不得自行绕过资格执行。已有登记协议/历史否定不被重判或自动重跑。

此规则不会要求把 R12 D0 或已经关闭的 R14N0 当成候选再生成视频。R14N0 的局部原生实验已经显示该固定算子逊于 UB1，关闭如实保留。它们可以激发新的计算方法，但新版本须有新的算子机制和独立登记。

对应统一研究评价：docs/72 的同前提竞争和质量—速度 Pareto 是论文目标；本页的**至少一次真实完整生成、避免质量明显崩溃**是候选晋级的定性必要条件。二者都不是过去随意数值阈值的替身。
