## 1. CR：真正运行的是什么

版本化的本仓库 `tools/fit_step_budget.py:fit_position` 先按训练来源的**平均 C-score**选 K（原始64通道组），然后拟合 centered gain 与折叠 bias，再由 post-Q1 V1 拟合 rank256 RRR；**K 的选择标准并不包含最后得到的残余误差方向**。这不是“原先未做补偿”，而是“**先选组后补偿，没有按补偿后残差重新审视支持**”。

`tools/step_budget_runtime.py:create_runtime/apply` 逐 step/block 保存一组 packed W0/W2，支持组数为 `[54,108,108,162]`，每块 W0/W2 分别对当前完整输入执行一次 `F.linear`。对 W0 输入做 Smooth1、cast、HiF4 QDQ1；在 W0 之前对 post-Q1 V1 执行两层 R256 预测；W2 输入再做 Smooth2、HiF4 QDQ2 和 alpha/cast，W2 输出与 R256 修正先相加，再交给后续原生 gate/cast/residual。相关门控路径在历史 LightX2V 源码快照 / [第08号上游审计](08_上游源码校对_20261020.md) 中定位；当前仓库这两个 runtime 文件本身不实现外部原生 gate。**服务器当前运行副本与快照逐字绑定及任意新 support 的 QDQ 相容性仍 OPEN_BINDING**，不能把源码结构理解为已重做原生回放。

| 关键对象 | 张量/边界 | 已证实/未知 |
|---|---|---|
| post-Q1 V1 | `M×5120`，原生 BF16/QDQ | runtime源码检查；采样的256行不是完整M |
| W0 / 激活 / W2 | `5120→13824→5120`，GELU(tanh)，按64组截取 | 已核对 FFNDS 源码与历史控制；绝不能用完整W1后裁W2冒充双侧裁剪 |
| R256 | `V1→256→5120`，在原生 gate 之前加回 | 残差为已实现的参考基线，改支持时冻结它仅是机制隔离 |
| 支持粒度 | **单 step/block 一份权重、全M共享** | 源码确认；任意 per-tile 双bank/segmented GEMM 不存在现有参考执行器 |
| 终点 | FFN gate/writeback→其余blocks→flow→scheduler→后续steps→VAE/质量 | 历史链路部分确认；对新方法的条件质量敏感度仍 UNKNOWN |

历史约束：[UB1速度/质量](28_固定步间计算预算对照.md)为 1.546111×、总主 MAC 50%、原20通过；[补充20](29_冻结候选的来源分离补充验证.md) imaging 下降3.165968%失败；[OP3](46_真实状态重拟合与导入延迟修正.md)与[NF2](47_复用残差隐藏量的输出修正.md)没有提供继续增大/重拟合残差头的理由。[TC1](42_连续小块的支持迁移诊断.md)拒绝的是**单位置支持迁移C评分启发式**，不是尚未测量的整块有符号 oracle。历史[OP2](45_完整原生数据复核与回放控制.md)虽完成24来源×160位置的256行配对、192位置完整几何回放，256行坐标已被旧拟合使用，不能视为未参与开发的全空间或来源外测试。

## 2. DF：可直接演绎且无须重复 GPU 证明的三条结论

### D-R3-1：最先存在的是**静态**支持改良问题

记 `K0` 为UB1的固定整组支持，`K1` 为同宽的替代支持；在相同输入、量化/门控/输出边界和同一冻结R256、gain、bias下，记 `e=y(K0)-yD`、`d=y(K1)-y(K0)`。则

[
A(K1;K0)=\|e\|_2^2-\|e+d\|_2^2=-2\langle e,d\rangle-\|d\|_2^2.
]

它对实际候选输出**严格成立**，包括BF16/QDQ产生的输出差异，因而「单组贡献范数最大的组必须保留」不是有效保证。若有一个K1在既定来源分布上的 `E A>0`，它本身是一个更好的**静态**支持；不能把这部分收益称为动态选择器所获。

在**固定的实数 post-Q2 分组贡献** `c_b`、固定残差/alpha 与忽略packing/cast导致的非加性扰动时，对各组交换系数 `s_b∈{-1,0,+1}`，有 `d_lin=αΣ_b s_b c_b`。对事先固定的非负样本权重，记 `g_b=E⟨e,c_b⟩` 与 `G_bc=E⟨c_b,c_c⟩`，得到**条件二次代理**

[
\boxed{E A_{lin}=-2\alpha\,g^\top s-\alpha^2s^\top Gs.}
]

`G` 半正定；非对角项反映组间抵消和方向耦合，是逐组 C-score 所缺失的信息。它可以用于**离线提出很少量整组交换候选**，并由 native 候选输出复核；**不是**原生QDQ/packing、跨token动态激活或完整视频质量的精确式。为了避免在整160位置物化216×216个大张量，第一轮只需流式积累少量入围组的交叉内积。此机制不增加在线路由或双bank驻留，匹配UB1主GEMM宽度；但新支持需实际重新packing验证，不能直接继承已测 1.546×。

### D-R3-2：必须先决定选择器的**最粗有效粒度**

对两个冻结且等预算的支持，按预定义的连续执行单元 `U` 聚合真实收益 `A_U`。完美知道 `A_U` 时，相对两个支持中更好的固定支持，其单位归一化动态收益为

[
V_U=\mathbb E (A_U)_+-\max(0,\mathbb E A_U)
=\tfrac12(\mathbb E|A_U|-|\mathbb EA_U|).
]

若按一致的权重先对多个小单元求和为大单元，则 `(ΣA_small)_+≤Σ(A_small)_+`，从而**允许更细分辨率的免费oracle不会比粗粒度oracle更差**；然而在线选择、分段GEMM和双支持访存成本恰好反向增大。对实际最优`Z`特征路由，还要从oracle收益扣去按 `|A_U|` 加权的误判损失。

因此数据驱动的粒度次序应为：**固定静态 K1 → 单输入/step/block仅选一个全M共享bank → 只有额外条件收益足够大才考察连续tile**。中间层并非BO1：BO1是在整个视频选择UB1/UB2预算方案；这里在相同预算的某个FFN位置选择不同的原始64组支持。单输入模式仍需主W1前可用的聚合特征、预打包bank和整块同步，并无已验证的部署成本。

### D-R3-3：不能从局部原生平方误差直接得到视频质量的排序

局部误差 `e` 若经连续近似传播 `J`，终端二次风险为 `eᵀJᵀJe`，并非 `eᵀe`；`JᵀJ` 通常未知，离散QDQ下不能无条件使用Jacobian作严格界。无需可微性的 [R1混合前缀/后缀 H_i](../research/20261021/Wan_Distill_FFN_Dynamic_in_Few_Step_演绎检验_20261021.md) 可作有序有限干预诊断，但额外dense计算不满足部署预算。[TF2](34_相同状态下的原生流误差.md)、[UB2](38_固定预算下恢复末步完整FFN.md)、LR2 已说明按单步post、终端latent MSE或末步系数单独分配预算不可靠。这是**目标函数失配的必要警告**，而不是视频成像劣化已经定位到某个频谱/空间区域的证据。

## 4. MNG：相邻研究已经覆盖哪些「看起来新」的想法

- [Jeong et al., AISTATS 2022：Optimal channel selection with discrete QCQP](https://proceedings.mlr.press/v151/jeong22a.html)：已显式考虑通道耦合与实际资源约束；**单独声称「加入通道相关的二次目标」不能构成原创性**。R3区别仅是提议在Wan蒸馏原生QDQ、冻结UB1补偿与固定整组MAC边界下检验这种目标是否仍有效；尚无实测创新。
- [OBS-Diff（ICLR 2026）](https://github.com/Alrightlone/OBS-Diff)：已研究扩散模型的timestep-aware误差累积与结构剪枝；仅靠「考虑时间敏感性」不足以主张新颖性。
- [TARDIS](https://arxiv.org/abs/2501.10054)：已具有线性折叠 + 选择性恢复非线性的算子思想；R2-B仅属已知算子迁移。
- [PrunePath](https://arxiv.org/abs/2605.28283)与[Spark Transformer](https://arxiv.org/abs/2506.06644)：结构化/预测式FFN稀疏均有先例；添加路由器本身不是创新。
- 不把 Sparse VideoGen、DFSAttn 等**注意力**稀疏的速度/分块结果直接推成这里的 FFN 证据。

**原创性状态：CANDIDATE（待出现Wan特异的区别性观察）**。真正可能的论文机制不是笼统的「二次选组」，而是：在量化蒸馏Wan、已补偿静态强基线和固定总MAC约束下，证明**何种未补偿的协方差/方向成分导致跨来源失败，以及为何特定选择粒度能被部署**。必须发现与匹配二次剪枝基线的可区别预测及实际正结果，方可升级为 `DISTINCT_PREDICTION` / `AUDITED` / `VALIDATED`。

## 5. 当下唯一合理的下一研究动作

**先执行只读的 CR/STATIC_CHECK**：重现冻结UB1最新原生布局与QDQ group规则；核对OP2已保存的V1、TeacherY、UB1 StudentY及其采样坐标和路径，在计算新的proxy之前确认大张量当前可访问且身份匹配。已证明的代数式不重跑GPU。若输入未就绪，止于定位依赖，不用任意旧C24/D-Q行假扮UB1真实状态。

获得授权恢复模型实验后，首个原生筛选应是**少数既定step/block的同MAC、有限（≤4组）静态支持交换**，配合原生K0复现及匹配C-score交换对照；不要先拟合新router、追加rank、启动全160支持搜索或视频质量大扫参。只有产生**原生且可跨来源复核**的收益，才进入source粒度选择与完整质量检查。

## 6. 算术与验证边界

本次对 `-2αgᵀs-α²sᵀGs` 与直接 `||e||²-||e+αΣs_bc_b||²` 做一个自构造实数小例计算，二者均为 **-38.4**；两个局部收益为 `+4,-4` 的合成例子显示细粒度oracle可为2而合并大单元收益为0。这是**合成代数一致性检查**，不是Wan证据、通用证明、QDQ数值等价或质量提升。

历史后续准入仍是同一实际实现的完整FFN≥1.5×和三个视频指标分别下降≤2%；历史UB1头寸只有同硬件同输入点估计的约202.357ms（3.074%）可增加时间，且现有original20/disjoint20都已参与开发。
