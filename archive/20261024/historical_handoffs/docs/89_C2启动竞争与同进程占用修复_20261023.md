# C2 启动竞争与同进程占用修复

C2N0 在开始前向前因 GPU 隔离检查失败而停止，完成视频 0 条、FFN/额外归一化/选择器调用均为 0。它没有检验尺度评分的质量或速度。原始结果、扣账、注册和导出记录保持原字节；见[故障解释](../research/20261023/C2N0_startup_failure_analysis.json)。

文件锁在北京时间 23:14:34 取得，监督进程于 23:17:31 结束，间隔177.356秒。期间完成了资产检查与模型加载，56222842880字节的参数和851066880字节的辅助张量被放入GPU。第一份隔离样本发现一个外部计算进程，退出码1。退出后的独立只读检查仍看到了该物理卡上的计算占用。失败的启动成本被保留，不能因前向数为0就当作没有使用GPU。

启动器的文件锁只约束遵守同一锁约定的程序。原流程先做较长的CPU准备，之后才建立模型CUDA上下文并启动隔离监视器；这留下了其他启动器再次看见空卡的窗口。原始数值记录未保存外部进程的精确起止时间，因此这里不反推出它的完整调度历史。

C2N1是同一科学计算的启动修复，不是新评分方法：锁定物理卡后以NVML UUID设置CUDA可见性；实际模型进程先建立CUDA上下文、申请一个逻辑字节的tensor，并确认自己的PID已在该卡的NVML进程表出现，再做CPU资产加载。隔离监控覆盖准备和六视频阶段，额外记录初始NVML进程显存、采样物理显存峰值和完整准备时间。逻辑1字节不代表CUDA上下文只占1字节显存。

CPU测试覆盖UUID不匹配、外部进程抢入、自身CUDA占用不可见、锁跨exec保留及失败不重试。六视频生成循环与冻结原版的AST相同，原评分、物理分支、补偿、source6、seed42和四步配置不变。完整媒体处理还通过了6×81帧的独立合成CPU夹具。这些不是GPU数值或真实视频验证；修复还没有在GPU上执行。

原C2N0协议明确`automatic_retry: false`，原范围已经关闭；未使用的前向额度不是重试授权。[C2N1固定草案](../research/20261023/C2N1_reserved_smoke_DRAFT.json)等待新的独立授权，仍为一张空闲GPU、6视频/2归一化/3选择器，零独立FFN、训练、分解和官方评分，HF新增结果≤0.5GiB。早期可见占用缩短启动空窗，不能阻止完全忽略占用状态的外部任务；原有隔离失败停止规则保留。

原导出器给零视频记录留下了通用`PENDING_VIDEO_REVIEW`状态字样；这不产生人工审阅任务。当前交接已明确零视频，原始导出收据不改，未来导出器按是否存在完整配对视频标记状态。

复现CPU检查：`python3 tools/check_c2_reserved_preflight.py --check`，并运行`test_startup_gpu_reservation.py`、`test_c2_reserved_contract.py`和`test_idle_queue_launcher.py`。实际GPU复验与原生完整视频仍待授权。
