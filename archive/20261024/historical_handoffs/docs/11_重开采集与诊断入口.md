# worker 重开采集与诊断入口

模型/量化算子按原 v4.9.2 合同恢复；这是新校准、新缓存、新边界系列。
原服务器的约 56 GB D-Q cache/R1 张量未转移，不把新结果写成原 AR2 的逐字节续算。
当前实际状态以 [执行记录](09_worker执行记录.md) 为准。

## 校准与缓存

先按执行记录恢复源码、环境、12 个模型文件和原研究输入，再运行：

```bash
.venv/bin/python tools/fetch_calibration_inputs.py
python3 tools/run_on_worker.py --gpu 1 -- python tools/collect_smooth_stats.py --out runs/worker_restart_20261020/calibration12_smooth
```

校准工具每条输入完整执行原四步，并验证两个 expert 各 400 模块、各自两个 step 的调用覆盖。
完成条目与 hash 绑定，重启核验后复用。原校准图包含 task10，task10 不作独立验证。
不将其他校准输入或未完成统计写入这个系列。

量化输出放 worker 本机 HF cache，两个命令分别占一张空闲卡：

```bash
python3 tools/run_on_worker.py --gpu 0 -- env HF_HOME=/var/tmp/ffnds-xiang/huggingface python tools/rebuild_hif4_cache.py quantize --experts high
python3 tools/run_on_worker.py --gpu 1 -- env HF_HOME=/var/tmp/ffnds-xiang/huggingface python tools/rebuild_hif4_cache.py quantize --experts low
python3 tools/run_on_worker.py --gpu 1 -- env HF_HOME=/var/tmp/ffnds-xiang/huggingface python tools/rebuild_hif4_cache.py merge
```

这里是 Smooth(alpha=.5, eps=1e-8)→BF16→原生 HiF4 RTN，不需要 Hessian。
cache 是 BF16 存储的 QDQ 权重、在线 activation QDQ、BF16 F.linear，不能称硬件 FP4 GEMM。
合并必须覆盖完整 80 分片/800 模块；核验完整文件 SHA256 后才发布完成 manifest。
当前小型清单共享于 `.runtime/hif4_rebuilt_cache.json`，实际大文件在 worker 的 `/var/tmp/ffnds-xiang/huggingface/`。

`stage_hif4_cache_local.py` 只用于停止旧 writer 后，校验迁移已完成分片。
`stage_model_view_local.py` 在 worker 以标准 HF blobs/snapshots/view 布局镜像原始模型字节：

```bash
ssh -o ProxyCommand=none worker '/usr/bin/python3 /home/xiang/projects/FFNDS/tools/stage_model_view_local.py'
```

两种 staging 都保留磁盘余量并在完整 SHA256 匹配后发布；node-local 文件不能在其他节点直接读取。
模型 runner 自动采用 host/逻辑身份完全匹配的本机 view，也可以显式指定 `--io-model-view`。

## 四输入边界矩阵

每条输入都分开运行 plain 与 observed，然后比较四步 latent 的实际字节。
每个 observed 保存 blocks0/10/20/38 × 四步、每 scope 512 个新均匀行及其 π/1π。
D-Q 保存实际 Q1/Q2 输入/输出、原生 b2/gate、有效 W2 位哈希和写回边界。

```bash
python3 -u tools/capture_research_matrix.py --arm D-Q --gpu 0 --out runs/worker_restart_20261020/dq_matrix --cache-manifest .runtime/hif4_rebuilt_cache.json --tasks 6
python3 -u tools/capture_research_matrix.py --arm D-Q --gpu 1 --out runs/worker_restart_20261020/dq_matrix --cache-manifest .runtime/hif4_rebuilt_cache.json --tasks 0
```

controller 使用 SSH 启动 GPU 任务；轨迹比较固定 8 CPU threads、隐藏本地 CUDA。
恢复时核验已完成视频、latent、边界文件和源码身份；保留失败目录，不能无提示覆盖。
完成后每个 controller 写一个 `MATRIX_*.json`。scope/seed/行数不作为额外独立来源计数。

## 新 AR2 局部诊断

仅在两个矩阵都为 `COMPLETE_DATA_CAPTURE_AND_NOOP` 后执行。
在 worker 调用 CPU 包装器，确保大权重分片路径可读且不会使用本地或远程 GPU：

```bash
bash scripts/worker_cpu_exec.sh python tools/run_ar2_restart.py \
  --matrices \
  runs/worker_restart_20261020/dq_matrix/MATRIX_dq_gpu1_tasks0_seeds20261001-20261002.json \
  runs/worker_restart_20261020/dq_matrix/MATRIX_dq_gpu0_tasks6_seeds20261001-20261002.json \
  --out runs/worker_restart_20261020/ar2_uniform512
```

协议、源码、环境、矩阵与 tensor hash 都绑定到 checkpoint identity。
主要输出为 `scope_policy_summary.csv`、`decisions.json`、`score_geometry.json` 和可校验的逐行 NPZ。
该诊断实际仍调用完整 CPU GEMM，logical mask50% 不代表主 GEMM 已省50%。
只有同一个冻结候选另行通过全部 160 位置真实 CUDA FFN 总时间、实际主 GEMM 稀疏率、
以及正式 subject10+background10 三项逐项质量门槛，才构成项目整体验收。
